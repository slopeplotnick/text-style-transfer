The way they tried to relax things before didn't work well because it didn't deal with loops that never end, like when a loop keeps going because it's always set to true. Now, we're doing it differently by using a method similar to what we do with if-statements, adding else relaxation variables to manage what happens when the original condition is turned off. This helps us understand all the different ways the program can run, even if there are loops that don't stop. When we work with extra functions, CFAULTS sets up the relaxation variables in the main part of the program and uses them as needed. This way, the same variables are used every time those functions are called. Listing 5 shows what the program looks like after CFAULTS has done its thing to the program in Listing 2. The same parts of the program, like statements and instructions, use the same relaxation variable that's set up in the main part. So, if a relaxation variable is false, that part of the program doesn't run in any test. Also, the relaxation variables in Listing 5 are not set up at the start, so CFAULTS can figure out the least number of parts that need to be turned off. Remember, these relaxation variables are not global but local to the main part to stop the C compiler from setting them all to false automatically.
