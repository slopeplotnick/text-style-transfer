To see if LLM reasoning can solve MRTA problems, we copied the SMART-LLM framework (Kannan et al. 2024) as a starting point to check if it’s doable. This helped us find basic issues with using LLMs for coordination before making our improved version. For testing, we used the SMART-LLM dataset with 36 tasks split into four levels: Elemental (one action), Simple (many objects with similar robots), Compound (different robots with special skills), and Complex (teams working together). We ran the tasks in the AI2-THOR simulation. For the LLM setup, we used Claude 4 Sonnet as the reasoning tool with a temperature of 0.0 to make sure the results were consistent and decisions could be repeated. For checking performance, we followed the SMART-LLM method and looked at five things: Success Rate (SR), Task Completion Rate (TCR), Goal Condition Recall (GCR), Executability (EXE), and Robot Utilization (RU). These measure how well tasks are done and how good the robot teamwork is. After finding issues with validation and LLM reliability during the SMART-LLM test, we made and tested the Self Corrective-Agent Architecture to show that using structured checks and retry steps can fix these problems and prove LLMs can work for MRTA tasks. The Self Corrective-Agent Architecture added multi-step checks with retry options. Important settings included: up to 3 retries per agent, checks at every step (breaking down tasks, assigning them, generating code), and feedback loops to keep improving.
