To answer this question, we broke down the task into two parts, which we explain in Section 2. First, we figure out how to connect what the query is asking for to specific features of the products, creating links between them. Second, we use those links to compare the features of the products to what the query wants. The model needs to do three main things to handle this process. First, it needs to understand the specific terms and hidden details in the query using knowledge, and then it uses reasoning to figure out what the query really means and what features the products should have. For example, in Fig. 1(a), the model has to know that "morning C, evening A" means Vitamin C and retinol, and that "for mom" means it’s for middle-aged women. Second, the model has to match information from different formats, like text and images, to connect the query with product features. For instance, in Fig. 1(b), the query mentions "yellow," but this isn’t in the text, so the model has to look at the product’s image to find the color. Third, the model has to follow rules to make decisions. For example, in Fig. 1(c), if someone searches for "LV bags" but the product is a second-hand bag, the model can’t just rely on matching features and has to follow specific rules to decide if it fits the query.
