The dataset has 81 questions, each about a health problem and a possible treatment. These problems cover 50 disease and condition categories like "Cancer," "Low back pain in adults," and "AIDS," plus a general well-being category called "Other," which includes things like weight management. Figure 2 shows 10 example categories that are most often mentioned in the health questions. You can find the full list of questions and their categories in Appendix Table A4. To see how language models handle real-world biomedical knowledge conflicts, we made five prompt templates to test how they do in different question-answering situations. Table 2 shows that for each example from the HEALTHCONTRADICT dataset, we create five question prompts using these templates: Question: { Question } Question: { Question } Question: { Question } Context: { Correct Document } Question: { Question } Context: { Incorrect Document } We chose our baseline models for two reasons: (i) to see if fine-tuning for biomedical topics improves performance in that area and (ii) to check if bigger models perform better. We also picked language models that can handle long documents. Details of the models we picked are in Table 3. Each biomedical model was made by fine-tuning a general model listed in the same row. "Instruct" refers to models fine-tuned to follow user instructions. We don't fine-tune any models and do zero-shot inference for the baseline models we chose. We look at open-source language models from 1B to 8B parameters to make sure they work in resource-limited healthcare settings. As shown in Table 4, the difference between larger language models (7-8B) is small. Also, the fine-tuned biomedical model MEDITRON3-QWEN2.5-7B doesn't do as well as QWEN2.5-7B. These top evaluation benchmarks aren't great at understanding differences in what models can do because they mostly look at a model's built-in knowledge.
