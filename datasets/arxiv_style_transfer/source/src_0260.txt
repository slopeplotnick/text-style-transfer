The system runs on Spring Boot, and the database is managed by PostgreSQL. Agronomists use Python or MATLAB to make the simulators. The IT team uses a main platform called Cross, which is a big framework, to create application code. At first, the platform was made to create Proof of Concepts. Over time, this changed, and now the platform is used as a base for finished products. There are 7 different versions for 3 Product Owners. New versions are made for specific client needs, with a new one coming out about once a year. The Architecture Dimension levels, as described in the FEF framework, deal with how to build the software and decide how the products are made in the software product line. At Level 1, the architectures are just for single systems, with no focus on reuse. At Level 2, there's a move towards reusing third-party infrastructure, with common software parts like middleware, but no formal use of domain-specific assets. At Level 3, common features in the domain are put into a software platform, providing a reference architecture for all applications, mainly focused on using the platform. But this platform doesn't support handling different configurations. At Level 4, both common features and differences in the domain are captured, and a reference architecture is set up for the whole software product line. Domain assets are made to help create products, with a focus on managing differences within the software product line architecture. Finally, at Level 5, the reference architecture is the main focus, with application architectures only slightly different from it. Automated product creation is possible using scripts, tools, and high-level languages, while application development mainly involves setting things up within the reference architecture's limits, allowing for automated product setup.
