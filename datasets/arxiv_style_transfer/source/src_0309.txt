Even after cleaning, CPV data still has some noise because of issues with item information quality. Also, item SKU features have a lot of extra stuff because of their natural characteristics. So, we take some data and split it into training and test sets to check how effective the features are. We start with product titles and add other features step by step to see how they help. Table 2 shows that adding CPV and SKU features makes the model work better, meaning that if the input info is relevant and stable, it can still improve the model even if there's some extra stuff and noise. We also added main item images to give visual features that text alone can't cover. We didn't include SKU images because the main image already has most of the visual info. SKU images usually show small differences like style or color, which are covered by SKU text features. Adding them would make the model more complicated without giving useful info. In the end, we got a lot of product information that we'll use for all future training. To pick the best base model, we look at two important things: the ability to do complex reasoning and knowledge integration from Section 2, and the efficiency needed for real-world use. We chose some great open-source models with parameters from 7B to 14B. This size is good enough and lets us train and run them on a single GPU. Then, we took some of the existing annotated data and split it into training and validation sets. We used the basic relevance task definition as the prompt and did simple fine-tuning from Section 3.1 for each model on the training set and checked how they performed. In the end, the Qwen2.5-7B model did the best among all the models we looked at and was also efficient in running. So, we picked it as the base model for our setup.
