Some algorithms like OPRO or EvoPrompt don’t use few-shot examples, but they can still make large language models work better, even with simple ways to pick examples. promptsolution adds a module that lets you pick examples after the fact, using random selection and random search to include few-shot examples in a fixed instruction. For starting prompts, many optimizers need a set of prompts to begin with. We provide tools to automatically make prompts from a task description, a basic prompt, or examples from a dataset. Optimizers also have callbacks that help track progress during optimization. These callbacks can check the optimizer’s state at each step and stop the process if needed. Examples include one that tracks token use and stops if it goes over a limit, and another that saves prompts and scores to a file for later review. To test how promptolution works compared to other tools, we ran prompt optimization on GSM8K (math problems) and SST-5 (sentiment classification). We used gemma-3-27B as the main language model and sometimes as the meta-model for optimizers that need one. More details about datasets and how we set things up are in Appendix A.2. For comparison, we tested optimizers CAPO, EvoPromptGA, and OPRO from promptolution, along with top optimizers from AdalFlow and DSPy. To see how much optimization helps, we also tested three manually made prompts for each dataset and averaged their results. We kept the settings for each optimizer the same to make it fair and limited the token budget to one million for input and output combined, keeping costs under $0.15 for this model. All frameworks started with just a task description and no initial prompts to see how well they work automatically. Both the unoptimized prompts and the best ones from each optimizer were tested on a separate test set.
