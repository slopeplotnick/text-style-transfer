Agentic systems are like modern software setups with different parts working together, showing interfaces, and being set up in software processes. They're different from regular programs because they work in a random and flexible way to solve problems. People usually judge these systems by whether they succeed or fail at the end, which misses out on understanding how they think, plan, act, or change their methods over time. We came up with GRAPHECTORY to map out the time and meaning connections in these systems, helping to create ways to measure and analyze how well they work, not just if they succeed. Using GRAPHECTORY, we looked at 4000 paths of two main agentic programming methods, SWE-agent and OpenHands, using four main Large Language Models (LLMs), trying to fix SWE-bench Verified issues. Our automatic checks showed that: (1) agents with better prompts or stronger LLMs have more complex GRAPHECTORY, showing deeper thinking, wider context gathering, and better checking before submitting fixes; (2) agents' ways of solving problems change with how hard the problem is and the LLM used—for problems that are fixed, the methods usually follow steps like finding the issue, fixing it, and checking it, while unfixed ones show messy, repeated, or going-back behaviors; (3) even when they work, agentic programming systems often have slow processes, making the paths longer than needed. Agentic systems using large language models (LLMs) have become a promising way to solve tough, multi-step tasks in different areas like software engineering, web browsing, virtual help, scientific discovery, and robot navigation. Like regular software systems, agentic systems are made of parts like LLMs, tools, APIs, and memory, and have inputs, internal states, ways to work, and outputs. But instead of working in a set way, these systems create paths—steps of thinking, acting, and observing in order—that together make the logic for finishing tasks. Judging agentic software systems has mostly been about the end result: whether the path they make can solve a problem.
