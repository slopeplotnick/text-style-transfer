Refusal rates change in unpredictable ways, with some models saying no more often and others saying no less often depending on the length of the context. The type of padding used affects how well the models work, with padding that looks like real text doing better than random padding, and random padding doing better than multi-task padding. Where the padding goes also matters, because putting context after the task description can make the model perform worse compared to putting it before. LLM agents are AI systems that use pre-trained language models in a loop to make decisions and handle tasks with multiple steps and turns, using tools on their own. Context windows have gotten way bigger, going from 2,000 tokens in GPT-3 to 2 million in Grok 4 Fast, thanks to better position embeddings and attention mechanisms. But these models still tend to focus too much on recent stuff and don’t remember older information very well. Tests like NIAH and LongBench show that bigger context windows help the models take in more information but don’t make them smarter or better at using it. Safety tests for LLMs look at things like toxicity, spreading false info, and ways to break the system, with LongSafety testing how models handle long inputs of up to 5,000 tokens. Safety tests for agents focus on interactive tasks, with AgentSecurity and Agent Dojo checking how well they deal with prompt injection attacks, and RedCode and MobileSafetyBench looking at risks with running code. AgentHarm is a test that looks at how agents handle harmful tasks and how well they can do workflows with multiple steps. We’ve added to the AgentHarm test to see how agents behave and perform when given long-context inputs for both safe and harmful tasks. AgentHarm also tests how well agents use tools in multi-step tasks. It includes tools that are manually set up to act like real-world tools, like Google Search or an API for posting on social media, so testers can fully control how tasks are carried out.
