For GraphMatch, we found that mixing random and hard negatives is really important for it to work well. If GraphMatch is trained only with random negatives, it does about as well as TextMatch-small. We looked at different node features for GraphMatch: "no-feat" just uses TextMatch node embeddings, "no-text" uses number-based node features without text embeddings, and "full" combines TextMatch node embeddings with number-based node features. GraphMatch-full, trained with tough negatives, does the best, while GraphMatch-no-feat does about as well as TextMatch-large, even though it's a much smaller model. We noticed that having text context is key for making accurate predictions, as shown by the low accuracy of GraphMatch-no-text. It's important to sample data accurately over time. Picking the right subgraphs and node features at the right time is needed to train a model that works well with new nodes. To check this, we trained GraphMatch in two ways. The "no-temporal-nodes" version doesn't use time-specific node features during training but always uses the latest feature version in the training set. The "no-temporal-graph" version also doesn't pick time-specific subgraphs but has access to all graph edges during training.
