We use a layered model to mix different statistical distributions that look at different parts of the statistical process separately. This helps us show that some things are independent from each other. For instance, even though different CPUs with the same specs and different instructions use different amounts of energy, these differences don't affect each other. Our method sets up a WCEC energy model to figure out a device's total energy use, as shown in Figure 1, which has two parts: first, the measurement part that checks how much energy the benchmark uses on the hardware, and second, the modeling part that builds a Bayesian model for how much energy the programming language uses. There are several programming languages that work with JVM and are statically typed. To model these languages in one way, we measure the energy of bytecode patterns, which is how the programming language's source code gets turned into bytecode by the compiler, as shown in Figure 2. A microbenchmark has one version of a source code statement from all the possible data types and sizes for a certain operation, as shown in Figure 3. Each microbenchmark measurement happens in a cycle that checks the current, voltage, and time it takes for one microbenchmark. Every cycle starts with setting up the multimeter to get it ready for measuring. Then, to reduce memory noise, the garbage collector runs to clear out memory during the cycle. Each microbenchmark cycle runs 10 times to account for changes in the measurements, and we use a split plot method, which means we mix up the order of the microbenchmark cycles to prevent any bias from the order they run in.
