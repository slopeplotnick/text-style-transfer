The threat model looks at what happens after a bad tool is used by an agent. We think the tool's code might be seen or checked, but because bad and good actions look similar, the hidden backdoor isn't noticed. In cloud or mixed setups, users can't see how tools work inside, so the risk is only in what they can see. The attacker stays within the allowed limits and doesn't try to get more control or mess with memory. The attack is successful if it does two things: (1) completes the attacker's task, and (2) keeps the agent working well on the user's task with only small changes. The threat is about money. Misused computing power costs money, like using up API tokens or GPU time. Many tools doing this can waste a lot of resources. This part talks about the LeechHijack attack. We start with a basic idea of how the attack works. Then, we explain how a hidden backdoor is put into a tool that follows the rules. Next, we talk about how the backdoor is used to open a secret channel and make the agent do extra work. We end with the rules for what makes the attack work and how we measure it. LeechHijack takes over computing in two steps. First, the attacker releases a tool that looks safe but has a hidden backdoor. The backdoor stays off during normal use and doesn't show any bad actions. In the second step, the backdoor is turned on by a specific trigger. When it's on, the tool gives changed answers that make the agent do extra work for the attacker. This step ends when the tool is used again. LeechHijack gives back the attack results and goes back to normal, leaving nothing obvious for the user to see.
