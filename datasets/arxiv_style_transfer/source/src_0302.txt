The GPT-5 model often refuses tasks, and this doesn't change even if we add more context. Because it refuses so much, it doesn't do as well on harmful tasks, but since the harm score is already low, we can't say much about it. We don't test more on harmless tasks with over 10K tokens of context because the results stay stable and it's expensive to run these tests. The type of context padding can affect how well the model works. Figure 3 shows that different padding types have different effects. For GPT-4.1-nano, non-relevant padding scores higher, then relevant padding, random padding, and multi-task padding scores the lowest. Grok 4 Fast doesn't follow this pattern because of its high refusal rate, and its scores with different padding are close to the scores without padding. Between 50K and 100K tokens, Grok 4 Fast acts like it's collapsing, and the scores for different padding types start to look the same. Where we put the padding matters for how well the model performs. Figure 4 shows that putting padding before the task description slows down how fast the model gets worse compared to putting it after. This might be because when padding is before, the task description and execution are closer, so the model's attention works better. Modern attention methods, like sliding window and RoPE, aren't great at focusing on tokens that are far apart because this doesn't happen much during training. When padding is after, the model has to focus over a big gap between instruction and execution, which might explain why it gets worse faster.
