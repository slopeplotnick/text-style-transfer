We tested how well the attack works by keeping the model the same (Deepseek) and trying it on different frameworks, and then keeping the framework the same (OpenManus) and trying it on different models. For all the tests, we set the generation temperature to 0 and limited the number of tool uses to 20. To figure out how much extra computing power the LeechHijack attack uses, we added it to different types of tools and compared how much it used compared to normal tools. We mainly looked at the total number of tokens, which includes both input and output. Since the backdoored tools can trigger LeechHijack multiple times during one task, we also calculated the average extra cost for each trigger. The extra task output only uses part of the total hijacked resources, but from the user's point of view, this extra use of computing power is still a big security issue. To see how useful LeechHijack is, we checked how well an attacker could use the stolen resources. We compared the accuracy of the extra task's responses to the usual accuracy of each model on the MMLU benchmark. The results, shown in Tables 7 and 8, show that LeechHijack can use stolen resources to do hidden tasks, but it does cause some noticeable performance drops. This means the attack works as a way to hijack resources and could be valuable for attackers.
