UnresolvedRetry is when someone tries to change a file a bunch of times but keeps failing. In Figure 12-a, there's an example where a SWE-agent named Dev tries to use str_replace on utils.py 183 times but doesn't succeed and hits the cost limit. StrNotFound happens when the change doesn't work because the old text isn't in the file, like in Figure 13-a. This usually happens because of formatting or small text differences. NoEffectEdit is when the old and new text are the same, so nothing changes. Figure 13-b shows this, where a string is replaced with itself, doing nothing and wasting resources. AmbiguousTarget is when the old text shows up more than once in the file, making it unclear which one to change. Figure 13-c shows this with multiple identical if statements, making it hard for the editor to know which one to change, showing a problem with string-based editing. We looked at these patterns in 4000 GRAPHEC-TORY cases. Figure 14 shows how these inefficiency patterns are spread out among all agents and models for both resolved (Figure 14-a) and unresolved cases (Figure 14-b). The percentages under the Venn diagrams show how many cases had at least one inefficiency pattern. Even in resolved cases, inefficiencies are common, which shows why it's important to analyze the process to understand agent behavior. Unresolved cases often have multiple inefficiency patterns in one go. Interestingly, stronger models like Claude Sonnet 4 are more successful but also show more of these patterns. Looking at it manually, it seems like the model thinks a lot before giving an answer. This is good for tough problems, as shown by the higher success rate, but it can be inefficient when extra steps don't help make better solutions.
