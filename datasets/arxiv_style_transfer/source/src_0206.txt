We train the model in a way similar to the earlier SFT process, but this time we use reasoning examples created during training. Along with the tokens the model generates, we also randomly swap out some sentences with tokens, just like we did before. This helps the model get better at reasoning efficiently. When we use the model, it usually works in a regular mode, but if it sees certain tags, it switches to a different reasoning mode (check Figure 1). These tags show the difference between the two modes, but they aren’t special tokens in the model’s vocabulary. Instead of training the model to use these tags, we just prompt it to do so. The model also decides how many tokens to generate by predicting a number. At first, these tags aren’t used much, but as training continues, they start showing up more often. In this part, we explain two tasks we used to test our method: Flawed Fictions and Next-Chapter Prediction. We go over how these tasks were originally set up and how a basic reasoning model (without the special reasoning mode) is trained to handle them. Both tasks involve complicated story-based reasoning that’s different from the usual tasks used in this area. Flawed Fictions is a test created by Ahuja and others in 2025 to check skills like understanding characters’ thoughts and keeping track of story details. The dataset is made from short stories from Project Gutenberg, using a tool called FlawedFictionSMaker, which adds mistakes to the stories like plot holes and continuity errors. Human reviewers then filter the results (see Table 2 for more info about the dataset).
