This method tries to make things fair for different tasks and groups by improving balanced accuracy directly. It's different from the usual CE loss because it focuses on fixing performance differences between big and small groups, making multi-task fine-tuning more consistent. We did a study to see how different training methods compare. We looked at how single-task and multi-task fine-tuning affect mental health predictions. We made a mental health check app for iOS using llama.cpp as the backend, using GGUF V3 models that work well on phones. The models were changed from PyTorch to GGUF format using a special conversion process, allowing them to run efficiently on CPUs and GPUs. The app is built with Swift/SwiftUI and connects to llama.cpp through a C++ layer, letting it work directly on iOS without needing outside servers. When running, it uses Apple Metal to speed up matrix operations, switching to CPU when the GPU is too busy. It uses up to 8 threads for better performance on Apple's cores. Model weights are set up to use less RAM and load parts as needed. For stability, it uses a 4,096-token window with smart cache management and batch processing to handle long inputs without issues. Long social media posts are cut to 6,000 characters. We tested three models on an iPhone 15 Pro Max: Menta (2.33 GB), Phi-4 Mini (2.40 GB), and Qwen-3 (2.30GB), with open-source code. The framework can also use other quantization methods, balancing speed and accuracy. For our Menta model, we used four top-quality data sets to detect depression, stress, and suicidal thoughts from Reddit, excluding disorder-related samples and getting experts to label the rest. The study used these data sets.
