Some agent frameworks like Roo Code or Terminus let users interact with tools through messages. These frameworks might not fully use our improved reasoning persistence because of the context management rules mentioned earlier. So, we suggest using models that don't think for better performance with these setups. Since we have reasoning data (non-agentic) and non-reasoning agentic data, a simple way to combine these is by using well-designed prompts. We believe the model can follow clear instructions well, which helps it include tool execution in the reasoning process. To show how the cold-start mechanism works, we pick some training data as shown in Appendix Tables 6-8. It's important to know that different tasks have different system prompts. Tables 6-8 give an example related to a competitive programming prompt. Table 6 shows our reasoning data example, where a system prompt asks the model to think before giving the final answer and uses a special tag <think></think> to mark the reasoning path. Table 7 shows the prompt for non-reasoning agentic data, where the system prompt guides tool calling. Table 8 has the system prompt we made to tell the model to use multiple tool calls in its reasoning process. Even though reasoning in tool-use patterns might not be strong, the model can sometimes create the needed paths, which helps in the next reinforcement learning stages. A variety of RL tasks is important for making the model more robust. For tasks like search, code engineering, and code interpretation, we use real tools like web search APIs, coding tools, and Jupyter Notebooks. Even though these RL environments are real, the prompts used are either taken from the Internet or made up, not from real user interactions.
