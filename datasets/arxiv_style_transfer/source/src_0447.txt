The model loader gets the PEFT model ready using the init_adapter method. After that, we let the PEFT provider libraries and the LLaMA-Factory framework handle loading, training, and saving the model. Unlike LLaMA-Factory, PEFT-FACTORY uses a flexible way to load custom PEFT methods, which makes it easy to expand and change. This setup lets researchers and users add custom PEFT methods without changing the main code of PEFT-FACTORY. To show how our Custom PEFT Interface works, we copied two PEFT methods that aren't in any standard PEFT framework, called BitFit and SVFT. When loading dynamically, the peftloader module finds and loads PEFT methods from a well-organized folder setup. Each custom PEFT method has its own folder with two main parts: a config.py file that defines a PeftConfig subclass and a model.py file that has a BaseTuner subclass. The loader checks each setup by looking for needed attributes like peft_type for configurations and prefix for model classes before adding them. The loader loads the config and model subclasses and registers them using the register_peft_method function, which puts the config and model into the Hugging Face PEFT library constants. Also, this process is explained by Algorithm 1 in Appendix B.1. After loading, the custom PEFT method is treated like standard methods as explained in Section 3.1. To add a new method, you need to follow the folder setup inside the PEFT methods directory, which can be set by the environment variable PEFT_DIR with ./peft as the default, to match the organization and class inheritance. We give details about example method templates in Appendix C and in the PEFT-FACTORY documentation.
