When we run the benchmark tests, the system might get noisy because of other stuff happening in the background. We turned off the Wi-Fi to cut down on some of this noise and took a bunch of samples at different times to try and filter it out. The way we set up our statistical model is really important for our research, but it might not be perfect. We made some assumptions based on past research and how we think the data is spread out. This helps reduce any personal bias in the model. But, just like with any model, people might argue about the choices we made for the model's settings and how we spread them out. We based our choices on the Java Virtual Machine (JVM) rules and how programming languages are defined, focusing on parts of Java Bytecode. We use the Gaussian distribution because it often shows up in nature and fits well with how things usually add up and balance out, according to the central limit theorem. We don't know much about the measurements except that they have an average and a range, so this distribution shows our uncertainty. Other issues mostly relate to the system and JVM. The memory state before running each bytecode pattern could change the outcome, so we run the garbage collector before each test. To avoid problems from paging, caching, and other processes happening at the same time, we test each bytecode pattern ten times, mixing up the order each time.
