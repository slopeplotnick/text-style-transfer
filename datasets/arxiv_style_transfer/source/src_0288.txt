This paper talks about finding where problems are in a system by using a model-based diagnosis with several observations as one optimization problem. We put all the failing tests together into one MaxSAT formula. This way, we only get the smallest set of diagnoses that can find all the faulty parts in the system, like a C program or a Boolean circuit. Algorithm 5 shows how we do this. We think the system doesn't change with different observations, so the parts are copied for each observation, but the healthy parts are shared. This is important because we look at all observations together, which can change how the parts act. This section talks about CFAULTS, a tool for finding faults in C programs and Boolean circuits with multiple failing tests. Unlike before, CFAULTS uses the method from Section 4.2, and C programs are relaxed at the code level, so users can use other model checkers better. Figure 1 shows the five steps of CFAULTS: unrolling the system, adding tools to the system, checking the model (CBMC), changing it to MaxSAT, and using an Oracle (MaxSAT solver). Before unrolling the C program, CFAULTS first uses CPPCHECK and CLANG-TIDY to find problems like uninitialized variables and possible runtime errors, like dividing by zero. If there are problems, CFAULTS tells the user right away; if not, it goes on to unroll the buggy program. We added these tools after a study showed they help find problems in students' programming assignments. Input actions like scanf are changed to read from arrays for the inputs, and output actions like printf are changed to write to arrays for the program's output. Every exit point of the program, like a return in the main function, is changed to a goto statement that moves the program to the next failing test's area. Also, to stop the C compiler from automatically setting uninitialized global variables to zero, we set them to random values.
