We used another method during training. The base model sometimes has trouble following instructions when the prompt is long, so we added a quick warm-up stage with supervised fine-tuning to help it stick to the format. Here's how it works: the Challenger role does few-shot grounded generation and calculates a reward. Then, the Solver role does online curriculum learning, calculates its reward, and updates. This makes sure the Solver focuses on problems that are hard but doable, which matches with good learning theory. The Solver reward uses both made-up and real data, adjusted by how hard the curriculum is. R-FeW keeps the same loop as R-ZERO but now uses a grounded and curriculum-aware data setup. The Challenger makes up tasks with few-shot examples from human input. The Solver tries to solve these tasks and checks how often it succeeds. An online filter picks tasks of medium difficulty from both made-up and real data. We use Qwen3-4B-Base and Qwen3-8B-Base as our main models. For comparison, we check against several baselines: (1) Base Model — the original model without extra training, available for download; (2) R-Zero — the first self-play approach where the model makes its own questions and answers to improve itself; (3) Absolute Zero — a self-play setup limited to code generation tasks with Python checking; (4) SPICE — a self-play setup that uses large documents to create reasoning tasks with document-based answers. We recreated baselines (1)-(2) using available setups with the same training setup, while results for (3)-(4) come from the reports by Liu et al.
