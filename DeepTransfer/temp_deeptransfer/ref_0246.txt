Benchmarking the power consumption of LLM inference is fundamentally different from evaluating throughput or latency. Unlike traditional performance metrics, energy consumption is shaped by hardware heterogeneity, software stack complexity, and workload dynamics, all of which vary significantly across deployments. Existing LLM benchmarks offer limited support for this variability, often assuming fixed configurations, static model sizes, and expensive instrumentation. As illustrated in Figure 1, TokenPowerBench overcomes these limitations through a three-layer architecture: Configuration, Execution & Measurement, and Report Generation. This framework offers a modular, configurable, fully reproducible, and scalable benchmarking methodology tailored to modern LLM inference. The first task of TokenPowerBench is to assist users in setting up the test environment by selecting the model to run, the inference engine to use, and the prompts to feed into it. To streamline this step, TokenPowerBench provides three plug-and-play modules: a model pool, a prompt-dataset menu, and an inference-engine selector. The model pool includes models with different underlying architectures to capture how design choices impact energy profiles. This encompasses standard decoder-only transformers, such as the LLaMA series, and Mixture-of-Experts models, like Mixtral, which exhibit distinct computational patterns, particularly in parameter activation and memory access. The benchmark covers a broad spectrum of model sizes, from smaller models with fewer than one billion parameters—suitable for a single consumer-grade GPU—to frontier-scale models like Llama 3-405B, which require multi-GPU and/or multinode distributed inference. This allows for the study of how energy consumption scales with increasing model size and hardware complexity. Moreover, the prompt-dataset menu significantly influences energy consumption during inference, as prompt length and style can vary. To capture this variability, TokenPowerBench provides built-in support for two representative datasets: Alpaca, featuring short, chat-style prompts, and Long-Bench, which includes extended contexts of up to 10,000 tokens. Users can also supply custom data in CSV or other compatible formats.
