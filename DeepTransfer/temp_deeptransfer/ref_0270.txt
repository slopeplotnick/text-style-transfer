Hyperparameters. To isolate experimental variables, we first evaluated the attack's effectiveness across various frameworks using a fixed model (Deepseek). Conversely, we assessed its performance on different models within a fixed framework (OpenManus). For all experiments, the generation temperature was set to 0, and the maximum number of tool invocations was capped at 20. Resource hijacking. To quantify the overhead introduced by the LeechHijack attack, we integrated it into diverse tool categories and compared its computational resource consumption against benign MCP tools. Our primary evaluation metric was the total token count, encompassing both input and output. Given that our backdoored toolkit may trigger LeechHijack multiple times within a single user task, we also defined a distinct metric to compute the average resource cost incurred by each individual trigger. Although the resources dedicated to generating the extra task output constitute only a fraction of the total hijacked cost, from the user's perspective, this unauthorized consumption of computational resources remains a significant security concern. Hijacking resource utilization. To assess the utility of LeechHijack, we next evaluated the efficacy with which an attacker can leverage the hijacked resources. We established a performance baseline using each model's publicly reported accuracy on the MMLU benchmark. We then measured the accuracy of the responses generated for the extra task and compared this against the established baseline. The results of this analysis, presented in Tables 7 and 8, indicate that while LeechHijack can successfully leverage hijacked resources to execute covert generation tasks, this appropriation results in discernible performance degradation. This suggests that the attack is demonstrably viable as a resource hijacking vector and has exploitable value for attackers.
