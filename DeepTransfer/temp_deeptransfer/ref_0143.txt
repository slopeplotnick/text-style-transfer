Pre-Execution Defenses. Pre-execution defenses emphasize the static analysis of agent components to ensure their security and integrity before deployment. For example, tools such as MCP-watch are utilized to audit the source code of components integrated with the agent. Similarly, frameworks like MCP-scan systematically analyze MCP servers to uncover a variety of security vulnerabilities, including those exploitable through prompt injection or manipulation. Runtime Defenses. During the agent's execution, dynamic defenses are essential for real-time threat mitigation. Several strategies have been proposed to address this need. One such approach, SLM as Guardian, leverages a compact model to detect and block potentially harmful user queries. To specifically counter prompt injection attacks, a structured queries method has been introduced. This technique enforces a strict separation between developer prompts and user data, thereby strengthening the system against manipulation attempts. Post-Execution Defenses. Post-execution analyses focus on reviewing procedural records of agent operations to identify potential issues. While the LLM-as-a-Judge paradigm offers a cost-effective alternative to human inspection, its effectiveness is limited to recognizing known risk patterns and is less capable of addressing novel security challenges. Contemporary LLM-agent architectures, such as those employing the Model Context Protocol (MCP), illustrate how the LLM serves as a central coordinator. The LLM interprets user instructions, formulates intermediate reasoning steps, and invokes external tools to execute specific tasks. Each MCP tool operates independently within the agent, communicating with the LLM through a standardized API. Throughout task execution, the LLM maintains contextual awareness across tool interactions to support complex reasoning. In this architecture, the LLM functions as the reasoning core, while the tools act as modular executors of specialized functions. Adversaries, in this context, aim to exploit the agent's computational resources without gaining elevated privileges or compromising the host system. These adversaries are modeled as third-party MCP tool providers who distribute tools within open marketplaces. They lack direct access to the agent's internal state, memory, or parameters and cannot alter the platform's sandbox or runtime policy.
