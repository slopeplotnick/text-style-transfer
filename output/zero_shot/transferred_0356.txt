When utilizing language models such as Claude 3.5 Haiku and GPT-4, discrepancies in outputs can arise even when identical prompts are provided. While these systems occasionally perform as intended, errors in the generated code can occur. Additionally, GPT-4 often repeats examples from prior interactions, which may lead to confusion, such as applying incorrect objects to tasks. These observations revealed limitations in the earlier system's error detection capabilities, prompting the integration of error-checking and retry mechanisms within the LangGraph framework. The LangGraph system incorporates three key components—task decomposition, task assignment, and code generation—into a unified workflow. However, efforts to enhance performance on more complex tasks by introducing additional examples inadvertently led to input length exceeding system constraints, culminating in failures. This trade-off, where extended context improves output quality but exceeds input size limits, motivated the refinement of input handling and contextual management within the LTAA (Long-Term Automated Assistance) system.  These two challenges—output inconsistency and input length constraints—underscored the need for improved quality control and design optimizations to support reliable collaboration between robots and large language models (LLMs). To address these issues, a system emphasizing error detection and iterative feedback was developed. This approach evolved through the SMART-LLM framework, enabling the evaluation of LLMs’ potential in robotic applications. Subsequently, the Self-Corrective Agent Framework was introduced. Unlike the previous single-agent configuration, this new system employs a three-agent architecture, whereby one agent specializes in task decomposition, another in task allocation, and the third in code generation. As depicted in Figure 2, each agent incorporates independent error-checking procedures, which are coordinated by the overarching LangGraph system. The decomposition agent initiates the process by translating high-level instructions into smaller, actionable steps, determining the required actions, identifying the necessary objects, and establishing the sequence of operations. The task allocation agent then matches these steps to the most suitable robots based on their capacities and available resources, while also organizing the execution order.
