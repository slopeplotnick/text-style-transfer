Recent findings indicate that inefficiencies remain prevalent even in scenarios where tasks appear to be resolved, albeit to a lesser extent. In unresolved cases, numerous localization and editing issues often occur simultaneously. While advanced models such as Claude-4 demonstrate higher levels of success, they also exhibit increased inefficiencies due to greater internal exploration. Over the past year, Software Engineering (SWE) agents have gained significant attention for automating issue resolution and performing software engineering tasks. These systems can be broadly categorized into two types: single-agent and multi-agent systems. Single-agent systems, such as SWE-agent and OpenHands, operate using a single execution loop, whereas multi-agent systems, including CodeR, Magis, and MASAI, distribute tasks among specialized agents. These tasks can include searching for code snippets, generating and validating reproduction scripts, modifying code, and testing changes.  The integration of GRAPHECTORY within multi-agent systems enables the merging of outputs from multiple agents into a unified framework. Additionally, SWE agents may also be classified based on the tools they employ. Some agents, such as Agentless, rely solely on prompting strategies without utilizing external tools. Others adopt traditional search methodologies or embedding-based techniques to locate specific files. Advanced systems like TRAE, CGM, and MarsCode Agent leverage code knowledge graphs and language server protocols to analyze software projects and identify relevant code entities. Without GRAPHECTORY, evaluating and comparing these diverse approaches would present significant challenges. By integrating GRAPHECTORY with LANGUTORY, these tools can collectively align within the Localization phase of the development lifecycle.  Following the release of the Claude 3.5 Sonnet model, SWE agents such as SWE-agent and OpenHands have incorporated the use of bash commands for code search, as well as tools for file visualization and modification. Consequently, SWE-agent and OpenHands were selected as the focus of our experiments, given their compatibility with these advancements.
