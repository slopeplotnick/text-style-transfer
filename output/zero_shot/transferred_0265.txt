GraphMatch demonstrates robust performance in addressing the cold start problem for nodes, similar to TextMatch, by effectively leveraging text embeddings in the absence of graph-based information. This capability highlights the model's adaptability in scenarios where graph data is initially unavailable. The architecture of GraphMatch is composed of three integral components: a feature store, an inference service, and a graph database. This modular design enables various graph neural network (GNN) models to utilize specific node features while maintaining a shared graph structure to accommodate diverse requirements.   Node sampling within the system is facilitated through the Cypher query language, allowing users to specify the node and edge types required for inference tasks. The feature store predominantly contains statistical aggregates, including counts and averages. To manage and synchronize data, production databases and business information are mirrored in Snowflake. Feature tables are updated hourly through SQL Mesh jobs and stored in Feast. In cases where features for certain nodes are absent from the graph but not yet available in the feature store, default values are utilized to ensure continuity.  The graph database is implemented using Neo4j Aura, with two distinct pipelines managing updates. A Kafka-based pipeline handles rapidly changing entities, such as job postings, while an hourly Airflow pipeline processes updates for less dynamic entities. The database retains essential node attributes, including type, identifier, and timestamp, which facilitate efficient subgraph sampling during inference.  The inference service operates on a Python/FASTAPI microservice architecture, deployed on Amazon EC2 instances equipped with Nvidia A10G GPUs. Autoscaling of the service is based on the rate of incoming requests per second, as GPU and CPU utilization metrics are less reliable predictors of potential latency issues. To further optimize inference performance, TextMatch embeddings are cached whenever freelancer profiles or job descriptions are updated. Consequently, online inference processes focus solely on the GNN layers, reducing embedding generation times to under 70 milliseconds per entity. This efficiency ensures scalability and supports real-time applications across various use cases.
