The model loader initializes the PEFT (Parameter-Efficient Fine-Tuning) model using the `init_adapter` method. Subsequently, the PEFT provider libraries, in conjunction with the LLaMA-Factory framework, manage the processes of loading, training, and saving the model. In contrast to LLaMA-Factory, PEFT-FACTORY employs a modular and extensible approach to incorporate custom PEFT methods, thereby facilitating flexibility and scalability. This design enables researchers and practitioners to integrate custom PEFT methodologies without requiring modifications to the core functionality of PEFT-FACTORY.   To demonstrate the capabilities of the Custom PEFT Interface, two non-standard PEFT methods, BitFit and SVFT, have been adapted. These methods, which are not included in any conventional PEFT framework, serve as illustrative examples. The dynamic loading mechanism is implemented within the `peftloader` module, which identifies and loads PEFT methods from a structured directory hierarchy. Each custom PEFT method resides in a dedicated folder comprising two essential components: (1) a `config.py` file defining a subclass of the `PeftConfig`, and (2) a `model.py` file containing a subclass of `BaseTuner`. Prior to registering the methods, the loader verifies the configurations and models by checking for requisite attributes, such as `peft_type` for configuration classes and `prefix` for model classes.  Once these attributes are validated, the configuration and model subclasses are dynamically loaded and registered through the `register_peft_method` function. This process integrates the custom methods into the constants defined by the Hugging Face PEFT library. A detailed explanation of this procedure is provided in Algorithm 1, presented in Appendix B.1. After successful loading, the custom PEFT methods are treated equivalently to standard methods, as elaborated in Section 3.1.   To introduce a new method, developers must adhere to a predefined directory structure within the PEFT methods directory. This directory path is specified by the environment variable `PEFT_DIR`, which defaults to `./peft`, and must align with the required organizational hierarchy and class inheritance conventions. Additional information and templates for example methods are provided in Appendix C and are further documented in the PEFT-FACTORY documentation.
