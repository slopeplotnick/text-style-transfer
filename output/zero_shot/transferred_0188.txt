Prior to initiating measurements, no specific information is available regarding the properties of the variables being analyzed, except that the measurements are continuous and exhibit finite mean and variance. Consequently, energy consumption is modeled using a normal distribution. This choice minimizes the introduction of additional assumptions, simplifies mathematical handling, and expedites the analytical process. To enhance computational performance and efficiency without compromising the integrity of results, a multi-level model with a non-centered parameterization is employed. The methodology is implemented in Java 21, although it is adaptable to any statically typed programming language compatible with the Java Virtual Machine (JVM). This study evaluates the viability of the proposed approach by focusing on a subset of Java applications. All Java code is compiled into Java bytecode using the OpenJDK 21.0.6 compiler.  To minimize external interference and ensure accurate worst-case energy consumption measurements, several operational factors are carefully controlled. Specifically, dynamic class unloading and Just-In-Time (JIT) compilation are disabled in the Java runtime environment, which is operated in interpreted-only mode. Additionally, the CPU frequency is fixed at its lowest setting of 1.5 GHz, and wireless networking is disabled on the test platform.  The experimental benchmark comprises 174 distinct micro-tests, each characterized by variations in operation type, data type, and data size. For data types, the study includes 32-bit and 64-bit integers, floating-point types, and reference types for arrays and objects. Each operation is associated with multiple distinct bytecode patterns depending on data size. For instance, addition operations for integers, long integers, doubles, and floats are represented by three distinct patterns per data size, resulting in a total of 12 addition patterns. Operations involving arrays and objects are treated separately from those using primitive data types. A single array is modeled for each primitive data type, with a fixed size of one. For objects, classes and static nested classes are modeled, each comprising four fields corresponding to the four primitive data types.
