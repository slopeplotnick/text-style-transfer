Guiding LLMs on automated program repair, CFAULTS has been integrated with Large Language Models (LLMs) to enhance automated program repair for C programming assignments. Through this integration, CFAULTS identifies the faulty components of a C program and provides the LLM with a modified program sketch where these erroneous segments have been removed. This hybrid approach follows a Counterexample Guided Inductive Synthesis (CEGIS) loop to iteratively refine the program. The LLM is then tasked with generating potential fixes for the missing portions, which are subsequently evaluated against a test suite. If the initial correction is unsuccessful, evaluative feedback from the test outcomes is provided to the LLM, prompting a revised synthesis. This iterative process enables LLMs to repair more programs and produce smaller fixes, thereby outperforming alternative methodologies that do not incorporate FBFL techniques or state-of-the-art symbolic program repair tools. Fault localisation techniques typically fall into two main categories: spectrum-based (SBFL) and formula-based (FBFL). SBFL methods estimate the likelihood of a component being faulty based on test coverage information from both passing and failing test executions. However, while SBFL techniques are generally fast, they may lack precision, as not all components identified are necessarily responsible for the observed failures. In contrast, FBFL approaches are considered exact. These methods conceptualize fault localization as a Model-Based Diagnosis (MBD) problem, aiming to identify the minimal set of faulty components. For each failing test case, FBFL methodologies employ a systematic procedure to identify the minimal set of faulty components responsible for the observed failure. These individual diagnoses are then aggregated to construct a comprehensive explanation of the program's malfunction.
