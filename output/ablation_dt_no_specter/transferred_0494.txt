File editing tools, such as create, str_replace, and insert, can be used to create or modify a test file for reproducing an issue (Localization), an application file for fixing a bug (Patching), or a test file for validating a generated patch (Validation). In debugging, testing plays a dual role: it aids in bug localization and validates the effectiveness of generated patches. Agents utilize Python to execute newly created reproduction or regression tests, while pytest is employed for running pre-existing regression tests. Notably, the same tools or commands may serve different purposes depending on the context, and their application can vary across different phases.

These inefficiencies may lead to repeated failed edits or necessitate adjustments to the localization strategy, as outlined in the first pitfall (§1). GRAPHECTORY enables the computation of process-centric metrics, which are instrumental in analyzing agentic systems. Table 1 enumerates six metrics supported by the current GRAPHECTORY implementation, along with their formal definitions and methods for computation. These metrics quantify the effort exerted by an agent in resolving a task. While the metrics alone cannot determine whether the effort is effective, they provide valuable insights into how well the effort aligns with the problem's complexity and the agent’s success in solving it. Below, we elaborate on each metric and its significance:

- **Temporal Edge Count (TEC):** This metric measures the total number of temporal transitions between actions. A higher TEC reflects a longer execution path to task completion. For instance, Figure 2 illustrates that the execution path for SWE-agent Dev (14) is longer than that of SWE-agent DSK-V3 (8). Similar to NC, TEC values tend to increase with problem difficulty, thereby aligning the GRAPHENCY complexity with the level of challenge posed by the problem.

- **Loop Count (LC):** This metric captures the frequency with which an agent repeats a previously executed action. As discussed in §3.2, a higher LC may indicate a suboptimal strategy, where the agent becomes stuck in a cycle of unsuccessful actions, such as the self-loop at edge 9 in Figure 2-a. Alternatively, it may suggest the need to refine prior reasoning or planning after a series of ineffective actions, as seen with the back edge at 10 in Figure 2-a (§3.3.2). In some cases, a higher LC may also reflect the necessity of re-executing actions incrementally to address a particularly complex problem. LC is analogous to Cyclomatic Complexity [35] in traditional software, which measures branching and the diversity of execution paths. Within the GRAPHENCY framework, branching signifies that localized reasoning redirects the execution flow along a different trajectory.

- **Average Loop Length (ALL):** This metric measures the average number of actions performed before an agent repeats a previously executed action. A longer ALL suggests that the agent takes more time to recognize the ineffectiveness of its actions, indicating weaker reasoning or insufficient contextual information for effective decision-making. However, as shown in our findings (§3.2.1 and §3.3.2), agents that invest in gathering richer contextual information during localization tend to exhibit shorter loop lengths. This ability to quickly identify inefficiencies and adapt strategies demonstrates improved reasoning and problem-solving capabilities.
