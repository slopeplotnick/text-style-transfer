The robot analyzes its operational success rates and current workload status to inform its decision-making processes. Based on calculated success probabilities, it determines the optimal course of action and provides a concise explanation of its reasoning, typically articulated in 2-4 sentences. Furthermore, the system evaluates the projected workload distribution following the decision and assesses the confidence level associated with the decision, categorized as high, medium, or low. Additionally, it articulates the trade-offs involved in reaching the decision. To enable context-aware reasoning, the decision-making framework employs Nodes 2 and 3, which collaboratively generate structured prompts and execute LLM inference. Specifically, Node 2 is responsible for generating contextually appropriate prompts, which are then utilized by Node 3 to facilitate cognitive processing. In Node 3, as illustrated in Figure 11, the reasoning process is executed by invoking the LLM using a structured combination of two prompt components: the system prompt, which defines overarching reasoning behavior and decision policies, and the user prompt, which is dynamically generated in the previous node to reflect the current allocation context. These prompts are sequentially concatenated to form the model input, where the system prompt provides global guidance and the user prompt delivers task-specific situational details, such as success priors, workload intensity, and phase context. The invoke() function of the LLM client transmits the combined prompt as a structured message sequence. Consequently, the LLM generates a natural language response containing its allocation decision, explanatory rationale, anticipated success probability, and confidence level, which is subsequently parsed and validated in the next phase. At this stage, the system processes the combined prompts prepared earlier, comprising the static system prompt that encapsulates reasoning policies and operational rules, alongside the dynamically generated user prompt embedding LLM-specific features, workload status, and phase information. These components are integrated into a structured message sequence and passed to the LLM client for inference. During execution, the model interprets this contextual input to produce a natural-language explanation that includes an allocation decision, explanatory justification, expected success rate, and confidence level. This response serves as the node's output and forms the direct input for the reasoning parsing and validation stage, ensuring continuity and traceability throughout the workflow.
