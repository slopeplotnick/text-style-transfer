We have no prior knowledge about the characteristics of the variables under investigation, except that the measurements are continuous and possess finite mean and variance. Therefore, we model energy consumption as a Gaussian distribution, as this approach avoids introducing additional assumptions while also simplifying mathematical operations, thereby enhancing computational efficiency and expediting the analytical process. Moreover, we employ a hierarchical model with a non-centered parameterization, which optimizes the model's performance and convergence rate without compromising the validity of the results. Our methodology is implemented in Java 21, though it is applicable to any statically typed programming language that runs on the Java Virtual Machine (JVM). For this study, we focus on a subset of Java to evaluate the approach's effectiveness (see Table 1). All Java source code is compiled into Java bytecode using the OpenJDK 21.0.6 compiler. To minimize external interference and ensure that the energy measurements reflect the worst-case energy consumption (WCEC), we control several factors that could influence energy usage. Specifically, within the Java runtime system, we disable dynamic class unloading and Just-In-Time (JIT) compilation, operating exclusively in interpreted-only mode. Additionally, we configure the CPU to operate at its minimum frequency of 1.5 GHz and deactivate wireless networking on the platform. The benchmark configuration consists of 174 microbenchmarks, each defined by operation, data type, and data size. Regarding data types, we analyze 32- and 64-bit integers (int and long), floating-point types (float and double), and reference types for arrays and objects. For example, we define three distinct Bytecode patterns for addition operations on int, long, double, and float data types, corresponding to their respective data sizes, resulting in a total of 12 addition operation patterns. Arrays and objects, however, differ from operations on primitive data types. Specifically, we model one array per primitive data type, with each array constrained to a size of one. For objects, we model instances derived from classes and static nested classes, each containing four fields, one for each primitive data type.
