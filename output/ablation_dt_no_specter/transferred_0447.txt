The model loader then utilizes the init_adapter method to create the PEFT model. From this point, the tasks of loading, training, and model saving are delegated to the PEFT provider libraries and the LLaMA-Factory framework. However, unlike LLaMA-Factory, PEFT-FACTORY employs a dynamic loading mechanism for custom PEFT methods, thereby enhancing its extensibility and modularity. This design allows researchers and practitioners to seamlessly integrate custom PEFT implementations without modifying the core codebase of PEFT-FACTORY. To demonstrate our Custom PEFT Interface, we replicated two PEFT methods not included in any off-the-shelf PEFT framework, namely BitFit (Ben Zaken et al., 2022) and SVFT (Lingam et al., 2024). During the dynamic loading process, the peftloader module automatically discovers and loads PEFT methods from a structured directory hierarchy. Each custom PEFT method is organized in its own subdirectory containing two essential components: a config.py file defining a PeftConfig subclass, and a model.py file implementing a BaseTuner subclass. The loader validates each implementation by checking for required attributes, such as peft_type for configurations and prefix for model classes, before registration. It then dynamically loads the config and model subclasses, registering them via the register_peft_method function, which adds the config and model to the constants of the Hugging Face PEFT library. This process is further detailed by Algorithm 1 in Appendix B.1. After dynamic loading, the corresponding custom PEFT method is managed similarly to off-the-shelf methods, as described in Section 3.1. To introduce a new method, it is necessary to adhere to the directory structure within the PEFT methods directory, which can be specified by the environment variable PEFT_DIR, defaulting to ./peft, to ensure consistency with the organizational structure and class inheritance. Detailed information regarding example method templates is provided in Appendix C as well as within the PEFT-FACTORY documentation.
