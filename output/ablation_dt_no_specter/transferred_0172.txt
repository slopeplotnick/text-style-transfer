In recent years, numerous autonomous Software Engineering (SWE) agents have emerged for automated issue resolution and software engineering tasks. These agents can be broadly categorized into two architectural approaches: single-agent and multi-agent systems. Single-agent systems, exemplified by SWE-agent and OpenHands, utilize a unified loop. Conversely, multi-agent systems, such as CodeR, Magis, and MASAI, employ multiple specialized agents for distinct tasks, including the collection of relevant code snippets, the creation and verification of reproduction scripts, the implementation of code modifications, and the validation of changes. GRAPHECTORY can be seamlessly integrated into multi-agent systems by merging the individual trajectories from sub-agents into one trajectory. Another dimension for categorizing SWE-agents is their tool usage. Some agents, such as Agentless, operate without any external tools, relying solely on large language model prompting strategies. However, other agents employ traditional retrieval mechanisms, such as BM25, alongside embeddings for semantic search to identify relevant files. TRAE, CGM, and MarsCode Agent utilize code knowledge graphs and language server protocols for project understanding and code entity retrieval capabilities. Without GRAPHECTORY, it would be a herculean task to compare and contrast these approaches effectively. The combination of GRAPHECTORY and LANGUTORY allows all of these sophisticated tools to be mapped under the common bucket of the Localization phase. Since the release of Claude 3.5 Sonnet, SWE agents such as SWE-agent and OpenHands have increasingly adopted bash commands for code search and the 'str_replace editor' tool for file inspection and modification. Consequently, SWE-agent and OpenHands were selected as the primary SWE agents for the experimental framework employed in this study.
