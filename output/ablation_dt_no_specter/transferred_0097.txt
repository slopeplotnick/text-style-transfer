Node 6: Retry with Feedback Integration manages retry logic with a maximum of three attempts per task. Enhanced prompts combine original context with specific feedback to guide improved reasoning on re-attempts. The phase-adaptive strategies are implemented through sophisticated methodologies that translate strategic weights into contextual reasoning guidance. Moreover, the prompt engineering system dynamically incorporates phase-specific priorities and natural language instructions, ensuring that the system applies appropriate trade-off logic at each project stage. For instance, during the early phase allocation, prompts emphasize success rate maximization with directives like "prioritize robots with the highest success rates" and "accept moderate workload imbalances." However, as the project progresses, late-phase prompts shift to "favor workload equity" and "consider balance as the primary factor." This adaptive prompt mechanism enables the system to naturally apply the strategic frameworks defined in the phase-adaptive approach. The authors operationalize this integration through three mechanisms: (1) probabilistic modeling of robot capabilities that computes task-specific success rates, (2) structured prompt generation that embeds quantitative priors and workload context, and (3) standardized response formatting that enables reliable parsing and validation. The robotic system comprises three types of robots—Light, Medium, and Heavy—each modeled with distinct strengths and probabilistic success profiles. The success profiles for each robot are derived from probabilistic associations between task features and robot capabilities. Accordingly, each robot's overall success rate for a given task is obtained by aggregating its feature-conditioned success values. Each robot's ability to perform a given task depends on the overlap between the task's required features and the robot's capability distribution. Tasks are sequentially processed through a queue initialized with all 36 tasks from the TEACH dataset. Here, sequential processing means that each task is individually passed through the full workflow, including phase detection, prompt generation, reasoning, validation, and allocation, before proceeding to the next one. Upon completion of each task, the system updates progress metrics and recalibrates the queue length until all tasks are successfully assigned.
