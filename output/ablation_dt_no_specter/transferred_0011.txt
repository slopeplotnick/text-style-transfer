The AgentHarm public test dataset contains 176 samples from 44 unique tasks across 8 categories, such as disinformation and fraud. Each task can be expanded with two modes: one providing a hint about the initial tool to use and another offering detailed step-by-step instructions. Combining these modes results in four variations of each task description. For our experiments, we focus on the simplest subset to reduce costs and provide an upper bound on model capabilities, ensuring that capability is not the limiting factor and that context length primarily influences performance (see Section A). AgentHarm employs an automatic scorer alongside evaluations by LLM-based judges (Zheng et al. 2023). We focus on two metrics: (1) the Harm Score, a rubric-based completion score ranging from 0 to 1 for harmful tasks based on manually implemented rubrics, and (2) the Refusal Rate, defined as the fraction of samples flagged as refusals by the LLM model. For further details, see Section B. We use the Harm Score as the main metric and exclude semantic judgment, assuming reliable evaluation on the simplest subset of tasks. For refusal evaluation, we make minor modifications to both the prompt and the underlying model, as detailed in Section E. To systematically assess the impact of context length, we experiment with four types of context padding: random padding, which uses tokens randomly sampled from the tokenizer; non-relevant padding, which incorporates coherent text from fiction literature across five genres—humor, mythology, sci-fi, crime, and romance—that is unrelated to the task category; relevant padding, which uses coherent text from Wikipedia articles related to the task category; and multi-task padding, which samples task descriptions from the validation dataset. These padding types allow us to isolate different factors: random padding provides full control over reproducibility, non-relevant and relevant padding use coherent in-distribution text, and multi-task padding tests robustness to semantically confounding context. For more details, please refer to Sections F and G.
