In this study, we aim to systematically identify patterns that may indicate inefficiency or regression, leveraging the rich structure of the GRAPHECTORY framework (§2.3.2). Unlike prior work [29], which relies solely on manual analysis of trajectories, our approach enables the systematic mining of meaningful patterns. To achieve this, we define a series of heuristics that can potentially signal inefficient or regressive behavior. Specifically, H1 refers to a large loop, characterized by a sequence of consecutive actions connected by a back edge, which suggests that the agent repeatedly performed actions that failed to resolve the issue, thereby requiring a change in strategy. H2 highlights a misalignment between temporal and structural edges, indicating erratic navigation within the project structure rather than steady, linear exploration. H3 is identified by a long phase length, where the agent engages in a sequence of actions without making substantial progress, suggesting potential stagnation. H4 pertains to a failure outcome for any node, which may reflect inefficiencies in reasoning or suboptimal tool usage. Additionally, we define two specific patterns: RepeatedView and ZoomOut. RepeatedView occurs when the agent revisits the same structural region, such as a file, multiple times during navigation. This behavior often reflects redundant inspections of identical code, typically following unsuccessful edits or incomplete localization efforts. For example, as shown in Figure 2-a, after two failed edit attempts (step 9), the agent reopens the file client.py (step 10) to improve problem localization. On the other hand, ZoomOut refers to cases where the temporal order of actions contradicts the structural hierarchy of the project. This pattern, which signifies backward navigation, occurs when the agent moves from a deeper to a shallower level in the project structure, often upon realizing they have entered an incorrect directory or file. For instance, as depicted in Figure 2-b, after mistakenly navigating into the directory postgres (step 3), the agent retraces their steps to the parent directory /testbed/db (step 4) before proceeding to the correct sibling directory /testbed/db/postgreSQL (step 5) to locate the problematic file client.py (step 6).
