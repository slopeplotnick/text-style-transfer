Non-Deterministic Generation: Claude 3.5 Haiku and GPT-4 exhibited variability in outputs when presented with identical prompts, with some outputs being executable while others contained syntax errors. Training Example Contamination: Over repeated runs, GPT-4 occasionally reused few-shot example sequences, leading to logical inconsistencies, such as erroneously substituting task objects (e.g., replacing objects from "throw spatula in trash" with those from "put eggs in fridge"). These issues highlighted the absence of robust validation mechanisms in the initial system, prompting the integration of explicit validation and retry protocols within the LangGraph framework. This framework employed a few-shot prompting strategy that combined example demonstrations from three key stages—Task Decomposition, Task Allocation, and Code Generation—into a unified prompt. However, appending additional examples to address more complex tasks often resulted in input sequences exceeding the model's context window, causing API failures during inference. This scalability limitation, where richer context improved accuracy but exceeded feasible input lengths, underscored the need for modular prompt optimization and dynamic context management, which were later incorporated into the LTAA framework. These dual challenges—output inconsistency and context window constraints—directly informed the architectural requirements for reliable multi-robot collaboration: the implementation of systematic validation mechanisms to ensure reasoning quality and the adoption of a modular design to manage input limitations. To meet these requirements, the system was restructured into a validation-centric architecture that incorporated multi-stage validation, iterative feedback loops, and controlled retry mechanisms to enhance robustness and reliability. Furthermore, to address the limitations discovered during the implementation of the SMART-LLM framework and to evaluate the feasibility of leveraging LLM-driven reasoning for multi-robot task allocation, the researchers proposed a Self Corrective-Agent Framework. Unlike the earlier single-agent design, this novel framework introduced a multi-stage iterative pipeline consisting of three specialized agents: the Task Decomposition Agent, the Task Allocation Agent, and the Code Generation Agent. As illustrated in Figure 2, each agent operates with its own validation mechanism and is orchestrated through the LangGraph workflow engine to ensure systematic oversight and coordination. The Decomposition Agent initiates the process by converting high-level natural language instructions into a structured sequence of subtasks, identifying task dependencies, environmental objects, and the temporal order required for successful execution. Subsequently, the Allocation Agent assigns these validated subtasks to the most appropriate robots, taking into account their capabilities, skill sets, and available resources, while determining the optimal sequence for execution.
