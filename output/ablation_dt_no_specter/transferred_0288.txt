This paper encodes the fault localisation problem as a model-based diagnosis with multiple observations using a single optimisation problem. We simultaneously integrate all failing test cases into a unified MaxSAT formula. This approach allows us to generate minimal diagnoses capable of identifying all faulty components within the system, such as a C program or a Boolean circuit. Algorithm 5 presents our methodology. We assume that the system remains unchanged across different observations, where components are replicated for each observation, but healthy variables are shared. This assumption is crucial because the joint analysis of all observations can influence the behaviour of individual components. This section introduces CFAULTS, a model-based diagnosis (MBD) tool for fault localisation in C programs and Boolean circuits with multiple failing test cases. Unlike previous methodologies, CFAULTS employs the approach detailed in Section 4.2, where C programs are relaxed at the code level, thereby enabling users to effectively leverage other bounded model checkers. Figure 1 outlines the five integral steps of CFAULTS: system unrolling, system instrumentalisation, bounded model checking (CBMC), encoding to MaxSAT, and the application of an Oracle (MaxSAT solver). Before unrolling the C program, CFAULTS first utilises the static analysis tools CPPCHECK and CLANG-TIDY to detect issues such as uninitialized variables and potential runtime errors, including division by zero. If any issues are detected, CFAULTS immediately reports them to the user; otherwise, it proceeds to unroll the erroneous program. The integration of these static analysers was informed by a user study, which demonstrated their efficacy in identifying such issues within students' programming assignments. Input operations, such as scanf, are transformed into read accesses from arrays corresponding to the inputs, while output operations, such as printf, are converted into write accesses to arrays representing the program's output. Each program exit point, such as a return statement in the main function, is replaced with a goto statement that directs the program flow to the subsequent failing test's scope. Furthermore, to prevent the C compiler's default behaviour of zero-initialising uninitialized global variables, these variables are explicitly initialized to nondeterministic values.
