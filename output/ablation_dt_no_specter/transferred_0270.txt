Hyperparameters. To ensure experimental consistency, we first evaluated the attack's effectiveness across various frameworks while keeping the model fixed (Deepseek). Conversely, we examined its performance across different models within a fixed framework (OpenManus). For all experiments, the generation temperature was set to 0, and the maximum number of tool invocations was capped at 20. Resource hijacking. To quantify the computational overhead introduced by the LeechHijack attack, we integrated it into diverse tool categories and compared its resource consumption against benign MCP tools (Normal). Our primary evaluation metric was the total token count, encompassing both input and output. Since the backdoored tools can trigger LeechHijack multiple times within a single user task, we defined a distinct metric to compute the average resource cost associated with each individual trigger. Although the resources allocated to generating the extra task output constitute only a fraction of the total hijacked cost, this unauthorized consumption presents a significant security concern from the user's perspective. Hijacking resource utilization. To evaluate the utility of LeechHijack, we assessed the extent to which an attacker could exploit the hijacked resources. Using each model's publicly reported accuracy on the MMLU benchmark [55], [56], [62], [63] as a baseline, we compared the accuracy of the responses generated for the extra task against this benchmark. The results, detailed in Tables 7 and 8, demonstrate that LeechHijack can effectively leverage hijacked resources for covert operations. However, this exploitation is not without consequence, as it results in noticeable performance degradation. These findings indicate that the attack is both a viable resource hijacking mechanism and a tool with exploitable utility for malicious actors.
