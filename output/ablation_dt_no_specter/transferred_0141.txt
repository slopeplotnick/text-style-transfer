The previous approach to relaxation proved inadequate, as it failed to address non-terminating loops, particularly those where the loop condition remains perpetually true. To address this limitation, our revised methodology adopts a strategy akin to the relaxation technique used for if-statement conditions. Specifically, it introduces else relaxation variables to control the execution path when the original condition is deactivated. This improvement ensures a thorough exploration of all possible program execution paths, including those involving non-terminating loops. In the context of auxiliary functions, CFAULTS establishes the relaxation variables within the primary scope of the program and passes them as parameters. Consequently, this approach ensures the consistent application of these variables across all invocations of auxiliary functions. Similarly, identical program segments, such as statements and instructions, are associated with a consistent relaxation variable defined within the primary scope. As a result, if a relaxation variable evaluates to false, the corresponding program segment is excluded from execution in any test scenario. Moreover, the relaxation variables depicted in Listing 5 are not initialized at the outset. This allows CFAULTS to determine the minimal subset of components requiring deactivation. It is worth noting that these relaxation variables are not global; rather, they are local to the main scope, thereby preventing the C compiler from automatically assigning them a false value.
