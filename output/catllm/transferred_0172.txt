Over the past year, Software Engineering (SWE) agents have emerged prominently as tools for addressing automated issue resolution and software engineering tasks. These agents can be categorized into two primary types: single-agent and multi-agent systems. Single-agent systems, exemplified by SWE-agent and OpenHands, operate using a singular iterative loop, whereas multi-agent systems, including CodeR, Magis, and MASAI, utilize distinct agents for specialized tasks, such as identifying code snippets, generating and verifying reproduction scripts, modifying codebases, and testing implemented changes. The GRAPHECTORY framework is compatible with multi-agent systems, facilitating the integration of outputs from various agents into a unified process. Additionally, SWE agents can be classified based on their tool usage. Certain agents, such as Agentless, rely exclusively on prompting strategies without employing external tools. Conversely, other agents adopt conventional search techniques and embeddings to locate files. Specific systems, including TRAE, CGM, and MarsCode Agent, leverage code knowledge graphs and language server protocols to analyze projects and identify code entities. Without the implementation of GRAPHECTORY, comparative evaluations of these methodologies would pose significant challenges. The combination of GRAPHECTORY and LANGUTORY enables the integration of these tools within the localization phase. Following the release of Claude 3.5 Sonnet, SWE agents such as SWE-agent and OpenHands have incorporated functionalities such as bash commands for code searching and tools for file viewing and modification. Consequently, SWE-agent and OpenHands were selected as the focus of the experimental investigations conducted in this study.
