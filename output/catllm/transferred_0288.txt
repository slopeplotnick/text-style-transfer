This study investigates the identification of system faults through a model-based diagnostic approach, wherein multiple observations are formulated as a single optimization problem. Specifically, all failing tests are consolidated into a single MaxSAT formula, enabling the derivation of the minimal set of diagnoses required to detect all faulty components within the system, such as C programs or Boolean circuits. The methodology employed is detailed in Algorithm 5, which assumes that the system remains invariant across different observations. Consequently, components are replicated for each observation while maintaining shared healthy components, a consideration that proves critical when analyzing observations collectively, as this may influence component behavior. Furthermore, this research introduces CFAULTS, a diagnostic tool designed to identify faults in C programs and Boolean circuits subjected to multiple failing tests. Distinct from prior approaches, CFAULTS incorporates the method outlined in Section 4.2 and relaxes C programs at the code level, facilitating the integration of additional model checkers by users. The operational framework of CFAULTS is illustrated in Figure 1, comprising five sequential steps: unrolling the system, integrating diagnostic tools, conducting model checking using CBMC, transforming the model into MaxSAT format, and employing an Oracle (MaxSAT solver). Prior to the unrolling phase, CFAULTS utilizes CPPCHECK and CLANG-TIDY to detect issues such as uninitialized variables or potential runtime errors, including division by zero. If such issues are identified, immediate feedback is provided to the user; otherwise, the buggy program proceeds to the unrolling stage. The inclusion of CPPCHECK and CLANG-TIDY was informed by prior studies demonstrating their efficacy in identifying errors within students' programming assignments. Input actions, such as scanf, are modified to read from arrays containing input data, while output actions, such as printf, are adjusted to write program outputs to arrays. Additionally, exit points within the program, including return statements in the main function, are transformed into goto statements to facilitate progression to the failing test areas. To prevent the automatic initialization of global variables to zero by the C compiler, these variables are explicitly assigned random values, ensuring diagnostic robustness.
