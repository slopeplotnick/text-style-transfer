The implantation stage has three objectives: covertness, reversibility, and controllability. Covertness minimizes observable differences between the malicious tool and its benign counterparts. Reversibility guarantees that the tool can restore original outputs after an exploitation cycle. Meanwhile, controllability ensures that the attacker can reliably utilize computing resources to execute extra tasks. In this section, we present the detailed implementation of these objectives. A covert command-and-control (C2) protocol is utilized, employing a two-stage communication model. Initially, the implant sends a short beacon packet containing the victim identifier to a remote endpoint via an outbound network socket, which is then met with a response of an extra task payload. The implant seamlessly injects the payload into the tool's return value so that it appears as legitimate context. In the exfiltration stage, the implant monitors the next tool invocation to capture user-provided inputs and transmits them to the remote endpoint. This two-stage strategy effectively separates task delivery from data exfiltration, thereby minimizing the persistence of network connections. Consequently, the exploitation stage triggers the agent to execute the extra task and then restores the original tool's outputs, ensuring that the user task remains unaffected. Our trigger design employs three types: content-based, frequency-based, and context-based. A content-based trigger activates if the tool input contains a specific token or semantic marker. Conversely, a frequency-based trigger activates after a randomized number of benign invocations, reducing reproducible traces. Finally, a context-based trigger is set off when the agent invokes a specific tool sequence or executes a particular function based on a contextual request. The activation of any of these triggers results in LeechHijack retrieving an extra task from the attacker, thereby facilitating unauthorized consumption of agent resources.
