Non-Deterministic Generation: When utilizing Claude 3.5 Haiku and GPT-4, inconsistent outputs are observed even with identical prompts, with some being executable, while others contain syntax errors. Moreover, over repeated runs, GPT-4 exhibits a tendency to replicate few-shot example sequences presented during training, occasionally resulting in logical inconsistencies, such as incorrect object application for designated tasks (e.g., replacing "throw spatula in trash" with "put eggs in fridge"). These inconsistencies revealed the absence of error-detection mechanisms in the original architecture, thereby necessitating explicit validation and retry strategies within the LangGraph framework. This framework integrates examples across three stages—task decomposition, task allocation, and code generation—into a comprehensive prompt. However, the inclusion of additional examples to address complex tasks resulted in input sequences exceeding system context window limitations, subsequently precipitating API failures during inference. This scalability bottleneck, where richer context improved accuracy but exceeded feasible input lengths, informed the need for modular prompt optimization and dynamic context management, eventually leading to their integration into the LTAA framework. As such, these two challenges—the inconsistency of generated outputs and the constraints of input length—directly influenced the architectural requirements for dependable robot collaboration: systematic validation mechanisms to ensure high-caliber reasoning and a modular design to effectively manage input limitations. To address these requirements, a validation-centric system was devised, incorporating multi-stage validation processes, structured feedback loops, and controlled retry mechanisms to optimize performance. To further tackle the limitations identified during the SMART-LLM configuration and assess the efficacy of LLMs in facilitating robotic tasks, the authors developed a Self Corrective-Agent Framework. Unlike traditional single-agent models, this system employs a tri-agent structure, where distinct agents are designated for task decomposition, task allocation, and code generation. As delineated in Figure 2, each agent operates with its own validation protocol, and the orchestration of these agents is managed through the LangGraph infrastructure. The initial agent transforms high-level instructions into smaller, manageable subtasks, identifying task dependencies, environmental objects, and determining the temporal sequence necessary for task execution. Subsequently, the Allocation Agent aligns these delineated steps with the most suitable robotic units, evaluating their specific capabilities, skill sets, and available resources, while also determining the optimal execution order.
