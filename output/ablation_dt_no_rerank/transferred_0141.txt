The previous relaxation methodology proved ineffective as it failed to address non-terminating loops, particularly when the loop condition consistently evaluates to true. In our revised approach, we employ a strategy similar to that used for relaxing if-statement conditions, incorporating else relaxation variables to regulate the execution path when the initial condition is deactivated. This refinement ensures that the analysis comprehensively captures all control flow possibilities, including scenarios involving infinite loops. In scenarios involving additional functions, CFAULTS establishes the relaxation variables within the core segment of the program, which are subsequently utilized as required. Thus, a consistent application is ensured each time the functions are invoked. This process is exemplified in Listing 5, which illustrates the transformed state of the program from Listing 2 following the application of CFAULTS. The same components of the program, such as statements and instructions, utilize the identical relaxation variable established in the primary section. Therefore, if the relaxation variable evaluates to false, the respective section of the program does not execute during any test. Furthermore, the relaxation variables delineated in Listing 5 are not initialized at the outset, which permits CFAULTS to identify the minimal number of components that require deactivation. It is important to note that these relaxation variables are defined locally within the main program segment to prevent the C compiler from defaulting them to a false value universally.
