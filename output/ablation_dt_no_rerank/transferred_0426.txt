The objective of this study is to identify patterns that denote inefficacy or regression within processes. By leveraging the analytical capabilities of GRAPHECTORY, we systematically mine these patterns, thereby facilitating streamlined identification. We focus on specific indicators of inefficiency, starting with Heuristic 1 (H1), which characterizes scenarios where repetitive actions fail to resolve the underlying issue, thus necessitating an exploration of alternative approaches. Meanwhile, H2 refers to situations where an individual persistently shifts focus within project boundaries, consequently hindering consistent progression. In contrast, H3 denotes a scenario where an extended period is spent on a task without realizing substantive progress, indicative of inefficiency. Furthermore, H4 describes instances where a malfunction or operational inadequacy is observed, potentially signifying suboptimal utilization of available tools and resources. The RepeatedView phenomenon involves an individual persistently examining the same project segment, such as a specific file, indicating redundant assessments of identical code sections typically following unsuccessful revisions or when the problem remains unidentified. For example, after two unsuccessful modification attempts (step 9), the same file, client.py, is reopened (step 10) to ascertain the underlying issue. On the other hand, the ZoomOut pattern is characterized by a discrepancy between the sequence of actions and the project's hierarchical structure, whereby the individual retreats from a more intricate to a more superficial level within the project framework. This sequence distinctly indicates a retracing of steps upon realizing an incorrect directory entry. Specifically, after initially accessing the erroneous directory postgres (step 3), the agent returns to the primary directory /testbed/db (step 4) and subsequently navigates into the correct sibling directory /testbed/db/postgreSQL (step 5) to ultimately locate the erroneous file client.py (step 6).
