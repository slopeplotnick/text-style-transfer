UnresolvedRetry represents a scenario where an agent attempts multiple consecutive edits on the same file, all of which fail to yield a successful outcome. For example, Figure 12-a illustrates how the SWE-agent Dev repeatedly executes str_replace commands on utils.py 183 times, reaching the cost limit without success. StrNotFound occurs when an edit fails because the specified old string is not found in the file, as shown in Figure 13-a. Such failures typically arise from formatting issues or minor textual differences. Meanwhile, NoEffectEdit happens when the old and new strings are identical, resulting in a meaningless replacement. Figure 13-b depicts this, where a command replaces a string with itself, causing no change to the file and wasting execution cost. AmbiguousTarget captures cases where the specified old string appears multiple times in the file, leading to ambiguity about which occurrence should be replaced. This is illustrated in Figure 13-c, where multiple identical if statements prevent the editor from deterministically applying the replacement, highlighting a key limitation of string-based editing mechanisms. The percentages below the Venn diagrams indicate the proportion of instances exhibiting at least one localization inefficiency pattern. Notably, inefficiencies, though less pronounced, are also prevalent in resolved instances. This underscores the importance of process-centric analysis to raise awareness of agent behavior. Unresolved cases often involve multiple inefficiency patterns within a single trajectory. Interestingly, stronger models like Claude Sonnet 4 achieve higher success rates yet still exhibit more of these patterns. Manual analysis suggests that the model engages in extended internal reasoning before producing a solution. Although this approach can be beneficial in solving difficult problems, as evidenced by the model's higher success rate, it leads to inefficiency when additional steps do not contribute to better solutions.
