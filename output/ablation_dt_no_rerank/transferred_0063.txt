The threat model focuses on the execution phase after a malicious tool has been integrated and invoked by the agent. In fully localized deployments, we assume that the tool's source code may be publicly visible or subject to static review; however, the semantic similarity between benign and malicious behavior keeps the latent backdoor undetected. Meanwhile, in cloud-hosted and hybrid environments, the internal structure of tools remains invisible to users, restricting the potential attack surface to their observable outputs. The attacker operates entirely within the existing sandbox and does not engage in privilege escalation, code injection, or memory corruption. The success of the attack relies on two conditions: first, the successful execution of the attacker's external computational task, and second, the preservation of the agent's functional accuracy on the user's original task within an acceptable deviation threshold. The threat is primarily economically motivated, as hijacked computation directly incurs resource costs like API token usage or local GPU cycles. Consequently, the cumulative effect of many such tools can lead to significant resource leakage across the agent ecosystem. This section presents the architectural framework of the LeechHijack attack. We start with a high-level overview of the attack workflow, then describe the implantation phase where a latent backdoor is embedded into a compliant MCP tool. Subsequently, we explain the exploitation phase, during which the backdoor is activated to establish a covert communication channel and impose extra workloads on the victim agent. Finally, we conclude with formal definitions of the attack success criteria and metrics for evaluation. LeechHijack achieves computation hijacking through a two-stage process. In the implantation stage, the adversary releases a seemingly benign MCP tool containing a dormant backdoor component. During normal operation, the backdoor remains inactive and does not evoke detectable malicious behavior or side effects. In the exploitation stage, the backdoor is triggered conditionally. Upon activation, the tool returns manipulated responses that prompt the agent to perform additional tasks specified by attackers. The exploitation stage concludes when the tool is reactivated in a subsequent invocation. LeechHijack then returns the attack calculation results and restores normal outputs, leaving no overt artifact visible to the user.
