All components of the system operate within a unified configuration framework, which ensures seamless interchangeability while preserving compatibility with the system architecture. Each component is individually configurable; however, the ExperimentConfig facilitates a streamlined approach by managing all settings centrally. The LLM component interfaces with large language models to extract responses efficiently. Its primary configuration supports concurrent operations and monitors token utilization. There are three distinct classes implemented: APILLM enables integration via API, supporting platforms such as OpenAI and Anthropic, illustrated through the DeepInfra API setup. LocalLLM accommodates local model execution using transformers on personal devices. VLLM leverages the v11m library to handle high volumes of requests, enhancing compatibility with GPU architectures. The Predictor component is tasked with extracting solutions from the model's output. In classification, it identifies the predicted category; for mathematical tasks, it determines the final answer. The FirstOccurrencePredictor finds the first potential solution in the output as its criterion, whereas the more reliable MarkerBasedPredictor discerns solutions marked by specific identifiers. For example, computing the total number of fish across fishbowls follows a sequential additive method, like combining 62 fish with an existing 3 fish to achieve a total of 65 fish. The Task section encapsulates essential procedural data and specifics, while setting evaluation criteria for prompts, ensuring efficient time management by avoiding redundant tests.
