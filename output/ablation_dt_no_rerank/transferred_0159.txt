Energy efficiency is a concern in many areas, such as mobile software design and software in data centers. Understanding and reducing the energy consumption of simple software systems is challenging, and modern language run-time systems with dynamic optimizations further complicate the matter. For instance, consider statically typed JVM-based programming languages like Java, Scala, or Kotlin, which utilize Java bytecode, a platform-independent intermediate representation executed on a virtual machine. The energy consumption of such software hinges on many factors—the compiler and its optimizations, the Java Virtual Machine (JVM), the garbage collector, the operating system, and the target hardware. To thoroughly comprehend the energy impact of software design decisions, software engineers must pierce through these abstraction layers and grasp the specifics of the intended execution platform(s). Previous work has explored methods for workload-based energy profiling, where developers run software with a specified workload in a specialized environment that measures energy consumption and attributes it to individual code components. However, the practical application of workload-based energy profiling is limited by the need for a custom hardware setup, which is not always feasible in routine software engineering tasks. Although some hardware platforms reveal energy consumption details for specific components like the CPU, few can measure the total energy consumption of the platform. The model constructs Gaussian distributions for each quadruple describing a source code statement while categorizing each element to demonstrate their individual effects on energy consumption, such as the impact of operations, data types, data sizes, and devices. This model illuminates the energy effects of altering data types within an algorithm. Moreover, it specifically targets the worst-case energy consumption (WCEC) of single code statements, using predictive techniques to assess energy consumption across functions and comprehensive programs. The distributions encapsulate the WCEC, as a single point estimate fails to account for the possible range of consumption values in worst-case scenarios, which may be influenced by random energy variations like temperature fluctuations or external interference. Furthermore, the approach retains statistical properties, such as mean, skewness, and mode, and enables calculations of entropy and probability functions, which single-point estimates cannot achieve. Thus, employing worst-case energy consumption predictions ensures that software conforms to energy requirements—crucial for battery-operated devices and cost-savings in data center environments. Consequently, program analysis or software verification tools can leverage this methodology to provide accurate energy estimates.
