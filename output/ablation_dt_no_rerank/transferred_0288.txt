This paper tackles the fault localization problem by framing it as a Model-Based Diagnosis with multiple observations within a single optimization problem. We integrate all failing test cases into one MaxSAT formula, enabling the derivation of minimal diagnoses that effectively identify all faulty components, such as a C program or a Boolean circuit. Algorithm 5 outlines our proposed methodology. We assume that the system remains consistent across different observations; thus, components are duplicated for each scenario while healthy variables are shared. This assumption is crucial, as analyzing all observations together can impact component behavior. This section introduces CFAULTS, a model-based diagnosis (MBD) tool for fault localization in C programs and Boolean circuits plagued by multiple failing test cases. Unlike existing approaches, CFAULTS employs the strategy described in Section 4.2, where C programs are relaxed at the code level, enhancing the usability of other bounded model checkers. Figure 1 provides an overview of the five-step CFAULTS process: system unrolling, system instrumentalization, bounded model checking (CBMC), transformation to MaxSAT, and application of an Oracle (MaxSAT solver). Before the unrolling phase, CFAULTS utilizes the static analyzers CPPCHECK and CLANG-TIDY to detect issues like uninitialized variables and potential runtime errors, such as division by zero. If any issues are detected, CFAULTS immediately reports them to the user; otherwise, it proceeds with unrolling the faulty program. These static analyzers were integrated following a user study that highlighted their value in helping students identify such issues in programming assignments. Moreover, input operations, like scanf, are transformed into read accesses from arrays of inputs, and output operations, like printf, are replaced by writing operations to arrays representing the program's outputs. Additionally, each program exit point, such as a return statement in the main function, is substituted with a goto statement that directs the program flow to the next failing test's scope. Furthermore, to prevent the automatic zero-initialization of uninitialized global variables by the C compiler, these variables are explicitly initialized to nondeterministic values.
