Hyperparameters. To isolate the experimental variables, we first systematically evaluated the attack's efficacy by applying a fixed model (Deepseek) across diverse frameworks. Conversely, we assessed its performance on various models within a constant framework (OpenManus). In all experimental procedures, the generation temperature was standardized at 0, and the maximum number of tool invocations was limited to 20. Resource hijacking. To ascertain the computational overhead introduced by the LeechHijack attack, we integrated it into assorted tool categories and compared its resource utilization against benign MCP tools. Our primary evaluation metric was the comprehensive token count, covering both input and output data. Since our backdoored tools have the capability to trigger LeechHijack multiple times within a single user task, we introduced a distinct metric to calculate the average incremental resource cost associated with each trigger. Although the additional task output only uses a portion of the hijacked resources, from the user's perspective, this unauthorized consumption of computing power constitutes a substantial security concern. Hijacking resource utilization. To evaluate the utility of LeechHijack, we examined how effectively an attacker could exploit the compromised resources. We compared the accuracy of responses generated for these additional tasks to the established baseline accuracy of each model on the MMLU benchmark. The results, presented in Tables 7 and 8, indicate that LeechHijack successfully utilizes hijacked resources to execute concealed tasks. However, this resource appropriation causes some discernible declines in performance. Thus, the attack functions as a viable resource hijacking mechanism and holds considerable value for malicious actors.
