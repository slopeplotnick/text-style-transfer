Our methodology utilizes a layered model that combines multiple statistical distributions, each focusing on separate aspects of the statistical process, thus enabling us to articulate assumptions of statistical independence. For example, while different CPUs with the same specifications and varying instructions may show diverse energy consumption patterns, these variations remain statistically independent. We define the WCEC energy model to determine the overall energy consumption of a device, as depicted in Figure 1, with two components: the measurement component, which assesses the energy consumption of the benchmark harness executed on the target hardware, and the modeling component, which constructs a Bayesian model to quantify the programming language's energy consumption. There are several statically typed JVM-based programming languages. To facilitate unified modeling, we measure the energy associated with bytecode patterns, which involve translating the programming language's source code statements into bytecode representations via the compiler (refer to Figure 2). A single microbenchmark includes a permutation of a source code statement from the comprehensive set of data types and sizes for a specific operation, as illustrated in Figure 3. Each microbenchmark measurement takes place in the measurement cycle, where current, voltage, and execution time are thoroughly assessed. Each cycle begins with configuring the multimeter to prepare it for measurement. Subsequently, to reduce memory noise, the garbage collector runs to clear memory allocations during the cycle. Each microbenchmark cycle is conducted 10 times to accommodate variability in the measurements, using a split plot approach, where the execution order is randomized to prevent bias from sequential arrangement.
