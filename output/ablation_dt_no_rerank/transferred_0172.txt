In recent years, numerous autonomous agents have emerged for automated issue resolution and software engineering tasks. SWE agents can be broadly classified into two architectural paradigms: single-agent and multi-agent systems. For example, single-agent systems such as SWE-agent and OpenHands use a unified iterative process, whereas multi-agent systems like CodeR, Magis, and MASAI deploy specialized agents for distinct tasks. These tasks correspond to different phases such as collecting relevant code snippets, creating and verifying reproduction scripts (Localization), implementing code modifications (Patching), and validating changes (Validation). GRAPHECTORY is easily applicable to multi-agent systems by merging individual trajectories from various sub-agents into one comprehensive trajectory. SWE Agents' Tools. Another perspective for categorizing SWE-agents is based on their tool usage. Some agents, such as Agentless, operate independently of external tools, relying solely on large language model prompting strategies. Other agents employ traditional retrieval mechanisms like BM25 and embeddings for semantic search to identify pertinent files. Additionally, agents such as TRAE, CGM, and MarsCode Agent leverage code knowledge graphs and language server protocols for advanced project understanding and code entity retrieval. Without GRAPHECTORY, making a comparative analysis of these methodologies would pose substantial challenges. The integration of GRAPHECTORY and LANGUTORY enables these diverse tools to be grouped under the common umbrella of the Localization phase. Since the release of Claude 3.5 Sonnet, SWE agents, including SWE-agent and OpenHands, have adopted bash commands for code search and the 'str_replace editor' tool for viewing and modifying existing files. Consequently, SWE-agent and OpenHands were chosen for our experimental procedures.
