GraphMatch demonstrates comparable efficacy to TextMatch in handling cold start nodes, indicating the model's capability to utilize text embeddings in the absence of graph information, thereby addressing the cold start issue. The real-time deployment architecture of GraphMatch consists of three main components: a feature store, an inference service, and a graph database. This structure permits diverse Graph Neural Network (GNN) models to leverage specific node features while maintaining a common graph structure adaptable for various applications. Node sampling is executed using Cypher, allowing practitioners to specify the required node and edge types for inference. The feature store primarily comprises aggregated statistics such as counts and averages. Our data warehouse, Snowflake, stores replicas of production relational databases and assorted business datasets. Feature tables are updated on an hourly basis through SQL Mesh ETL processes and maintained in Feast. In situations where features are missing for entities present in the graph but not yet in the feature store, we have defined smart default values to manage these absences effectively. The graph is hosted using the Neo4j Aura graph database, with updates facilitated by two distinct ETL pipelines: a near-real-time Kafka pipeline for highly dynamic entities like job postings and an hourly batch pipeline utilizing Airflow for the remaining entities. In the graph database, only essential node properties, such as type, ID, and creation timestamp, are stored to enable precise subgraph sampling for inference. Model inference operates through a Python/FASTAPI microservice deployed on EC2 instances equipped with Nvidia A10G GPUs. Requests per second determine autoscaling, as this metric provides a more accurate prediction of latency issues than GPU/CPU utilization. To enhance inference efficiency, we compute and cache TextMatch embeddings each time a freelancer profile or job posting description is updated. Consequently, online inference is confined to the exclusive use of GNN layers, maintaining embedding generation latencies below 70 milliseconds per embedding across all entity types. This approach facilitates horizontal scalability and enables near real-time applications.
