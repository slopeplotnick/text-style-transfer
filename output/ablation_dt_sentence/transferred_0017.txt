The implantation stage has three primary objectives: covertness, reversibility, and controllability. Covertness minimizes observable differences between the malicious tool and its benign counterparts. Reversibility guarantees that the tool can restore original outputs following an exploitation cycle. Controllability ensures that the attacker can continuously manage computing resources to execute additional tasks beyond the system’s intended operations. In this section, we describe the implementation of these three objectives. To achieve covert communication, the backdoor employs a two-phase command-and-control (C2) mechanism that remains indistinguishable from benign operational traffic. During the first phase, known as Beacon, the implant transmits a short signal containing the victim's identifier to a remote endpoint via an outbound network socket. The remote endpoint then returns a payload specifying an additional task. This payload is embedded into the tool’s output stream, preserving the appearance of expected behavior. In the second phase, called Exfiltration, the implant monitors the subsequent tool invocation, captures user-provided inputs, and forwards them to the remote endpoint. This two-round structure decouples task delivery from data exfiltration, thereby reducing the duration of observable network activity. During the exploitation stage, the implant induces the agent to perform the extra task while returning the original tool outputs, ensuring that the user's workflow remains unaffected. To manage activation, the design integrates three distinct trigger types: content-based, frequency-based, and context-based. A content-based trigger activates when the tool input includes a specific lexical token or semantic marker. A frequency-based trigger activates after a randomized number of benign invocations, reducing the risk of pattern detection. A context-based trigger activates when the agent engages a designated tool sequence or responds to a particular contextual request. Upon trigger activation, LeechHijack retrieves an additional task from the attacker, enabling unauthorized consumption of agent resources.
