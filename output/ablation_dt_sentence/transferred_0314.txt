Large Language Models (LLMs) have been employed to support automated program repair for C programming assignments. In this context, CFAULTS integrates with LLMs through a process where it identifies faulty sections within a C program and presents the LLM with a version of the program where these erroneous parts are removed. The LLM is then tasked with synthesizing candidate completions for the missing segments, which are subsequently evaluated for correctness using a test suite. If the proposed fix fails, corrective feedback is provided to the LLM based on the test results, prompting a reattempt. This iterative approach enables LLMs to repair more programs and generate more concise fixes, surpassing alternative configurations that do not incorporate FBFL techniques or symbolic program repair tools. Fault localisation (FL) methods are generally divided into two main categories: spectrum-based fault localisation (SBFL) and formula-based fault localisation (FBFL). SBFL leverages test execution outcomes to rank program components by their likelihood of being faulty. However, its effectiveness is limited by the lack of a formal guarantee that the identified elements are causally responsible for the observed failures. These methods approach fault localisation as a Model-Based Diagnosis (MBD) problem, aiming to identify the minimal subset of faulty components. For each failing test case, FBFL methods identify the minimal diagnosis corresponding to the failure, and then aggregate these individual results into a unified explanation for the program's malfunction.
