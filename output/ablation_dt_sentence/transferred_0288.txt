This paper encodes the fault localisation problem as a Model-Based Diagnosis (MBD) with multiple observations using a single optimisation problem. All failing test cases (observations) are simultaneously integrated into a single MaxSAT formula. This approach allows us to compute a minimal set of diagnoses that collectively identify all faulty components in the system, such as a C program or a Boolean circuit. Algorithm 5 outlines our methodology. We assume that the system remains invariant across different observations, where components are replicated for each observation, while the healthy components are shared. This assumption is essential because we analyse all observations jointly, which may influence the components’ behaviour. This section introduces CFAULTS, a model-based diagnosis tool for fault localisation in C programs and Boolean circuits with multiple failing test cases. Unlike prior approaches, CFAULTS applies the technique described in Section 4.2, where C programs are directly relaxed at the code level. This design choice enables users to more effectively utilise alternative bounded model checkers. Figure 1 illustrates the CFAULTS workflow, comprising five steps: system unrolling, system instrumentation, bounded model checking (CBMC), transformation into a MaxSAT formula, and resolution via an Oracle (MaxSAT solver). Before unrolling the C program, CFAULTS invokes the static analysers CPPCHECK and CLANG-TIDY to detect issues such as uninitialised variables and potential runtime errors (e.g., division by zero). If such issues are detected, CFAULTS immediately notifies the user; otherwise, it proceeds to unroll the faulty program. We incorporated these static analysers following evidence from a user study demonstrating their effectiveness in detecting issues in students’ programming assignments (see Section 8). Input operations, such as `scanf`, are translated into array reads representing program inputs, while output operations, such as `printf`, are converted into array writes capturing the program’s output. Each program exit point (e.g., a return statement in the main function) is replaced with a `goto` statement that redirects control flow to the scope of the next failing test. Furthermore, to prevent the C compiler from zero-initialising global variables by default, all uninitialised global variables are explicitly assigned nondeterministic values.
