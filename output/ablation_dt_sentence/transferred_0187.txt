The temporal phase classification, workload balance quantification, and phase-specific strategic frameworks are integrated into the workflow through Node 1 (Phase Detection), which serves as the initial reasoning checkpoint in the nine-node LTAA architecture. This node receives the current system state and computes the temporal context required for downstream reasoning stages. The Phase Detection Node evaluates task progress and updates workload-related metrics to inform the next steps in the reasoning pipeline. As illustrated in Figure 9a, it receives four key state variables from the system: the number of completed and total tasks, the current workload distribution across robots, and the ideal target workload. These parameters collectively define the allocation context at each iteration of the process. Within this node, the framework calculates the current progress ratio and classifies the system’s operational phase as early, middle, or late. Each phase constitutes a distinct decision context that guides how subsequent reasoning nodes adjust success rates and maintain workload fairness. The node then calculates a balance score to quantify task distribution uniformity and assess imbalance severity based on deviation from the ideal workload. These metrics encapsulate temporal progress and workload dynamics in a compact form. The node concludes by updating the system state with four derived parameters—allocation_phase, balance_score, imbalance_severity, and operational_mode—which are propagated to the next node in the workflow. This ensures that all downstream stages operate with the most current contextual understanding of progress and workload conditions. As shown in Figure 9a, this process forms a unidirectional flow in which the Phase Detection Node transforms raw operational data into structured decision context for subsequent reasoning. The phase-adaptive allocation strategy depends on robust LLM reasoning to make context-sensitive decisions. However, LLM outputs exhibit inherent variability and may fall short of safety standards required for construction-related applications. To mitigate the generation inconsistencies identified during the SMART-LLM implementation, the authors developed a comprehensive validation framework that ensures reasoning quality through a weighted multi-criteria assessment and structured feedback mechanisms.
