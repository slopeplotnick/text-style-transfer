Exemplar Selection: Certain algorithms, such as OPRO and EvoPrompt, do not incorporate few-shot examples. However, they can still significantly improve the performance of large language models, even when utilizing relatively simple selection methods. In contrast, promptsolution includes an additional module for post-hoc exemplar selection, which employs random selection and random search techniques to integrate few-shot examples into a fixed instruction. Initial Prompt Creation: Many prompt optimization algorithms require an initial pool of candidate prompts to begin the search process. To address this, we provide tools that automatically generate prompts from a task description, a foundational prompt, or examples extracted from a dataset. Callbacks: The base class for optimizers supports callbacks, allowing for the tracking of optimization progress. These callbacks can access the state of the optimizer at every step, and can optionally halt the process when necessary. Key implementations include the TokenCountCallback, which monitors token usage and halts optimization if a specified threshold is exceeded, and the FileOutputCallback, which logs prompts and their corresponding scores to a file for subsequent analysis. Setup: To evaluate promptsolution and contextualize its performance relative to other tools, we conduct prompt optimization experiments on the widely used GSM8K (grade-school math reasoning) and SST-5 (fine-grained sentiment classification) datasets. We utilize gemma-3-27B as the primary language model, and, where applicable, also use it as the meta-model for optimizers requiring one. Further details regarding the datasets and setup configuration are provided in Appendix A.2. For comparison, we include the optimizers CAPO, EvoPromptGA, and OPRO from the promptsolution framework, alongside leading optimizers from the AdalFlow and DSPy frameworks. To assess the impact of optimization, we also evaluate three manually crafted prompts per dataset and compute their average performance. To ensure a fair comparison, we retain identical hyperparameter settings for all optimizers. Additionally, we restrict the combined input and output token budget to one million, which corresponds to an inference cost of under $0.15 for this model. All frameworks are initialized from a single task description, without any pre-existing prompts, to test the fully automated optimization process. Both the unoptimized prompts and the optimal prompts identified by each optimizer, based on validation performance, are evaluated on a separate test set.
