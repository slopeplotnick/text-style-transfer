The differing approaches of the agents highlight significant variations in their problem-solving strategies. SWE-agent Dev commences by identifying the bug within the client.py file and proceeds through a multi-step process: creating a reproduction test, editing various parts of the file, attempting a sequence of edits, and finally validating the patch through the reproduction test before submission. In contrast, SWE-agent DSK-V3 localizes the bug, performs a single edit, and submits the patch without validation. Despite both agents ultimately achieving success, they encounter notable challenges. Specifically, SWE-agent Dev methodically edits the client.py file in a step-by-step fashion, with two failed attempts before making a conclusive alteration. Conversely, SWE-agent DSK-V3 efficiently resolves the bug with a single patch generation. Importantly, neither agent performs regression tests for patch validation; instead, SWE-agent Dev relies on reproduction test outcomes, while SWE-agent DSK-V3 focuses on edge case correctness. This example underscores that process-centric analysis, which emphasizes trajectory examination, can provide deeper insights into agents' problem-solving capacities. However, recent efforts to document agentic workflows through manual analysis face biases and limitations, failing to scale to new systems. Moreover, analyzing sequential steps alone does not effectively illustrate agent behaviors and decision-making efficiency.
