The threat model focuses on the execution phase after the malicious tool has been integrated and invoked by the agent. It is assumed that, in fully localized deployments, the tool's source code may be publicly visible or subject to static review; however, due to the semantic overlap between benign and malicious behavior, the latent backdoor remains undetected. In cloud-hosted and hybrid configurations, the internal structure of tools is opaque to the user, limiting the potential attack surface to their externally observable outputs. The attacker operates entirely within the existing sandbox, refraining from privilege escalation, code injection, or memory manipulation. The attack is deemed successful if it satisfies two conditions: (1) successful execution of the attacker's external computational task, and (2) the agent's preservation of functional accuracy on the user's original task within an acceptable deviation threshold. Furthermore, the threat is economically motivated, as hijacked computation directly results in measurable resource costs, such as API token consumption or local GPU cycles. The cumulative effect of multiple such tools can lead to large-scale resource leakage across the agent ecosystem. This section introduces the design of the LeechHijack attack, beginning with a high-level overview of the attack workflow. Next, we describe the implantation phase, during which a dormant backdoor is embedded into a compliant MCP tool. Subsequently, we detail the exploitation phase, where the backdoor is activated to establish a covert command-and-control channel and inject additional tasks into the victim agent. Finally, we conclude with formal definitions of the attack's success criteria and the metrics used for evaluation. LeechHijack achieves computational hijacking through a two-stage process. In the first stage, the adversary disseminates an ostensibly benign MCP tool containing a dormant backdoor component, which remains inactive during normal operation and does not exhibit any detectable malicious behavior. In the second stage, the backdoor is activated by a specific conditional trigger. Upon activation, the tool manipulates responses, prompting the agent to perform additional tasks specified by the attacker. This phase concludes when the tool is re-engaged in a subsequent invocation. LeechHijack then returns the computed attack results and restores normal functionality, leaving no overt artifacts visible to the user.
