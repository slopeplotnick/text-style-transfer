In more detail, the rule for relaxing a general program statement is to envelop the statement with an if-statement, whose condition is a relaxation variable. For example, lines 5 and 6 in the program on Listings 3 are relaxed by CFAULTS through the use of relaxation variables _rv1 and _rv2 respectively, which appear as lines 11 and 12 in Listings 4. Moreover, when relaxing if-statements, the statements inside the then and else blocks follow the same relaxation rule described previously. However, the conditions of if-statements are relaxed using a ternary operator, as shown in line 14 of Listings 4. If the relaxation variable is assigned true, the original if condition is evaluated; otherwise, a distinct relaxation variable (e.g., _ev4 in Listings 4) determines whether the program execution proceeds into the then-block or the else-block, if one exists. These else relaxation variables are scoped locally to each failing test and allow different tests to control whether the execution enters the then or else-block. When handling expression lists, CFAULTS employs a similar strategy to that used for general program statements, enclosing each expression within a ternary operator instead of an if-statement. If the program component is deactivated, the corresponding expression is replaced with 1. For instance, the initialization of variable i in line 11 of Listings 3 is transformed into a ternary operation in line 17 of Listings 4. Lastly, all relaxation variables within a loop are represented as Boolean vectors, which are used to relax statements across iterations. Each element of these vectors corresponds to the relaxation of a statement in a specific loop iteration. The maximum number of loop iterations is specified by the CFAULTS user. CFAULTS applies a similar approach for inner loops by constructing arrays of arrays. Thus, for simple program statements inside a loop, CFAULTS wraps them in if-statements, indexing the relaxation variables by the iteration number. Line 20 of Listings 4 demonstrates such a relaxed statement inside a loop. The loop condition itself is relaxed via a relaxation variable, as illustrated in line 18 of Listings 4. Furthermore, each loop maintains its own set of offsets to index relaxation variables; these offsets are initialized immediately before the loop and incremented at the end of each iteration, as shown in line 19 of Listings 4.
