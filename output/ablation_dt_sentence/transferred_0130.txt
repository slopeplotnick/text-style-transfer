All components of the system are designed to function cohesively within a shared configuration, ensuring seamless interchangeability while maintaining full compatibility with the overall framework. Although each component can be configured independently, the ExperimentConfig object, along with associated utility functions, offers a unified mechanism for specifying all configuration parameters collectively. This setup enables centralized control over experimental settings, streamlining the configuration process. The LLM component is utilized to obtain responses by leveraging the inferential and generative capabilities of a large language model. Its core configuration supports the parallel execution of multiple operations and systematically monitors total token consumption across both input and output streams. APILLM facilitates the use of models via an API, supporting common providers such as OpenAI and Anthropic. Listing 3 (L.1-5) provides an example of the configuration using the DeepInfra API. In contrast, LocalLLM enables the deployment of models on local machines using transformers (Wolf et al., 2020). Meanwhile, VLLM integrates the v11m library to efficiently manage high-volume requests, demonstrating robust performance in GPU-accelerated environments. The Predictor component specifies the method by which answers are extracted from the model’s output. For classification tasks, only the predicted class is extracted, while for mathematical reasoning tasks, the final solution is obtained. One class of predictor identifies the earliest occurrence of any candidate response within the generated output and selects this instance as the predicted result. Another, more reliable variant, identifies responses enclosed within designated tags. To calculate the total number of fish across all fishbowls, one would incrementally sum the quantities—starting with 62 fish, then adding the 3 fish from another bowl, resulting in a total of 65 fish. The *Task* component encapsulates relevant data and specifications that define the intended operation, maintaining all information needed to determine the required actions within the workflow. It also governs the criteria for testing prompts, ensuring that only necessary prompts are evaluated, thus optimizing the time efficiency of the evaluation process. This functionality is critical for achieving optimal results while minimizing resource expenditure. We implement a set of tasks relevant to natural language processing.
