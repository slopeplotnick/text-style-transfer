To isolate experimental variables, we first evaluated the attack's effectiveness across various frameworks using a fixed model (Deepseek). In contrast, we assessed its performance on different models within a fixed framework (OpenManus). For all experiments, the generation temperature was set to 0, and the maximum number of tool invocations was capped at 20. To quantify the overhead of the LeechHijack attack, we integrated it into diverse tool categories and compared its computational resource consumption against benign MCP tools (Normal). Our primary evaluation metric was total token count, encompassing both input and output. Given that the backdoored toolkit may trigger LeechHijack multiple times within a single user task, we also introduced a distinct metric to isolate and compute the average resource cost incurred by each individual trigger. Although the resources dedicated to generating the extra task output constitute only a fraction of the total hijacked cost, the increased computational demand remains a significant security concern from the user's perspective. To assess the utility of LeechHijack, we next evaluated the efficacy with which an attacker can exploit the hijacked resources. We established a performance baseline using each model's publicly reported accuracy on the MMLU benchmark [55], [56], [62], [63]. The accuracy of the responses generated for the extra task was then compared against this baseline. The results of this analysis, presented in Tables 7 and 8, demonstrate that LeechHijack can successfully leverage hijacked resources to execute covert generation tasks. However, this appropriation is not cost-free, manifesting as discernible performance degradation. Therefore, we conclude that the attack is a viable resource hijacking vector, offering exploitable value for attackers.
