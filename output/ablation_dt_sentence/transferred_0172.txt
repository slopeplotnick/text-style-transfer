Inefficiencies are common even in runs that appear to be resolved, though typically to a lesser degree. In contrast, unresolved runs often accumulate multiple localization or editing anti-patterns within a single trajectory. Despite their higher success rate, stronger models, such as Claude-4, tend to exhibit more inefficiencies, likely due to their increased internal exploration. Over the past year, a significant number of autonomous agents have emerged for automating issue resolution and software engineering tasks. These SWE agents can be broadly categorized into two architectural approaches: single-agent and multi-agent systems. Single-agent systems, such as SWE-agent and OpenHands, utilize a unified ReAct loop, whereas multi-agent systems, including CodeR, Magis, and MASAI, deploy multiple specialized agents for distinct tasks that map to different phases outlined in Section 2.1. These tasks include searchers that collect relevant code snippets, reproducers that create and verify reproduction scripts (Localization), programmers that implement code modifications (Patching), and testers that validate changes (Validation). GRAPHECTORY can be readily applied to multi-agent systems by merging the individual trajectories from sub-agents into a unified trajectory. An additional dimension for categorizing SWE-agents is their tool usage. Some agents, such as Agentless, operate without external tools, relying solely on LLM prompting strategies. Other agents, such as TRAE, CGM, and MarsCode Agent, employ traditional retrieval mechanisms (e.g., BM25) and embeddings for semantic search, alongside code knowledge graphs and language server protocols, to aid in project comprehension and retrieve code entities. Without GRAPHECTORY, comparing and contrasting these approaches would be a daunting task. The integration of GRAPHECTORY and LANGUTORY, however, allows for the systematic categorization of these sophisticated tools within a common Localization phase. Since the release of Claude 3.5 Sonnet, SWE agents, including SWE-agent and OpenHands, have increasingly adopted bash commands for code search and the 'str_replace editor' tool for viewing and editing files. This shift in tool usage led us to select SWE-agent and OpenHands as the SWE agents for our experimental evaluation.
