The previous approach to relaxation was inadequate, as it failed to address non-terminating loops, such as those where the loop condition is perpetually assigned a true value. In contrast, our current method mirrors the structure of if-statements, incorporating else relaxation variables to manage the execution path when the original condition is deactivated. This enhances the understanding of various potential execution paths, even when loops may not terminate. Moreover, when dealing with auxiliary functions, CFAULTS initializes the necessary relaxation variables in the primary scope of the program, utilizing them as needed. As a result, the same variables are consistently employed whenever the respective functions are invoked. Similarly, identical program components, such as statements and instructions, rely on the same relaxation variable defined within the main scope. Therefore, when a relaxation variable is assigned false, the associated program component is effectively disabled during all test executions. Furthermore, the relaxation variables in Listing 5 are not initialized initially, allowing CFAULTS to identify the minimal set of components that must be deactivated. It is important to note that these relaxation variables are not declared as global variables; instead, they are localized within the main scope to prevent the C compiler from automatically initializing all variables to false.
