**Pre-Execution Defenses.** Prior to execution, the constituent components of the agent undergo a systematic inspection to assess their safety and compliance with predefined security requirements. Tools such as MCP-watch are specifically designed to audit the source code of components integrated with the agent. Concurrently, frameworks like MCP-scan [20] systematically examine MCP servers to identify a range of security vulnerabilities, including those susceptible to manipulation or tampering. **Runtime Defenses.** During the agent's operation, dynamic defenses are crucial for real-time threat mitigation. Several approaches have been proposed in this regard. For example, SLM as Guardian employs a compact model to detect potentially harmful user queries. Furthermore, to mitigate prompt injection attacks, this approach enforces a strict separation between developer prompts and user-provided data, thereby strengthening the system against manipulation attempts that seek to conflate these two channels. **Post-Execution Defenses.** Following execution, the agent’s actions are analyzed to identify potential issues. The LLM-as-a-Judge paradigm provides a cost-effective alternative to human evaluation; however, its efficacy is limited by its reliance on predefined risk signatures and its reduced robustness when addressing novel or unforeseen security threats. In this context, we examine a contemporary LLM-agent configuration that adheres to the Model Context Protocol (MCP). The LLM within the agent functions as a central coordinator that interprets user instructions, derives intermediate reasoning procedures, and orchestrates the invocation of external tools to accomplish the designated tasks. Each MCP tool operates independently within the agent, interfacing with the LLM via a standardized API protocol. During task execution, the LLM maintains an awareness of the ongoing context, allowing seamless transitions across tool invocations to facilitate coherent multi-step reasoning. In this architecture, the LLM serves as the primary reasoning component, while auxiliary tools are responsible for executing specialized, well-defined functions. **Adversarial Model.** The adversary aims to exploit the agent’s computational resources without obtaining elevated privileges or compromising the integrity of the host system. This adversary is modeled as a third-party developer who creates and distributes MCP tools within the open market. Notably, the adversary cannot observe the internal workings of the agent or alter the system's operational rules.
