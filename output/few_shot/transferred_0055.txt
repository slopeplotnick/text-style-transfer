In order to simplify a program statement, it is encapsulated within an if-statement using a condition known as a relaxation variable. For instance, in the program presented in Listings 3, lines 5 and 6 are modified by CFAULTS through the utilization of relaxation variables _rv1 and _rv2, which appear as lines 11 and 12 in Listings 4. When relaxing if-statements, the content within the then and else clauses adheres to the same relaxation principle. However, for the conditions of if-statements, a ternary operator is employed, as illustrated in line 14 of Listings 4. If the relaxation variable evaluates to true, the original if condition is executed. Otherwise, an alternative relaxation variable (e.g., _ev4 in Listings 4) determines whether the program progresses into the then-block or the else-block, if present. These relaxation variables are tailored to each failing test and assist in deciding whether to proceed into the then or else-block. For expression lists, CFAULTS applies a mechanism analogous to that for general program statements, placing each expression within a ternary operator rather than an if-statement. If a program segment is deactivated, the expression defaults to 1. For example, the initialization of variable i in line 11 of Listings 3 is transformed into a ternary operation in line 17 of Listings 4. All relaxation variables within a loop are Boolean vectors employed to relax statements within the loop. Each element of these vectors relaxes the loop's statements for each iteration. The CFAULTS user specifies the maximum number of loop iterations. CFAULTS similarly processes inner loops, constructing arrays of arrays. For simple program statements within a loop, CFAULTS wraps them with if-statements, associating relaxation variables with the iteration number. Line 20 of Listings 4 presents a relaxed statement within a loop. The loop's condition is relaxed via the relaxation variable, as demonstrated in line 18 of Listings 4. Each loop possesses its own offsets to index relaxation variables, which are initialized immediately prior to the loop and incremented at the conclusion of each iteration, as shown in line 19 of Listings 4.
