Recent advancements in Software Engineering (SWE) Agents have gained significant traction, especially over the past year, in addressing automated issue resolution and software engineering tasks. SWE Agents can broadly be categorized into two main types: single-agent and multi-agent systems. Single-agent systems, such as SWE-agent and OpenHands, operate within a singular execution loop. Conversely, multi-agent systems (e.g., CodeR, Magis, and MASAI) utilize distinct agents for discrete tasks, including code snippet retrieval, reproduction script generation and verification, code modification, and testing. The GRAPHECTORY framework integrates the outputs of these agents by consolidating their respective paths into a unified process flow.  An alternative classification of SWE agents is based on their tool usage. Certain agents, such as Agentless systems, eschew external tools, relying instead on prompting methodologies. Others incorporate traditional search mechanisms and embeddings to locate relevant files. Advanced systems, including TRAE, CGM, and MarsCode Agent, leverage sophisticated frameworks such as code knowledge graphs and language server protocols to analyze projects and identify code entities. The absence of GRAPHECTORY would render comparisons between these methodologies significantly more challenging. When combined with LANGUTORY, GRAPHECTORY facilitates seamless integration of these tools into the Localization phase of the software engineering workflow. Notably, since the advent of Claude 3.5 Sonnet, SWE agents such as SWE-agent and OpenHands have adopted advanced functionalities, including the utilization of bash commands for code search and tools for file inspection and modification. Consequently, SWE-agent and OpenHands were selected for the experimental evaluations conducted in this study.
