TCAS is a widely recognized program extensively utilized in empirical studies focused on identifying faults in software code. It is a C program derived from the Siemens suite, consisting of 41 versions with deliberately injected bugs for research purposes. Conversely, C-PACK-IPAs comprises a collection of student-generated programs sourced from an introductory programming course, encompassing 25 assignments and 1,431 buggy implementations derived from three laboratory sessions. These programs address fundamental programming concepts, including numerical computations, input-output handling, control loops, character processing, and vector manipulation. C-PACK-IPAs has proven valuable for evaluating various program analysis tasks.  For this study, the CFAULTS framework employs pycparser to interpret C programs and CBMC version 5.11 to convert C programs into Conjunctive Normal Form (CNF) formulas. To identify software bugs, new implementations of BugAssIST and SNIPER algorithms were developed, as their original versions were either unavailable or non-functional. The legacy SNIPER algorithm was limited in its capability to handle features such as loops, recursion, and specific variable types in C programs. Similarly, a modified version of the HSD algorithm was introduced to support fault localization in C programs, both with and without the core minimization feature, overcoming the original version's restriction to Boolean circuit analysis. The updated BugAssIST, SNIPER, and HSD algorithms were all integrated with components of the CFAULTS framework.  The experimental evaluation demonstrates that all tested algorithms produce outputs that meet predefined correctness criteria, verified using CBMC. This verification is particularly critical for BugAssIST, which may generate results that fail to align with all failing test cases. However, the MaxSAT-based solution of CFAULTS and the HSD algorithm consistently produce outputs that align with all observed failing scenarios. In contrast, SNIPER's method ensures correctness but may yield results that are not optimal in terms of simplicity. For BugAssIST, a scoring system is applied to iteratively assess the generated outputs until an observation-matching solution is identified.
