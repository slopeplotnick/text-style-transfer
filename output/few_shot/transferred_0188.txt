We assume no prior knowledge about the variables under measurement, except that the data consists of continuous readings with a constrained mean and variance. Consequently, energy usage is modeled as a normal distribution, as this approach avoids introducing additional assumptions and simplifies the mathematical framework, thereby expediting the analysis process. To enhance computational efficiency and accuracy, we employ a multi-level model with a non-centered parametrization. The implementation is conducted in Java 21, though the methodology is compatible with any statically typed language supported by the Java Virtual Machine (JVM). The investigation focuses on a subset of Java to evaluate the efficacy of the proposed method. All Java code is translated into Java bytecode via the OpenJDK 21.0.6 compiler.   To minimize external variability and ensure the reported energy measurements reflect worst-case energy consumption, several controls are applied. These include disabling dynamic class unloading and Just-In-Time (JIT) compilation in the Java runtime environment, restricting execution to interpreted-only mode, setting the CPU clock speed to a fixed 1.5 GHz, and deactivating wireless networking on the evaluation platform. The benchmarking framework consists of 174 microbenchmarks, each defined by a combination of operation, data type, and data size. Investigated data types include 32- and 64-bit integer and floating-point types, as well as reference types for arrays and objects. For instance, addition operations for `int`, `long`, `double`, and `float` types yield three distinct bytecode patterns per data size, resulting in a total of 12 addition patterns. Operations involving arrays and objects differ from those for primitive data types; for arrays, one instance per primitive data type of size one is modeled. For objects, the modeling is based on classes and static nested classes, each comprising four fields, one for each primitive data type.
