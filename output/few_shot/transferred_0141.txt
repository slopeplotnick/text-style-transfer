Previous attempts to relax constraints were ineffective, primarily due to their inability to handle non-terminating loops, such as those perpetually set to a true condition. The current methodology adopts a different approach by incorporating a process akin to the handling of if-statements, introducing else relaxation variables to control outcomes when the original condition is deactivated. This strategy facilitates comprehensive understanding of the program’s execution pathways, including scenarios with non-terminating loops. In the context of auxiliary functions, CFAULTS initializes the relaxation variables within the main program structure and utilizes them accordingly. Consequently, these variables maintain consistency across multiple function invocations. This ensures that when a relaxation variable evaluates to false, the corresponding program segment remains inactive across all test cases.
