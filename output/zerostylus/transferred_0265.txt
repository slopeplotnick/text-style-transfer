GraphMatch demonstrates effective performance on cold start nodes, comparable to TextMatch-small. This indicates the model's ability to effectively utilize text embeddings in the absence of graph information, addressing the cold start problem. The real-time deployment architecture of GraphMatch is composed of three primary components: a feature store, an inference service, and a graph database. This modular design ensures a shared, universal graph structure across diverse use cases, while permitting individual Graph Neural Network (GNN) models to leverage tailored node features. Furthermore, node sampling is implemented using Cypher, allowing users to specify the node and edge types required for inference by defining customized sampling criteria. The feature store primarily aggregates statistical measures such as counts and averages, which are integral for analysis and interpretation. To manage feature data effectively, the system employs Snowflake—a centralized data warehouse that stores replicas of production databases and a variety of business data. Feature tables are generated through hourly SQL Mesh extract-transform-load (ETL) jobs and maintained within the Feast framework. Since features update hourly, default values are employed to handle missing node features when entities exist in the graph but have not yet been integrated into the feature repository. The underlying graph database is hosted using Neo4j Aura, which facilitates robust graph data management. To maintain up-to-date graph state, two distinct ETL pipelines are utilized: a near real-time Kafka pipeline for highly dynamic entities, such as job posts, and an hourly Airflow batch pipeline for other entity types. Moreover, minimal node properties, including type, ID, and creation timestamp, are stored within the graph database to enable precise subgraph sampling during inference. Model inference is executed via a Python/FASTAPI microservice, deployed on EC2 instances equipped with Nvidia A10G GPUs, which provide 24GB of RAM for efficient and scalable serving. Autoscaling is determined based on requests per second, as GPU and CPU utilization metrics are less reliable indicators of latency under increasing workload conditions. To optimize inference efficiency, TextMatch embeddings are computed and cached whenever freelancer profiles or job post descriptions are updated. Consequently, online inference is limited to processing only the GNN layers, reducing computational overhead. This approach achieves embedding generation times of less than 70 milliseconds per embedding across all entity types, supporting horizontal scalability and enabling near real-time applications.
