We lack a priori knowledge regarding the variables under investigation, except that our measurements are continuous with a finite mean and variance. Therefore, we adopt a Gaussian distribution model for energy consumption, as delineated in Equation 1. This choice facilitates mathematical tractability without introducing unnecessary assumptions, thereby streamlining the evaluation process compared to more complex distributions. Moreover, we implement a multi-level model with a non-centered parameterization, as detailed in Section 2, which enhances computational efficiency and convergence rates while preserving the integrity of our results. Our methodology is implemented in Java 21, although it remains applicable to any statically typed language compatible with the JVM. We specifically focus on a subset of Java, as outlined in Table 1, to assess the methodology's efficacy. The OpenJDK 21.0.6 compiler translates all Java source code into Java bytecode. To ensure that energy measurements reflect the worst-case energy consumption (WCEC) and to mitigate external interference, we implement several controls: disabling dynamic class unloading and JIT compilation in the Java runtime system, and setting the system to operate solely in interpreted mode. Furthermore, the execution platform is configured with the CPU frequency at its minimum value of 1.5GHz, and wireless networking capabilities are disabled. The benchmark configuration comprises 174 discrete evaluations, each parameterized by operation, data type, and data size. We examine 32- and 64-bit integers and floating-point data types, as well as reference types for arrays and objects. In contrast, operations on basic data types differ from those involving arrays and objects; thus, we model one array per fundamental data type, specifically limited to a size of one.
