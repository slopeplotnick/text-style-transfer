This study encodes the process of identifying system faults as a model-based diagnosis problem, utilizing multiple observations within a single optimisation framework. All failing test cases are integrated into a unified MaxSAT formula, thus enabling a comprehensive representation of the problem. Consequently, this approach identifies the minimal set of diagnoses necessary to detect all malfunctioning components within systems such as C programs and Boolean circuits. The procedure for this is detailed in Algorithm 5. It is assumed that the system remains invariant across different observations; therefore, its components are replicated for each observation while the functional components are shared. By considering all observations collectively rather than individually, the interactions between individual components are influenced, which subsequently leads to changes in their behavior. This paper introduces CFAULTS, a fault localisation tool tailored for C programs and Boolean circuits, designed to effectively identify faults across multiple failing tests. To enhance compatibility with alternative model checkers, CFAULTS adopts the approach outlined in Section 4.2, whereby relaxation is applied directly at the code level to C programs. Figure 1 delineates the procedural stages of CFAULTS, which include system unrolling, integration of the tool into the system, model verification via CBMC, transformation into MaxSAT, and the application of a MaxSAT solver as an Oracle. Prior to unrolling the C program, CFAULTS employs static analysers CPPCHECK and CLANG-TIDY to systematically identify issues such as uninitialized variables and potential runtime errors, including division by zero. In the event of identified issues, CFAULTS promptly reports them to the user; otherwise, it proceeds with deconstructing the erroneous program. Following an investigation that demonstrated their efficacy in identifying issues within students' programming assignments, these tools were subsequently incorporated. Moreover, input operations like scanf are replaced with array-based input techniques, while output operations such as printf are substituted with array-based output methods, thereby aligning the program's input and output management with buffered approaches. Ultimately, each exit point of the program, such as a return in the main function, is converted into a goto statement, directing the program to the section corresponding to the next failing test. This is to prevent the C compiler from automatically initializing uninitialized global variables to zero by setting them to random values.
