The previous attempts at applying relaxation were largely ineffective as they did not adequately address scenarios involving non-terminating loops, which persist due to conditions that remain perpetually true. In contrast, this approach employs a method analogous to the handling of if-statements, wherein else relaxation variables are introduced to control behavior when the original condition is deactivated. This strategy serves to facilitate the comprehension of the various execution pathways available to the program, even in instances where certain loops may not terminate. Moreover, when additional functions are employed, CFAULTS systematically arranges the relaxation variables within the main program structure and utilizes them as necessary to ensure consistent use each time those functions are invoked. Consequently, Listing 5 illustrates the program's structure following the application of CFAULTS to the code presented in Listing 2. It is noteworthy that the same relaxation variable, defined in the main section of the program, governs the execution of repeated components such as statements and instructions. Furthermore, if the relaxation variable is assigned false, the corresponding segment of the program is not executed during any test. To optimize performance, the relaxation variables in Listing 5 are initialized only when necessary, thereby enabling CFAULTS to determine the minimal set of components to deactivate. Importantly, these relaxation variables are localized to the main part to prevent the C compiler from automatically setting them all to false.
