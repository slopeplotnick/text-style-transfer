The threat model examines the scenario that unfolds following the deployment and utilization of a harmful tool by an agent. It is hypothesized that, even though the tool's source code could potentially be scrutinized or audited, the semantic similarity between malicious and benign actions renders the latent backdoor undetected. In cloud or hybrid configurations, the internal mechanisms of tools are inherently obscured. Therefore, the risk assessment is limited to observable outputs alone. Interestingly, contrary to what might be expected of an attacker attempting to compromise system integrity, the tool's behavior consistently adheres to predefined parameters, without engaging in privilege escalation or memory manipulation. The attack is deemed successful if it fulfills two conditions: first, it must complete the adversary's intended task; second, it must ensure the agent remains effective in executing the user's task with minimal disruptions. The primary concern, therefore, pertains to the financial implications of such attacks. The costs associated with erroneous computational resource utilization are twofold: the depletion of API tokens, leading to financial loss, and the consumption of GPU time, which incurs additional monetary costs. Moreover, many tools performing similar functions exhibit resource inefficiencies. This section details the LeechHijack attack, which infiltrates a victim's agent system through legitimate tool invocations. Preliminary considerations outline the foundational concept underlying the attack's mechanism, which involves embedding a covert backdoor into a compliant tool. This backdoor employs a method to establish a clandestine channel and assign additional tasks to the agent. Criteria for the effectiveness of the attack and its evaluation metrics are subsequently concluded. LeechHijack is implemented through a dual-phase process: it initially establishes control over computing functions, deploying the tool with an innocuous appearance yet concealing a backdoor. Notably, the backdoor remains inactive during standard operations, exhibiting no malicious behaviors. It is only activated via a predetermined trigger mechanism. Upon activation, the tool alters responses, thus necessitating further effort from the agent to meet the attacker's objectives. The completion phase concludes with the tool's subsequent utilization, ensuring the primary functionality remains unaltered. Ultimately, LeechHijack seamlessly restores the system to its initial state post-attack, leaving no visible indicators for user detection.
