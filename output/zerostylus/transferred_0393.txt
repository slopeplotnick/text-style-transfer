TCAS is a widely recognized program benchmark frequently utilized in studies concerning fault detection within code. The Siemens program benchmark consists of a C program and 41 versions wherein known bugs were intentionally introduced, thus providing a controlled environment for testing fault localization methods. Conversely, the C-PACK-IPAs suite encompasses a collection of student programs originating from an introductory programming course. For this analysis, the complete C-PACK-IPAs set was employed, comprising twenty-five assignments and a total of 1431 defective programs derived from three laboratory classes. These programs encompass operations related to numerical processing, input-output mechanisms, iterative constructs, character manipulation, and vector handling. The C-Pack-IPAs benchmark has proven beneficial for evaluating a variety of program analysis tasks. In this manner, CFAULTS utilizes the pycparser tool for manipulation of C programs, while CBMC version 5.11 is employed to convert C programs into CNF formulas. However, since the original source code for BugAssIST and SNIPER is either unavailable or non-functional, new versions of their algorithms were developed and implemented. Notably, the legacy SNIPER system was capable of functioning with select C programs but encountered difficulties with loops, recursion, and certain variables. Due to the limitations of the previous version, which functioned solely with Boolean circuits, a novel iteration was developed for HSD to identify defective code in C programs, incorporating the option of core minimization. Following the integration of components from CFAULTS, BugAssIST, SNIPER, and HSD can now effectively interface with C programs. The tested algorithms consistently produced results that adhered to specific criteria, verified for correctness using CBMC. Primarily, this verification targets BugAssIST, as it may produce outcomes that do not correspond to all the specifications of the failing tests. Despite CFAULTS and HSD utilizing different methodologies, their approaches consistently align with all observed data. The SNIPER method produces accurate results; however, these results may not represent the most straightforward solutions. Finally, given the scoring mechanism utilized by BugAssIST, the procedure involves systematically reviewing the generated outputs until an instance is identified that aligns precisely with the observed criteria.
