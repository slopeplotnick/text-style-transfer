The approaches of the agents, SWE-agent Dev and SWE-agent DSK-V3, differ significantly in their problem-solving sequences. SWE-agent Dev initiates the process by identifying the bug in the client.py file (steps 1-4), then creates a reproduction test (step 5), and proceeds to edit multiple sections of the file (steps 6-8). After two failed attempts at editing (steps 9-10), it revisits and modifies a different section of the client.py file (steps 11-12), executes the reproduction test to validate the patch (step 13), and finally submits the patch (steps 14-15). In contrast, SWE-agent DSK-V3 also begins by localizing the bug to the client.py file (steps 1-6), but it performs a single edit (step 7) and submits the patch without any validation (steps 8-9). Despite both agents ultimately succeeding, they encounter several strategic pitfalls. Notably, SWE-agent Dev edits the client.py file line by line in steps 6-8, repeats a failed edit twice in steps 9-10, and makes a final edit at step 12, whereas SWE-agent DSK-V3 completes the patch in one attempt at step 7. Furthermore, neither agent conducts regression tests for patch validation; SWE-agent Dev merely checks if the reproduction tests pass (step 13), while SWE-agent DSK-V3 considers the correctness of the patch through edge cases (step 8). This example illustrates the importance of process-centric analysis in providing insights into how agents succeed or fail in problem-solving tasks. Recent efforts have focused on analyzing agentic workflows to derive a taxonomy of failure modes through manual, expert analysis. However, while these taxonomies are valuable, manual analysis is susceptible to human bias and incompleteness and does not scale to new agentic systems. More importantly, examining agentic trajectories as a linear sequence fails to capture the nuanced dynamics of agent behavior, such as execution flow, strategic planning, and adaptive reasoning.
