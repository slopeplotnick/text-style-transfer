This study aims to identify patterns indicative of inefficiencies or regressive behaviors within a given system. Unlike prior work that relies solely on manual analysis of trajectories, the structured framework provided by GRAPHECTORY enables us to systematically mine meaningful patterns (§2.3.2). To this end, we focus on identifying a series of heuristics that may signal such behaviors, though they do not necessarily confirm inefficiency or regression. These heuristics are as follows: H1 refers to a large loop, characterized by a series of consecutive actions connected by a back edge, which suggests that an agent performed repeated actions that failed to resolve the issue, thereby requiring a change in strategy. H2 highlights a misalignment between temporal and structural edges, indicating erratic progression where the agent moves back and forth within the project structure instead of maintaining steady exploration. H3 pertains to a long phase length, which reflects an extended sequence of actions without significant progress, signaling potential inefficiencies in task execution. H4 denotes a failure outcome for any node, suggesting possible inefficiencies in reasoning or suboptimal use of available tools or resources. Moreover, RepeatedView occurs when the agent revisits the same structural region, such as a file, multiple times during navigation. This pattern reflects redundant inspections of identical code, often following unsuccessful edits or incomplete localization of the issue. For instance, as shown in Figure 2-a, after two failed edit attempts (step 9), the agent reopens the file client.py (step 10) to refine the localization of the problem. Conversely, ZoomOut refers to scenarios where the temporal order of navigational actions contradicts the structural hierarchy, as the agent moves from a deeper to a shallower level within the project structure. This pattern suggests corrective navigation, where the agent realizes it has entered an incorrect directory or file. For example, as shown in Figure 2-b, after mistakenly entering the directory postgres (step 3), the agent retraces its path to the parent directory /testbed/db (step 4) and subsequently navigates to the correct sibling directory /testbed/db/postgreSQL (step 5) to locate the buggy file client.py (step 6).
