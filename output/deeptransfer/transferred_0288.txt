This paper formulates the fault localisation problem as a Model-Based Diagnosis (MBD) with multiple observations, encoded into a single optimisation problem. To achieve this, all failing test cases (observations) are simultaneously integrated into a unified MaxSAT formula. Consequently, this approach ensures the derivation of only the minimal diagnoses required to identify all faulty components within the system, such as a C program or a Boolean circuit. Algorithm 5 outlines this methodology. Importantly, we assume that the system remains consistent across different observations, wherein components are replicated for each observation while healthy variables are shared. This assumption is crucial as it facilitates the joint analysis of all observations, which may influence the behaviour of the components. This section introduces CFAULTS, a model-based diagnosis tool designed for fault localisation in C programs and Boolean circuits with multiple failing test cases. Unlike previous approaches, CFAULTS adopts the strategy detailed in Section 4.2, where C programs are relaxed at the code level, thereby enabling enhanced utilisation of other bounded model checkers. Figure 1 illustrates the five key steps of CFAULTS: system unrolling, system instrumentalisation, bounded model checking (CBMC), encoding to MaxSAT, and the use of an Oracle (MaxSAT solver). Before unrolling the provided C program, CFAULTS employs the static analysis tools CPPCHECK [36] and CLANG-TIDY [37] to identify issues such as uninitialised variables and potential runtime errors (e.g., division by zero). If any such issues are detected, CFAULTS promptly informs the user; otherwise, it proceeds with unrolling the faulty program. The inclusion of these static analysers was motivated by findings from a user study [38], which demonstrated their effectiveness in aiding the identification of programming errors in students' assignments (see Section 8). Input operations, such as scanf, are transformed into read accesses from arrays corresponding to the inputs, while output operations, such as printf, are converted into write operations to arrays representing the program's output. Additionally, every exit point in the program (e.g., a return statement in the main function) is replaced with a goto statement that redirects the program flow to the scope of the next failing test. Furthermore, to prevent the C compiler from defaulting to zero-initialisation of uninitialised global variables, these variables are explicitly initialised to nondeterministic values.
