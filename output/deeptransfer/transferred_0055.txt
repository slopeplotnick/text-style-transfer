In more detail, the rule for relaxing a general program statement involves enveloping the statement within an if-statement, the condition of which is determined by a relaxation variable. For instance, lines 5 and 6 in the program from Listings 3 are relaxed by CFAULTS using the relaxation variables _rv1 and _rv2, which appear as lines 11 and 12 in Listings 4. Moreover, when relaxing if-statements, the statements within the then and else blocks follow the same relaxation rule as described earlier. However, the conditions of if-statements are relaxed using a ternary operator, as illustrated in line 14 of Listings 4. Specifically, if the relaxation variable evaluates to true, the original if condition is executed. Otherwise, a different relaxation variable (e.g., _ev4 in Listings 4) determines whether the program transitions into the then-block or the else-block, if present. These relaxation variables, which are local to the scope of each failing test, enable different tests to decide whether to enter the then-block or the else-block. When handling expression lists, CFAULTS adopts a similar strategy to that used for general program statements, encapsulating each expression within a ternary operator instead of an if-statement. If a program component is deactivated, the expression evaluates to 1. For example, the initialization of the variable i in line 11 of Listings 3 is relaxed into a ternary operation in line 17 of Listings 4. Additionally, all relaxation variables within a loop are Boolean vectors, which serve to relax the loop's statements. Each entry in these vectors facilitates the relaxation of statements for a specific iteration. The maximum number of loop iterations is defined by the CFAULTS user. Similarly, CFAULTS applies this approach to inner loops by constructing arrays of arrays. For simple program statements within a loop, CFAULTS encapsulates these statements with if-statements, associating the relaxation variables with the iteration number. Line 20 of Listings 4 demonstrates a relaxed statement within a loop. The loop condition itself is relaxed through the implication of a relaxation variable, as shown in line 18 of Listings 4. Furthermore, each loop iteration is associated with unique offsets for indexing relaxation variables. These offsets are initialized immediately before the loop and incremented at the end of each iteration, as exemplified in line 19 of Listings 4.
