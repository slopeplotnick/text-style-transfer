We have no prior knowledge about the parameters under investigation, except that the measurements are continuous and possess finite mean and variance. Therefore, we model energy consumption as a Gaussian distribution, as this choice does not introduce additional assumptions and simplifies further modeling operations by reducing the need for complex calculations, thus expediting our analysis. Moreover, we employ a multi-level model with a non-centered parameterization, an optimization that enhances the efficiency and accuracy of our model without compromising the validity of the results. Our implementation is conducted in Java 21; however, the methodology is applicable to any statically typed language operating on the JVM. We concentrate on a specific subset of Java to evaluate the efficacy of our approach. The entirety of the Java code is compiled into Java bytecode using the OpenJDK 21.0.6 compiler. To minimize external interference and ensure that the energy measurements reflect the worst-case energy consumption (WCEC), we impose strict controls on factors influencing energy usage. Specifically, within the Java runtime system, dynamic class unloading and just-in-time (JIT) compilation are disabled, with execution restricted to interpreted-only mode. Furthermore, the CPU frequency is fixed at its minimum setting of 1.5 GHz, and wireless networking hardware is disabled on the execution platform. The experimental framework comprises 174 microbenchmarks, each parameterized by operation, data type, and data size. In modeling objects, we derive them from classes and static nested classes, each comprising four fields, with one field designated for each primitive data type.
