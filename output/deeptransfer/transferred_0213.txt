UnresolvedRetry represents the scenario where an agent performs multiple consecutive edits on the same file, yet all fail to yield a successful modification. Figure 12-a illustrates such a case, where SWE-agent Dev repeatedly executes str_replace commands on utils.py 183 times, ultimately reaching the cost limit without success. StrNotFound occurs when an edit fails because the specified old string cannot be found in the file, as shown in Figure 13-a. These failures typically arise due to formatting issues or minor text differences. NoEffectEdit happens when the old and new strings are identical, resulting in a meaningless replacement. Figure 13-b exemplifies this, where the command replaces a string with itself, causing no change to the file and wasting execution cost. AmbiguousTarget captures cases where the specified old string appears multiple times in the file, leading to ambiguity about which occurrence should be replaced. Figure 13-c illustrates this, where multiple identical if statements prevent the editor from applying the replacement deterministically, highlighting a key limitation of string-based editing mechanisms. The percentages below the Venn diagrams indicate the proportion of instances exhibiting at least one localization inefficiency pattern. Notably, inefficiencies, although to a lesser extent, are prevalent in resolved instances as well, underscoring the importance of process-centric analysis to enhance understanding of agent behavior. Unresolved cases often involve multiple inefficiency patterns within a single trajectory. Interestingly, stronger models such as Claude Sonnet 4 achieve higher success rates yet exhibit more of these patterns. Manual analysis suggests that the model tends to engage in extended internal reasoning before producing a solution. Although this approach can be beneficial when addressing difficult problems, as evidenced by the model's higher success rate, it also leads to inefficiency when the additional steps do not contribute to better solutions.
