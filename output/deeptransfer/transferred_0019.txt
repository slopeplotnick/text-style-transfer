Our methodology employs a hierarchical model, integrating multiple statistical distributions that independently examine distinct components of the statistical process, thus facilitating the articulation of statistical independence assumptions. For example, while different instances of identical hardware platforms, such as CPUs with the same specifications, and varying instructions exhibit differences in energy consumption, these variations are statistically independent. Our approach defines a Worst-Case Energy Consumption (WCEC) model to ascertain a device's comprehensive energy utilization, as illustrated in Figure 1. This model comprises two integral components: (1) the measurement component, which evaluates the energy consumption of the benchmark harness executed on the target hardware; and (2) the modeling component, which constructs a Bayesian model to represent the energy consumption of the programming language. Several statically typed programming languages are compatible with the Java Virtual Machine (JVM). To facilitate a unified modeling approach for these languages, we assess the energy consumption of bytecode patterns, which represent the translation of the programming language's source code into bytecode by the compiler, as depicted in Figure 2. A microbenchmark comprises a single permutation of a source code statement derived from the complete set of possible data types and sizes for a specific operation, as illustrated in Figure 3. Each microbenchmark measurement is conducted within a measurement cycle that evaluates the current, voltage, and execution time associated with the microbenchmark. Every measurement cycle begins with configuring the multimeter to ensure its readiness for accurate measurement. Subsequently, to attenuate memory-related noise, the garbage collector is activated to purge memory allocations during the measurement cycle. Each microbenchmark cycle is executed ten times to accommodate statistical variations in the measurements. Moreover, a split plot approach is employed, wherein the execution order of the microbenchmark cycles is randomized to avert bias attributable to the sequence of execution.
