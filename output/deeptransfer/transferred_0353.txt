A Software Product Line (SPL) is a methodology that transforms a set of related software systems, sharing common features, into a framework designed to enable the rapid and efficient development of new software products. This extractive process, which involves migrating an existing code base into an SPL, is inherently complex and time-consuming. Moreover, it can significantly disrupt established development practices and processes within the organization. This paper outlines the initial steps taken toward implementing such a transformation. The work was conducted in collaboration with ITK - Predict and Decide, a small and medium-sized enterprise (SME) that decided to migrate its code base into an SPL. As researchers, our role was to provide support and guidance throughout this migration process. The ITK code base is built around a framework called Cross, where software reuse is already a common practice. While this framework resembles an ad hoc SPL, it lacks the models and processes that define a traditional SPL. To assist the developers, we proposed a gradual transition plan aimed at reorganizing both their code base and engineering practices. As a first step, we assessed how the transition was perceived by the staff and provided recommendations to facilitate the process. This paper presents the findings of this preliminary study. Through interviews, we gathered insights into the company’s current practices, expectations for the SPL, and concerns about the migration. The results indicate that most participants were supportive of the transition and expressed a strong willingness to contribute to its implementation. Developers, in particular, were enthusiastic, viewing the migration as both a technical and managerial challenge. However, individuals involved in business operations were more cautious, highlighting potential risks such as increased maintenance complexity and reduced creativity, especially in user interface design.
