File editing tools, such as create, str_replace, and insert, can be used to create or modify a test file for issue reproduction (Localization), amend an application file to fix a bug (Patching), or validate the functionality of a generated patch (Validation). For debugging purposes, testing can either help localize bugs or verify the effectiveness of a generated patch. Agents utilize Python to execute newly created reproduction or regression tests, while pytest is employed for running pre-existing regression tests. Notably, the same tools or commands may serve different purposes depending on the context, thus being assigned to distinct phases. GRAPHECTORY facilitates the computation of process-centric metrics, enabling a detailed analysis of agentic systems. Table 1 outlines six metrics supported by the current implementation of GRAPHECTORY, along with their computational definitions. These metrics quantify the effort exerted by an agent to complete a task. While the values alone cannot determine the utility of the effort, they provide insights into whether the effort aligns with the complexity of the problem or contributes to its resolution. Each metric is explained as follows: Temporal Edge Count (TEC) measures the total number of temporal transitions between actions, with higher TEC values indicating longer execution paths to completion. For instance, Figure 2 illustrates a longer execution chain for SWE-agent Dev (14) compared to SWE-agent DSK-V3 (8). Similar to NC, TEC values tend to increase with problem difficulty, aligning the GRAPHENCY complexity with the intricacy of the problem. Loop Count (LC) measures the frequency with which the agent repeats a previously executed action. As demonstrated later (§3.2), a higher LC may indicate an ineffective strategy, leading to repeated unsuccessful actions, such as the self-loop at edge 9 in Figure 2-a, or necessitating refinements after actions fail to resolve the issue, as shown by the back edge at edge 10 in Figure 2-a (§3.3.2). Alternatively, a higher LC may reflect the agent’s need to re-execute actions incrementally to address complex problems. LC is analogous to Cyclomatic Complexity [35] in traditional software, which assesses branching and the number of distinct execution paths. In GRAPHENCY, branching reflects local reasoning that redirects execution flow to a divergent path. Average Loop Length (ALL) measures the average number of actions performed before repeating a previously executed action. A longer duration before identifying inefficiencies in reasoning suggests deficiencies in the agent’s reasoning or context-gathering processes. Our findings indicate that agents investing in richer context collection during localization tend to exhibit shorter loops, thereby demonstrating an enhanced ability to promptly identify reasoning inefficiencies and adapt their strategies accordingly (§3.2.1 and §3.3.2).
