The system operates on Spring Boot, and the database is hosted by PostgreSQL. Agronomists use Python or MATLAB to build the simulators. The IT team utilizes a central platform, named Cross, which serves as a comprehensive framework for building application code. Initially, this platform was designed to generate Proof of Concepts; however, its purpose has evolved over time, transforming into a foundation for end products. Currently, there are seven variants within the family, managed by three Product Owners. New variants are developed to meet specific client needs, with approximately one new variant introduced each year. The levels of the Architecture Dimension, as outlined in the FEF framework, address the technical methodologies for software construction and define the technical realization of products within the software product line. At Level 1, architectures are confined to single systems, with no apparent focus on reuse. At Level 2, there is a shift towards reusing third-party infrastructure, incorporating standardized software components like middleware, though domain-specific assets are not formally integrated. At Level 3, domain commonality is systematically captured and implemented into a software platform, providing a reference architecture applicable to all applications and primarily emphasizing platform utilization. Nevertheless, this platform does not support configuration variability. At Level 4, both domain commonality and variability are systematically identified, and a reference architecture is established to cover the entire software product line. Domain assets are carefully designed to facilitate product derivation, with explicit attention given to managing variability within the software product line architecture. Finally, at Level 5, the reference architecture becomes central, with application architectures deviating minimally from the established framework. Automated product derivation is enabled through scripts, tools, and high-level programming languages, while application development focuses predominantly on configuration within the reference architecture, thereby enabling automated product configuration.
