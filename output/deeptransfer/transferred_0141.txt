The previous relaxation approach proved inadequate as it failed to address non-terminating loops, particularly scenarios where the loop condition perpetually evaluates to true. However, our current methodology improves upon this by aligning with the relaxation technique applied to if-statement conditions, incorporating else relaxation variables. These variables regulate the execution path when the original condition is deactivated, thereby enabling a thorough analysis of all potential control flow behaviors, including those involving non-terminating loops. Moreover, in the context of incorporating additional functions, CFAULTS establishes the relaxation variables within the primary section of the program and utilizes them as needed. Consequently, these variables are consistently employed each time the functions are invoked. For instance, Listing 5 illustrates the program's configuration after applying CFAULTS to the program depicted in Listing 2. Identical segments of the program, such as statements and instructions, utilize the same relaxation variable established in the primary section. Therefore, if a relaxation variable evaluates to false, that segment of the program is not executed in any test case. Furthermore, the relaxation variables in Listing 5 are not initialized at the outset, allowing CFAULTS to determine the minimal number of segments requiring deactivation. It is important to note that these relaxation variables are local to the primary section of the program, preventing the C compiler from automatically initializing them to false.
