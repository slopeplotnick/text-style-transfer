The previous relaxation approach proved inadequate as it failed to address non-terminating loops, particularly scenarios where the loop condition perpetually evaluates to true. To overcome this limitation, our current methodology mirrors the relaxation technique applied to if-statement conditions by introducing else relaxation variables. These variables regulate the execution path when the original condition is deactivated, thereby enabling a comprehensive analysis of all control flow behaviors, including potentially non-terminating loops. Moreover, when additional functions are incorporated, CFAULTS systematically establishes relaxation variables within the primary section of the program and employs them as needed. As a result, these variables are consistently utilized upon each invocation of the respective functions. Identical program segments, such as statements and instructions, share a consistent relaxation variable established within the primary section. Consequently, if a relaxation variable evaluates to false, the corresponding program segment is excluded from execution in all test scenarios. Furthermore, the relaxation variables in Listing 5 are not initialized at the outset, which allows CFAULTS to determine the minimal number of segments requiring deactivation. Notably, these relaxation variables are local to the primary section of the program rather than global. This design choice ensures that the C compiler does not automatically initialize all such variables to false.
