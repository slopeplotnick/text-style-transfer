GraphMatch demonstrates effective performance on cold start nodes, comparable to TextMatch, which highlights the model's ability to default to text embeddings when graph information is unavailable, thereby mitigating the cold start problem. The real-time deployment architecture of GraphMatch is composed of three main components: a feature store, an inference service, and a graph database. This modular design supports a shared, universal graph structure across various use cases while enabling individual GNN models to utilize customized node features. Node sampling is implemented using Cypher, allowing users to define the specific node and edge types required for inference. 

**Feature Store.** Node features primarily consist of aggregated statistics, such as counts and averages. Snowflake serves as the data warehouse, storing clones of production relational databases and assorted business data. Feature tables are generated and updated hourly through SQL Mesh ETL processes and are maintained in Feast. To address cases where node features are missing from the graph and not yet available in the feature store, default values are defined to ensure seamless functionality.

**Graph Database.** The graph is hosted using the Neo4j Aura graph database. Two distinct ETL pipelines are employed to update the graph: a near real-time Kafka pipeline for highly dynamic entities, such as job posts, and an hourly Airflow batch pipeline for other entities. Within the graph database, only minimal node properties—such as type, ID, and creation timestamp—are stored to facilitate accurate subgraph sampling during inference.

**Inference Service.** Model inference is executed within a Python/FASTAPI microservice framework. The model is deployed on EC2 instances equipped with Nvidia A10G GPUs (24GB RAM). Autoscaling is driven by requests per second, as GPU/CPU utilization proves less reliable for predicting latency degradation under increasing load. To optimize inference efficiency, TextMatch embeddings are precomputed and cached whenever a freelancer profile or job post description is updated. This approach limits online inference to the GNN layers, achieving average embedding generation latencies of less than 70 milliseconds per embedding across all entity types. Consequently, this design supports horizontal scalability and enables near real-time applications.
