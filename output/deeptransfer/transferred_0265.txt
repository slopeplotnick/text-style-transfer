GraphMatch demonstrates comparable performance to TextMatch on cold start nodes, highlighting its ability to default to text embeddings when graph information is unavailable, thereby effectively addressing the cold start problem. The real-time deployment architecture of GraphMatch is composed of three primary components: a feature store, an inference service, and a graph database. This modular design ensures a shared, universal graph structure adaptable to diverse use cases while allowing individual GNN models to utilize customized node features. Node sampling is implemented using Cypher [7], enabling users to define the specific node and edge types required for inference. **Feature Store.** Node features primarily consist of aggregated statistics such as counts and averages. Our data warehouse, Snowflake [30], stores replicas of production relational databases alongside various business datasets. Feature tables are generated and updated hourly through SQL Mesh [32] ETL processes and are managed within Feast [6]. To handle missing features for entities present in the graph but not yet reflected in the feature store, we define smart default values. **Graph Database.** The graph is hosted using Neo4j Aura [24]. Two ETL pipelines update the graph: a near real-time Kafka [2] pipeline for highly dynamic entities like job posts and an hourly Airflow [1] batch pipeline for other entities. Within the graph database, we store minimal node properties—such as type, ID, and creation timestamp—to enable precise subgraph sampling for inference. **Inference Service.** Model inference is executed within a Python/FASTAPI [35] microservice framework deployed on EC2 instances equipped with Nvidia A10G GPUs (24GB RAM). Autoscaling is driven by requests per second, as GPU/CPU utilization proves less effective in predicting latency degradation. To optimize inference efficiency, TextMatch embeddings are precomputed and cached whenever a freelancer profile or job post description is updated. Consequently, online inference is confined to the GNN layers, achieving embedding generation latencies of under 70 milliseconds per embedding across all entity types. This design supports horizontal scalability and enables near real-time applications.
