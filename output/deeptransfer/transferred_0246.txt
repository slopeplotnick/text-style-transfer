Benchmarking the power consumption of LLM inference is fundamentally different from evaluating throughput or latency. Unlike traditional performance metrics, energy consumption is influenced by hardware heterogeneity, software stack complexity, and workload dynamics, all of which vary significantly across deployments. However, existing LLM benchmarks offer limited support for this variability, often assuming fixed configurations, static model sizes, and expensive instrumentation. As illustrated in Figure 1, TokenPowerBench overcomes these limitations through a three-layer architecture: Configuration, Execution & Measurement, and Report Generation. This framework offers a modular, configurable, fully reproducible, and scalable benchmarking methodology tailored to modern LLM inference. Initially, TokenPowerBench assists users in setting up the test environment by selecting the model to run, the inference engine to use, and the prompts to feed into it. To streamline this process, TokenPowerBench provides three plug-and-play modules: a model pool, a prompt-dataset menu, and an inference-engine selector. The model pool includes a diverse set of large language models (LLMs), enabling users to evaluate how architectural design choices impact energy consumption profiles. This selection encompasses standard decoder-only transformers, such as the LLaMA series, and Mixture-of-Experts (MoE) models, like Mixtral, which exhibit distinct computational patterns, particularly in parameter activation and memory access. The benchmark covers a broad spectrum of model sizes, from smaller models with fewer than one billion parameters—suitable for a single consumer-grade GPU—to frontier-scale models like Llama 3-405B, which require multi-GPU and/or multinode distributed inference. This comprehensive approach allows for an analysis of how energy consumption scales with increasing model size and hardware complexity. Moreover, the prompt-dataset menu captures variability in energy consumption by offering built-in support for two representative datasets: Alpaca, featuring short, chat-style prompts, and Long-Bench, which includes extended contexts of up to 10,000 tokens. Users can also supply custom data in CSV or alternative formats, thereby ensuring flexibility in experimentation.
