Moreover, over repeated runs, GPT-4 occasionally demonstrates training example contamination, reusing few-shot example sequences and creating logical errors, such as replacing task objects incorrectly. These inconsistencies revealed the absence of validation mechanisms in the original architecture, directly motivating the implementation of explicit validation and retry systems within the LangGraph framework. This framework's few-shot prompting approach concatenates example demonstrations from three stages—task decomposition, allocation, and code generation—into a single unified prompt. However, appending additional examples to enhance performance on complex tasks caused cumulative token counts to exceed the model's context window, triggering API failures during inference. This scalability bottleneck, where richer context improved accuracy but exceeded feasible input lengths, informed the need for modular prompt optimization and dynamic context management, later integrated into the LTAA framework. Consequently, these two challenges—LLM generation inconsistency and context window limitations—directly shaped the architectural requirements for reliable multi-robot coordination: systematic validation mechanisms to ensure reasoning quality and modular design to manage context constraints. To address these requirements, the authors developed a validation-centric architecture incorporating multi-stage validation, structured feedback loops, and controlled retry mechanisms. Furthermore, to address the limitations identified during the SMART-LLM implementation process and to verify the practical feasibility of LLM-driven reasoning for multi-robot task allocation, a Self Corrective-Agent Framework was developed. Unlike the earlier single-agent reasoning design, this framework implements a multi-stage iterative pipeline consisting of three dedicated agents: Task Decomposition Agent, Task Allocation Agent, and Code Generation Agent. As shown in Figure 2, each agent is coupled with an independent validation node and orchestrated through the LangGraph workflow engine. The Decomposition Agent initiates the pipeline by translating high-level natural-language instructions into a structured sequence of subtasks, identifying task dependencies, environment objects, and the temporal ordering required for successful completion. Subsequently, the Allocation Agent maps these validated subtasks to the most suitable robots based on their capabilities, skill sets, and available resources, while determining execution order.
