Training Example Contamination: Over repeated runs, GPT-4 occasionally reused few-shot example sequences, introducing logical errors, such as replacing task objects incorrectly (e.g., substituting "throw spatula in trash" with objects from "put eggs in fridge"). These inconsistencies highlighted the absence of validation mechanisms in the original architecture, which directly motivated the development of explicit validation and retry systems within the LangGraph framework. This framework employed a few-shot prompting approach that unified example demonstrations from three stages—task decomposition, task allocation, and code generation—into a single cohesive prompt. However, appending additional examples to improve performance on complex tasks led to token counts exceeding the model's context window, resulting in API failures during inference. Consequently, while richer context improved task accuracy, it simultaneously exceeded the model's input length constraints, creating a scalability bottleneck. This challenge underscored the need for modular prompt optimization and dynamic context management, which were later integrated into the LTAA framework. These dual challenges—LLM output inconsistency and context window limitations—directly shaped the architectural requirements for robust multi-robot coordination, emphasizing systematic validation mechanisms to ensure reasoning quality and modular designs to manage input constraints. To address these requirements, the authors developed a validation-centric architecture incorporating multi-stage validation, structured feedback loops, and controlled retry mechanisms. Furthermore, to overcome the limitations identified during the SMART-LLM implementation and to validate the feasibility of LLM-driven reasoning for multi-robot task allocation, a Self Corrective-Agent Framework was introduced. Unlike the traditional single-agent reasoning design, this framework employs a multi-stage iterative pipeline consisting of three specialized agents: Task Decomposition Agent, Task Allocation Agent, and Code Generation Agent. As illustrated in Figure 2, each agent is paired with an independent validation node and orchestrated through the LangGraph workflow engine. The Decomposition Agent initiates the process by converting high-level natural-language instructions into a structured sequence of subtasks, identifying task dependencies, required environment objects, and the temporal order necessary for successful execution. The Allocation Agent then maps these validated subtasks to the most suitable robots, taking into account their operational capabilities, skill sets, and available resources, while determining the optimal execution sequence.
