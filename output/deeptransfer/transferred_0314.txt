Guiding LLMs on automated program repair, CFAULTS has been integrated with Large Language Models (LLMs) via a zero-shot learning approach to enhance automated program repair for C programming assignments. In this context, CFAULTS identifies the buggy parts of a C program and presents the LLM with a program sketch where these faulty statements are removed. This hybrid approach follows a Counterexample Guided Inductive Synthesis (CEGIS) loop to iteratively refine the program. The LLM is then tasked with synthesizing the missing parts, which are subsequently checked against a test suite. If the synthesised program is incorrect, a counterexample from the test suite is provided to the LLM to guide a revised synthesis. Consequently, this method enables LLMs to repair more programs and produce smaller fixes, outperforming both alternative configurations that do not employ FBFL methods and state-of-the-art symbolic program repair tools. Fault localisation (FL) techniques typically fall into two main families: spectrum-based (SBFL) and formula-based (FBFL). SBFL methods estimate the likelihood of a component being faulty based on test coverage information collected from both passing and failing test executions. However, while SBFL techniques are generally fast, they may lack precision, as not all components identified in this way are necessarily responsible for the observed failures. In contrast, FBFL approaches are considered exact. As explained in Section 3, these methods (e.g., BugAssIST, SNIPER) deal with the problem of fault localisation as a Model-Based Diagnosis (MBD) problem, seeking minimal sets of faulty components. Typically, they make a MaxSAT call for each failing test case, yielding a minimal diagnosis for each failing observation in isolation rather than reasoning over all failures jointly. They then apply an aggregation procedure to consolidate the per-test diagnoses into a single explanation of the system's inconsistency.
