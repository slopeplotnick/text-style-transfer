Concrete actions facilitate a smoother transition and are widely employed in various software development life cycles, particularly during SPLE migration. Many agile practices can be used to minimize the negative effects associated with migration. For example, adopting a Sprint Zero can improve teamwork during the migration process. This sprint involves several steps: First, building a working agreement is essential, as it helps plan the agile rituals that assist the team during migration. Next, having a clear and common vision is crucial to ensure all team members understand the goals and benefits of the SPL. The third step involves building personas, which represent different user or developer profiles within the company. These personas are determined before starting the project to gain empathy and establish who will use it. Subsequently, the backlog is constructed by considering all the necessary tasks. Each task from the backlog must then be estimated and placed on a roadmap. Planning regular retrospectives allows the team to share insights and improve collaboration. Some software engineering practices are useful for improving project quality, such as regular refactoring sessions to enhance code reuse and reduce technical debt. These practices ensure better quality code: for instance, scheduling regular testing sessions helps avoid bugs, while planning acceptance testing sessions with end-users ensures alignment of expectations. Moreover, constantly monitoring code execution helps maintain the efficiency and scalability of the derived applications. These concrete actions are generally applicable to any software development setting, whether SPL-based or not. However, an SPL-based development setting offers strengthened advantages, as improved quality is embedded at the heart of the code base. This benefits current applications and will also benefit future derived applications.
