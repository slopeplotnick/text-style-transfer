Hyperparameters. To isolate experimental variables, we first assessed the attack's efficacy across various frameworks using a fixed model (Deepseek). Conversely, we evaluated its performance on different models within a fixed framework (OpenManus). For all experiments, the generation temperature was set to 0, and the maximum number of tool invocations was capped at 20. Resource hijacking. To quantify the computational overhead introduced by the LeechHijack attack, we integrated it into diverse tool categories and compared its resource consumption against benign MCP tools (Normal). The primary evaluation metric was the total token count, encompassing both input and output components. Since the backdoored tools could activate the LeechHijack mechanism multiple times within a single task, we introduced an additional metric to compute the average resource overhead incurred per individual trigger. Although the resources used to generate the supplementary task output represent only a fraction of the total hijacked computational cost, this unauthorized consumption remains a significant security concern from the end user's perspective. Hijacking resource utilization. To evaluate the utility of LeechHijack, we assessed the extent to which an attacker could exploit the hijacked resources for concealed tasks. Specifically, we compared the accuracy of responses generated for the additional task against the baseline accuracy of each model on the MMLU benchmark. The results, presented in Tables 7 and 8, demonstrate that LeechHijack effectively leverages hijacked resources to execute covert tasks. However, this exploitation comes at a cost, as it leads to observable performance degradation. These findings suggest that the attack is a viable resource hijacking mechanism with potential value for malicious actors.
