The framework did well with success rates from 0.10 for Compound tasks to 0.56 for Elemental tasks, showing it didn't do as well when tasks got more complicated. How well tasks could be done ranged from 0.39 to 0.71, meaning even when tasks got done, a lot didn't end up with good results. Robot Utilization scores between 0.56 and 0.66 showed that coordination wasn't very efficient no matter how complex the tasks were. The Self Corrective-Agent Architecture showed that checking things systematically and trying again in a structured way could fix the reliability problems found during SMART-LLM replication. Table 2 in the section about Performance Validation and Evaluation Limitations shows performance numbers for the same 36-task SMART-LLM test under the same conditions, focusing on how the architecture changes helped. The framework had success rates from 0.21 for Compound tasks to 0.50 for Elemental and Complex tasks. More importantly, how well tasks could be done got a lot better across all categories: Elemental (0.75), Simple (0.83), Compound (0.88), and Complex (0.86). These improvements of 9-30 percentage points show that the checks made sure the outputs were correct in structure and meaning. The Self Corrective-Agent Architecture shows it works better even though it uses the same few-shot prompting strategy as SMART-LLM. The framework uses 700,017 total tokens compared to SMART-LLM's 727,649 tokens (a 3.8% reduction) as shown in figure 13 and finishes in 746 seconds compared to 1,075 seconds (a 30.6% reduction) shown in figure 14. This improvement mainly comes from its modular prompting design, where each part (breaking down, assigning, or generating code) only uses its specific example file. On the other hand, SMART-LLM combines all three example files into every LLM call, no matter which part is being used. Because of this, each Self Corrective-Agent inference uses a lot fewer tokens, making it much faster. This way of prompting is so efficient that even with retries driven by validation, Self Corrective-Agent still uses fewer tokens overall.
