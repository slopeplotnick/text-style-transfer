Checking how much power LLM uses is not the same as checking how fast it works or how long it takes. Power use depends on different hardware, complex software, and how the work is done, which changes a lot depending on where it's used. Current LLM tests don't handle these changes well because they usually stick to set setups, fixed model sizes, and costly tools. But TokenPowerBench, as shown in Figure 1, deals with these issues using a three-part system: setting up, running and measuring, and making reports. It's a flexible and repeatable way to test LLM power use today. First, TokenPowerBench helps users get the test ready by picking the model, the engine to run it, and the prompts to use. To make this easy, TokenPowerBench has three parts you can mix and match: a model pool (pick any LLM it supports), a prompt-dataset menu (choose from Alpaca, LongBench, or your own prompts), and an inference-engine picker (vLLM, TensorRT-LLM, Transformers, or DeepSpeed). - Model Pool: We have models with different designs to see how these choices affect power use. This includes standard transformers (like the LLaMA series) and Mixture-of-Experts models (like Mixtral), which use computing power differently, especially in how they activate parameters and use memory. The test covers many model sizes, from small ones with less than 1 billion parameters that work on a regular GPU to big ones like Llama 3-405B that need multiple GPUs or nodes. This helps us see how power use changes as models and hardware get bigger. - Prompt-dataset menu: The length and style of prompts can change how much power is used during inference. To show this, TokenPowerBench supports two main datasets: Alpaca, with short chat prompts, and Long-Bench, with long contexts up to 10,000 tokens. Users can also use their own data in CSV or other formats.
