We looked at how fast and effective different systems are when editing PowerPoint files. Only MiniMax Agent and PPTPilot can finish edits in less than two minutes, while others are slower or often fail. Since speed is important, we only compared single-pass outputs and showed the results for loop-enabled edits separately in Table 4. The results show that good PowerPoint editing depends on three things in PPTPilot: planning that understands the structure and meaning of slides, a system that switches between using APIs and direct XML edits, and a process that checks and improves edits step by step to handle long and complex tasks. The tests show that most advanced systems still struggle with complex edits, mixed media, and changes across multiple slides, but PPTPilot does a better job at these. We also studied PPTPilot’s main parts to see how each one helps overall performance. We used the same measures as in Section 3: how often tasks succeed, if the PowerPoint file stays valid, how well instructions are followed, how good the slides look, and how much computing power is used. For the tests, we used the full PPTPilot setup, which includes creating a JSON snapshot, deciding when to use XML edits or a Python library, making sure the outputs follow strict rules, and fixing XML problems automatically. Then, we tested different versions of PPTPilot by turning off or changing certain parts while keeping everything else the same. For example, in one version, all edits were done directly in XML, which works well for small, specific changes like resizing one shape but is slower and less effective for big changes across the whole deck, like making all the text the same size or applying a theme. Another version used only the Python library, which is good for big changes like renaming or translating text but doesn’t work as well for detailed fixes that need precise control over specific elements.
