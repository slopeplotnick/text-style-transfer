We used a method to break down stories into parts like events, characters, and settings, and turned them into a JSON format. Then GPT-4 used this data to make new stories that kept the main ideas but added some new elements. We had specific rules to check how good the stories were, looking at things like how they worked, how creative they were, how easy they were to read, and if they felt real or thoughtful. Other AI tools, like GPT-4o, checked both the original and new stories to decide if they were good or not, labeling them as "Chosen" or "Rejected." The information from the stories was saved in JSON format, along with the labels, to make a dataset. This dataset showed emotional patterns and other details, which were shown in Figure 4. The dataset was split into two parts: one for training and one for testing, with most of it used for training. The training set had 8,866 pairs of preferences for improving the model, and the test set had 985 pairs that the model hadn’t seen before. We then improved the Llama-3-8B model using a method called AdamW optimizer and a fine-tuning approach called LoRA, with specific settings for learning rate, batch size, and training rounds. This gave us a test loss of 0.038. We picked these settings based on recommendations, testing, and the computer power we had. We also did tests to see how important different parts of the story were for making good stories. We started with a basic version of the Llama-3-8B model that used all the parts, then removed parts like "events" one at a time, retrained the model, and adjusted it to work with the new setup. All models were trained the same way to make sure the tests were fair. We checked how well each changed model worked using a separate test set. We also rated the stories using the same rules as before, looking at seven areas like creativity and clarity. The results of these tests will be explained in Section 6.
