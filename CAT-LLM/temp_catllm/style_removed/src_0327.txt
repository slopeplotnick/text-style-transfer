After the training phase, we set up a tough evaluation test to check how well the model works (Section 3.5). Since LLMs are really powerful and e-commerce data is super varied, we made sure the test covered a wide range of examples and included tricky ones based on the main skills we talked about in Section 2. Here, we did some basic prep work in three steps: building features, picking the model, and tweaking the prompts (see Fig 6). Based on the ideas in Section 2, making good relevance models means we need to fully map out the item's attributes. So, we picked features to help the model understand and reason using both pictures and text. First, for visual details like style, cuts, and patterns, we used the item's main product image. This is important for searches where just text isn’t enough. To add more details about the item, we also used category-property-value (CPV) triples and Stock-keeping-unit (SKU). Since CPV data can have extra stuff that doesn’t matter for judging relevance, we used a process that mixes prior knowledge with LLMs to clean it up. CPV data is shown as key-value pairs, and similar products often share the same keys. For instance, both "eye cream" and "face cream" usually have the key "brand". So, we looked at a lot of product data to find keys that show up a lot. Then, we gave a strong LLM called Qwen3-235B-Instruct the task of judging if each attribute helps with relevance, using the task definition, the attributes, and each key. To make sure the judgments were accurate, we ran the process eight times and only kept the attributes where the model consistently said "true".
