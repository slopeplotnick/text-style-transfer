At the end of the process, CFAULTS adds a check to make sure all the failing test requirements are included. This way, the program combines all the failing tests into one. Listing 2 shows part of a program created by unrolling the program from Listing 1. CFAULTS uses global variables to represent the inputs and outputs of each failing test (lines 1-3 in Listing 2). To keep things simple, the example only shows the part for test 0 from the test list in Table 1. Each failing test gets its own variables. Also, instead of using the scanf function, it uses input arrays (lines 8-10), and instead of printf, it uses CFAULTS' print functions, which work like printf but send the output to a buffer. At the end, the unrolled program has code like this: ```txt float _input_f0[3] = {1, 2, 3}; char _out_0[2] = "3"; int _ioff_f0 = 0, _off_0 = 0; // ... inputs and outputs for the other tests scope_0: int f_0, s_0, t_0; f_0 = _input_f0[_ioff_f0++] ; s_0 = _input_f0[_ioff_f0++] ; t_0 = _input_f0[_ioff_f0++] ; _off_0 = printInt(_out_0, _off_0, f_0); _off_0 = printInt(_out_0, _off_0, s_0); _off_0 = printInt(_out_0, _off_0, t_0); goto scope_1; } } // ... scope_1 and scope_2 final_step: assert(strcmp(_out_0, "3") != 0 || // other assertions); } ``` After adding all the possible runs and checks from the failing tests, CFAULTS changes the unrolled program by adding relaxation variables for each part of the program (like statements or instructions). These variables are linked to the healthy variables mentioned in Section 4. Each relaxation variable can turn a program part on or off by being set to true or false. CFAULTS makes sure the relaxation variable names don’t clash with the original variable names in the program. For this, CFAULTS needs to know the maximum number of times the program should be unrolled.
