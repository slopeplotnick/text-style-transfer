The tool library has a few tools: one for finding specific regions, one for planning how to analyze regions using a method called Think with Image, one for creating reports using templates, and one for checking the quality of radiology reports and giving feedback to improve them. These tools help with the whole process of making automated radiology reports. Figure 2 shows how the Radiologist Copilot works. For testing how well our Radiologist Copilot works, we use a liver radiology reporting task. We use a public 3D CT dataset called AMOS-MM, which has over 2,000 CT scans and detailed radiology reports. Out of these, 1,287 scans with reports are used for training, and 400 scans with reports are used for validation. For the liver task, we focus on reports in the AMOS-MM dataset that talk about the liver and use those as liver radiology reports. This gives us 1,149 CT scans with liver reports for training and 367 CT scans with liver reports for validation. The validation set is used to test how well our method works, and the training set is used to study the reports. First, we use a tool called BioBERT to turn the reports into data points, then group those data points using a method called K-means clustering to create template reports. These templates are broken down into liver-related details like the liver surface, liver tissue, bile ducts, and liver problems, which are used by the Analyzer Tool. The Radiologist Copilot is built using a system called OctoTools and runs on Python 3.10.18 with NVIDIA L20 GPUs. It doesn’t need extra training because it uses models that are already trained. The main reasoning tool is Qwen3-32B, and the Segmentator Tool uses a model called TotalSegmentator for finding regions. The Analyzer Tool uses a 3D medical model called Hulu-Med for analyzing CT scans. The system is set to take a maximum of 10 steps and can spend up to 500 seconds on each case.
