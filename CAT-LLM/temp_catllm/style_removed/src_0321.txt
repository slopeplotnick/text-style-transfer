We split each article into smaller parts to make sure the summary and each part fit within a 512 token limit. We compare the summary with each part and get the final SummaC score by averaging the scores across all parts, which gives a number between 0 and 1. We used heatmaps and a one-way ANOVA to see if the position of the input affects the summaries. We found that summaries are more similar to the first article in the input order. Figure 3 shows average scores for three metrics across six input orders and three stance categories. We calculate the average for each condition by averaging scores across all article groups with the same input order and stance. The differences in shading and scores show that the position of the input affects similarity patterns in summaries made by LLMs. Summaries have higher ROUGE-L and BERTScore values when compared to the first document in the sequence. BERTScore values are higher than those for Position 2 and Position 3, meaning documents shown first contribute more to the summaries. For RQ1, our results show a consistent trend: summaries are more similar to the first article in the input sequence. The metric values we found are different from those usually reported in summarization research. This is because we compare the generated summary directly with the full original articles, not against human-written reference summaries like in previous work. The summaries have about 220 words, while the source articles range from 300 to 1600 words, which naturally lowers token-overlap and similarity scores. So, we look at the relative score on different input conditions instead of the absolute metric values. Another issue is the lack of metrics to assess similarity between a summary and its source documents. Most evaluation frameworks are reference-based, so there are few ways to measure source alignment. SummaC, which looks at sentence-level entailment, gives low scores and doesn't change much with positional variation. Abstract summaries leave out details from the source, and entailment-based scoring penalizes unsupported or implied statements. Even if the model focuses on the first article, it's unlikely to reuse its exact wording. So, SummaC can't reward subtle content biases unless explicit supporting sentences are kept.
