Findings show that inefficiencies are common even when things seem resolved, but not as much. When things aren't resolved, they often have a bunch of localization or editing problems all in one go. Even though stronger models like Claude-4 are more successful, they still have more inefficiencies because they explore more internally. SWE Agents have been popping up a lot in the last year for handling automated issue resolution and software engineering tasks. You can split SWE agents into two main types: single-agent and multi-agent systems. Single-agent systems like SWE-agent and OpenHands use a single loop, while multi-agent systems like CodeR, Magis, and MASAI use different agents for different jobs, like searching for code snippets, making and checking reproduction scripts, changing code, and testing changes. GRAPHECTORY can be used with multi-agent systems by combining the paths from different agents into one. Another way to look at SWE-agents is by the tools they use. Some agents like Agentless don't use any external tools and just rely on prompting strategies. Other agents use traditional search methods and embeddings to find files. TRAE, CGM, and MarsCode Agent use code knowledge graphs and language server protocols to understand projects and find code entities. Without GRAPHECTORY, comparing these approaches would be really hard. GRAPHECTORY and LANGUTORY together let all these tools fit into the Localization phase. Since Claude 3.5 Sonnet came out, SWE agents like SWE-agent and OpenHands have started using bash commands for code search and a tool to view and change files. This led us to choose SWE-agent and OpenHands for our experiments.
