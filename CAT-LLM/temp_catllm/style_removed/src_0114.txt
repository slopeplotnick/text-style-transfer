PEFT-FACTORY calculates classification and efficiency metrics during predictions, along with token accuracy and semantic similarity metrics like Rouge and Bleu. For classification, it uses standard Accuracy and F1 metrics. To check efficiency when evaluating PEFT methods, it uses the PSCP metric, which is flexible and looks at things like the number of parameters, memory use, and how long it takes to make predictions. These metrics are set up in the train/sft/metric.py file for supervised fine-tuning, following the setup from LLaMA-Factory, with separate data classes for each metric called ComputeAccuracy, ComputeF1, and ComputePSCP. For classification, there’s a setting in the training options called compute_classification.metrics that you can turn on or off to include classification metrics. For efficiency metrics, there’s another setting called compute_pscp. More details about efficiency metrics are in Appendix B.3. PEFT-FACTORY is designed to be flexible and easy to use, making it a good tool for research on PEFT methods. To show how it helps with reproducibility and benchmarking, there are two examples. The modular design of PEFT-FACTORY makes it easier for researchers and developers to create and test new PEFT methods. Right now, when someone makes a new PEFT method, the shared code often doesn’t work properly or is hard to reproduce. Plus, developers usually have to write the training and evaluation code themselves, which can be repetitive, lead to mistakes, and cause inconsistent results.
