Here, we talk about our new evaluation system that connects Hallucination Detection and Fact Verification, which haven't been looked at together much before. We start by looking at why these two areas have been separate and check out the problems with current tests that make it hard to evaluate both together. Then, we explain the main ideas behind our system and describe how it works. Before we get into the details, it's important to understand why these two areas have been kept apart. The main issue is that traditional Fact Verification datasets focus on text, while Hallucination Detection methods focus on how models work. Fact Verification tests, like FEVER, use fixed pairs of claims and labels without considering where the claims come from. This setup doesn't work for Hallucination Detection methods, which need to look at how things are generated, like checking internal states or consistency across samples. These signals aren't in the fixed Fact Verification datasets, making it hard to evaluate both together. One idea to fix this is to make tests using pre-made outputs from large language models, like HELM. While useful, this approach has two big problems in the fast-changing AI world: - Models get outdated quickly. If you make a dataset with today's top models, like LLaMA-3, it might soon be just a historical record as new models come out. - You can't test new models. Fixed tests can't check Hallucination Detection methods on new or different models. Since these methods often depend on specific model features, a system that can't test new models limits progress and doesn't show true adaptability.
