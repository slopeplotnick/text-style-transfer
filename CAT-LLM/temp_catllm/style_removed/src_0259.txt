Just because a model is really accurate at tasks doesn’t mean it’s great at combining different types of information (check the middle part of Figure 8). For instance, GPT-5 Mini has a very low error rate but isn’t as good as other models at using multiple types of input together. This problem shows up the most when one type of input is much weaker than the other. Ideally, the model should rely less on the weaker input, but some models don’t do this well. This matters because if we only look at accuracy, we might end up favoring models that aren’t as good at handling noisy data. On the other hand, Llama-4 Maverick does better than a standard method called Bayesian reliability-weighted linear fusion, which suggests it uses more advanced ways to combine information. A non-linear random forest model matches how it works better than simpler linear methods. When we compare how models perform with one type of input versus two types (like text and images), we see that models like Llama-4 Maverick, Claude 3.7 Sonnet, and GPT-4o can use the extra input to make fewer mistakes in most tasks that involve both types of input. But this isn’t always the case, and the differences in improvement show there’s still room to make multimodal models better. You can check Appendix A.11 for more details on specific models. To go beyond just looking at accuracy, we came up with something called the Bayesian Consistency Score (BCS), which helps us see how models adjust their behavior in a logical way. This lets us evaluate models more completely, even when their accuracy is already very high. By testing how models behave when we tweak certain conditions, we can compare models with different starting performance levels and learn more about how they process information. While more complicated strategies, like focusing on important details or switching rules, might match patterns of responses better, it’s more useful to look at whether models behave in a way that aligns with Bayesian principles when the situation changes.
