Here's the deal: we’re looking at why this recent approach [16] doesn’t work so well. Basically, as shown in Figure 1(a), the model starts off paying attention to both audio and visual inputs, but as it keeps going, it focuses more on the text it’s already generated. This means the model ends up basing its reasoning on whatever emotional hints were in that first bit of text it made. Usually, the process starts with describing the video, because the training data is set up so that visual stuff comes first, then audio, and then reasoning. But this “visual-first” way of thinking doesn’t always make sense, especially when the emotion comes more from how something sounds or the meaning of the words. If the visual reasoning at the start is off or doesn’t matter, the rest of the reasoning gets more and more off-track, like what’s shown in Figure 1(b). So, the first step ends up being way too important. This kind of problem happens in other areas too, where early hints push the reasoning in the wrong direction [17]. To fix this, we came up with Modality-Importance-Guided Reasoning (MIGR). The idea is to start reasoning with the type of input (audio, visual, or both) that best matches the emotion we’re trying to figure out and to keep the reasoning consistent with that emotion all the way through. To do this, we added something called Modality Importance (MI), which figures out which input type is the most important for recognizing the emotion. It does this by comparing how well the model predicts the emotion when it only has audio, only has visuals, or has both. For example, if the model gets the emotion right with just audio but messes up when visuals are included, then the visuals probably don’t matter or might even be confusing. In that case, audio would be the main thing to focus on. Using this MI idea and some recent training methods for reasoning-based models [15, 16], we built a two-step learning process: (1) modality-aligned Supervised Fine-Tuning (SFT) and (2) modality-aligned reward optimization. In the SFT step, we use MI to break the reasoning text into parts based on the type of input and then rearrange it.
