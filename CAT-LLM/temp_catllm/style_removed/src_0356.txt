Sometimes, when using Claude 3.5 Haiku and GPT-4, you get different results even if you ask the same thing. Sometimes it works, and sometimes there are mistakes in the code. Also, GPT-4 sometimes repeats examples it's been shown before, which can cause mix-ups, like using the wrong objects for tasks. This showed that the original system didn't check for mistakes, so they added ways to check and try again in the LangGraph setup. This setup uses examples from three parts (breaking down tasks, assigning them, and making code) all in one go. But adding more examples to handle tough tasks made the input too long for the system to handle, causing it to fail. This problem, where more context helps but makes the input too long, led to changes for better handling of inputs and context in the LTAA system. These two problems, inconsistent outputs and input length limits, helped shape what was needed for reliable robot teamwork: ways to check for quality and a design that handles input limits. To fix these issues, they made a system focused on checking for mistakes, with steps to give feedback and try again if needed. To deal with the problems found during the SMART-LLM setup and to see if LLMs could really help with robot tasks, they made a Self Corrective-Agent Framework. Unlike the old one-agent setup, this new system uses three agents: one to break down tasks, one to assign them, and one to make code. As shown in Figure 2, each agent has its own way to check for mistakes and is managed by the LangGraph system. The first agent starts by turning big instructions into smaller steps, figuring out what needs to be done, what objects are needed, and in what order. The next agent matches these steps to the best robots based on what they can do and what they have, and decides the order to do them.
