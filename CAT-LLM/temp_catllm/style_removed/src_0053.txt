In this part, we explain the setup we use in this work. We talk about the data, the problem solvers, and the checkers, and we introduce the ways we measure how the solvers and checkers behave. We also explain how we set things up for checking in our study. It's important to know that "verifier gain" is a long-term measure. It shows what happens if you keep checking forever and acts as a limit on how much better you can get by using checker-based sampling. We use verifier gain to see how different checkers act. We put models into groups called families, like Llama3 or Qwen2.5, where each group has related models of different sizes. Since basic and improved models often act very differently, we see them as separate groups. For instance, the basic model meta-llama/Meta-Llama-3-70B is in the Llama3-Base group, and the improved model meta-llama/Meta-Llama-3-8B-Instruct is in the Llama3 group. We sort each solver-checker pair from our models into one of three checking setups. Each solver-checker pair can be one of these: 1. Self-Verification. The solver and checker are the same model, so it checks its own answers. For example, when a 70B Llama3 model is both the solver and checker, we measure things like accuracy on this single setup. 2. Intra-Family Verification. The checker looks at answers from other models in the same group. For example, a 70B Llama3 checker might check outputs from 8B or 13B Llama3 solvers. We average the measure over all these within-group solvers, not counting the self-checking case. 3. Cross-Family Verification. The checker looks at answers from models in different groups. For example, a basic Llama3 checker might check outputs from Qwen3 or from an improved Llama3. We average the measure over all these cross-group solvers.
