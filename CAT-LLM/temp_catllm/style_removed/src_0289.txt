The dataset was made by GPT-4o. You can find more details about the prompts, datasets, and model settings in the extra materials. Prompt engineering is a way to make sure language models do what you want when you give them instructions. We used something called prompt chaining, which helps break down big tasks into smaller steps so the models can handle them better. For story parsing, we broke it down into four parts: finding entities, finding events, making a story outline, and finding relationships. The results from each step are used in the next step. Prompt frameworks help make sure the models follow instructions correctly. In this paper, we used the TIDD-EC prompt framework, which includes five parts: what the task is, detailed instructions, what to do and not do, examples, and user content. This framework helps make sure the responses are accurate and relevant. There's a table that shows the prompts we used for the "Entity Extraction" task with the TIDD-EC framework. We also tried four different ways of prompting and compared how they did in turning stories into JSON format: - Zero-shot prompting: We explained the task in natural language without examples. - TIDD-EC framework: We used the TIDD-EC framework to set up the task. - TIDD-EC + CoT: We added chain-of-thought reasoning to the second strategy. - TIDD-EC + prompt chaining: We split the task into four parts, each using TIDD-EC, and connected them with prompt chaining.
