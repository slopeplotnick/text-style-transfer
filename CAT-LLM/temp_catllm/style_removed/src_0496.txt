This process figures out how many times we need to repeat something to be sure about the result, and it's a key part of how we train our system efficiently during testing. OptPO-SFT uses the same update method as TTSFT but decides how many times to repeat based on a Bayesian rule, making it both efficient and reliable. Both the RL-based and SFT-based versions of OptPO follow the same three steps: start the process, calculate a label using a specific method, and then update the parameters. The difference is in how they update: one uses policy-gradient optimization and the other uses cross-entropy fine-tuning, but overall, they work the same way. For testing, we use tough math and science problems: MATH-500 with 500 high school problems, AIME 2024 with 30 pre-Olympiad problems, AMC with American math competition problems, and GPQA with hard graduate-level science questions. We test OptPO on popular open-source models like Qwen2.5-Math1.5B, Qwen2.5-7B, and Llama-3.2-1B-Instruct to see how well it works across different sizes and types of models. To check how well TTSFT and OptPO-SFT work, we used Qwen2.5-Math-1.5B and Llama3.1-8B-Instruct as our main models. OptPO is a flexible system that can be added to different existing RL systems to make test-time training more efficient. We added it to PPO, GRPO, and Reinforce++ to see how well it works. We compared it to TTRL, which is a common method for optimizing policies during testing. We also checked how well OptPO-SFT works in similar situations. The learning rate for the critic is set to 1e-5. For SFT-based training, including TTSFT and OptPO-SFT, we use gradient descent on the labeled batch with AdamW at a learning rate of 2e-5.
