Here’s what we did: For both solvers and verifiers, we used a generation setup with temperature at 0.7, top-p at 0.9, and a max output length of 8192 tokens. If the output didn’t have a boxed answer, we threw it out. All the tests were run using vLLM on H200 GPUs. If you want to know more about the prompts or how we filtered outputs, check Appendix F. Now, about how the solvers performed: We tested all 37 models on 9 datasets, averaged their performance across tasks (you can see this in Figure 1), and listed detailed results for each task in Appendix G. In general, models with bigger capacities did better. Models from the Qwen3 and DeepSeek groups stood out as top performers, while Llama3-Base didn’t do well because it wasn’t familiar with the format for answering questions. Within each group, Qwen2.5-Base and DeepSeek showed clear improvements as they scaled up, and the other groups also showed similar trends of getting better with scaling. Then we looked at how solver performance matched up with verifier performance (see Figure 2). For all 21 post-trained models and each dataset, we checked how well the verifiers worked on the same solver models, measuring things like verifier accuracy, F1-score, precision, false positive rate (FPR), false negative rate (FNR), and gain for each solver-verifier pair. For each verifier, we split the metrics into three verification setups and averaged the results across solvers and datasets for each setup. Verifier accuracy usually got better as the verifier’s own solver accuracy improved, but other metrics showed more complicated patterns. For example, FPR went up during self-verification and when verifying models from the same group, but it went down a bit when verifying models from different groups. This shows that verifiers with better solver skills are more likely to wrongly mark their own outputs or outputs from their group as correct. If you want to see more details on F1-score and precision, check Appendix H.
