You can use file editing tools like create, str_replace, and insert to make or change a test file to see if there's a problem (Localization), fix a bug in an app file (Patching), or check if a patch works (Validation). For debugging, testing helps find bugs or check if a patch is good. The agents use Python to run new tests or pytest for old ones. The same tool or command can be used for different things depending on the situation. In the GRAPHECTORY of SWE-agent Dev, there's a loop at edge 9 and edge 10, showing possible issues in how the agent thinks or uses tools, leading to repeated failed edits or needing to change the plan (first problem in §1). GRAPHECTORY helps calculate metrics to analyze agent systems. Table 1 shows six metrics that GRAPHECTORY supports and how they can be figured out. These metrics show how much work an agent does to finish a task. By themselves, they don't say if the work is helpful or not but can show if the work matches the problem's difficulty or if the agents solve it. Here's what each metric means: - Temporal Edge Count (TEC) counts how many times actions change over time. More TEC means a longer path to finish. Figure 2 shows a longer path for SWE-agent Dev (14) than SWE-agent DSK-V3 (8). Like NC, TEC values go up with problem difficulty, matching the GRAPHENCY complexity with problem difficulty. - Loop Count (LC) counts how often the agent repeats an action. As shown later (§3.2), a bigger LC can mean a bad strategy, making the agent repeat failed actions, like the loop at edge 9 in Figure 2-a, or needing to rethink after actions that don't solve the problem, like back edge 10 in Figure 2-a (§3.3.2). Or, the agent might need to redo actions to solve a hard problem bit by bit. LC is like Cyclomatic Complexity [35] for software, which checks branching and different paths. In GRAPHENCY, branching means local thinking changes the path. - Average Loop Length (ALL) measures how many actions happen before repeating one. If it takes a long time for an agent to see its actions aren't working, its thinking or context gathering is weak. Our results show agents that gather more context during localization have shorter loops, meaning they quickly see when their thinking isn't working and change their plans (§3.2.1 and §3.3.2).
