We compared our approach to other benchmarks with judges. Our evaluation method is a big improvement over what’s been done before. Earlier methods, like PPTC-R, mostly focus on API-level differences. While that’s helpful, it’s not great at catching important mistakes, like when an agent puts the right text on the wrong slide. Our IF Judge works with structured summaries to spot these kinds of logical errors. Other benchmarks, like T2US, also use visual language models (VLMs) as judges, but they depend on prompts without a clear set of rules, which makes their results messy and unreliable. PPTArena fixes this by creating a solid and repeatable way to score things. In short, our dual-judge system, which is based on clear guidelines, is key for evaluating the complicated steps involved in editing PowerPoint presentations and for spotting subtle mistakes that simpler methods miss. We also created PPTPilot, a tool for editing presentations, which has a simple design but works really well—better than some paid tools like OpenAI’s ChatGPT Agent (explained more in Section 5.1). Our design is based on two main ideas. First, the hardest part of this work isn’t just understanding what needs to be done, but making sure it’s done accurately and reliably. PowerPoint files use a tricky format called Office Open XML (OOXML), which doesn’t handle errors or bad outputs from VLMs well, so it needs special formats and setups for editing. Second, we realized that no single editing method, like just using the XML format, is enough. A good tool has to be smart about picking the best way to edit for each task. PPTPilot is built with a dual-path setup, meaning it can handle editing requests either with programmatic tools or by directly editing the XML format.
