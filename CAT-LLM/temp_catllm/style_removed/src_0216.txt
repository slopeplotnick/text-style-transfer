To build a good relevance model, you need to figure out how to understand items, understand queries, and map paths. The model should be able to handle a lot of items and deal with different user needs, whether they’re straightforward or more abstract. To do this, it needs to do a few key things: it should use outside knowledge and logical thinking to clear up confusion in queries and understand abstract user goals when mapping paths. It also needs to work with both text and images to match and align details, which is important when dealing with items that rely heavily on visuals. Plus, it has to learn and follow complex rules to make sure the path-following process is consistent and reliable. When it comes to training large models for relevance tasks, the job is basically like a classification problem. Early methods used prompts to set up the task and responses to show the results, fine-tuning the models with supervised learning. But this simple approach didn’t work well when the data was different from what the model was trained on. Researchers found that making the model think through problems before giving answers helped it perform better on tough cases. Since there are limits on computing power and how the models are used, smaller models are usually chosen, but they don’t reason as well or follow instructions as effectively when just using prompts. So now, the common method is to use bigger teacher models like GPT-4 or DeepSeek-R1 to create reasoning data, then train smaller models with supervised learning to pick up those reasoning skills. Some researchers also add a reinforcement learning step after this, using methods like offline RL (Direct Preference Optimization or KTO) or online RL (Group Relative Policy Optimization).
