It's still hard to make these models work well in different situations. Even though they use a lot of varied training data, they often mess up when faced with new camera angles, lighting changes, or other unexpected scene changes. This makes them less useful in real-world settings where things are always changing and unpredictable. To fix this, people usually try two main approaches: one focuses on using more diverse data, and the other focuses on improving how the model represents spatial information. The data-based method involves using big datasets with lots of different views, like Libero-Plus, to expose the models to more visual situations. But collecting this kind of data in real-world environments is expensive and takes a lot of work, so it’s hard to keep doing it over time. The representation-based method tries to make the models better at understanding geometry, like how objects are positioned in 3D space, by using things like multi-view supervision or special architectures designed for 3D awareness. These methods help the models deal with changes in viewpoint, but they still struggle with things like cluttered backgrounds or changes in lighting, which shows they’re not fully adaptable to all visual conditions. Most of the time, people assume you need more data or better 3D-focused designs to make the models more robust, but not many studies actually look at whether the problem comes from how the spatial information is represented. To figure this out, we use a method that splits the model into two parts: one part handles spatial modeling, which is done by the visual encoder. This part figures out things like where objects are, how they’re oriented, whether they’re touching, and if one is blocking another, and it creates the spatial info needed for the next steps. The other part handles physical modeling, which combines the spatial info with task instructions and past actions to make decisions and come up with actions the model can take. When the camera angle changes, it mostly affects the spatial layout of the scene, not the actual meaning of the task or how actions should be carried out. This means the drop in performance is mostly because the spatial modeling part isn’t aligned properly, even though the physical modeling part is still working fine. Basically, the model can still think and plan, but it’s getting messed-up spatial info, which causes problems when it tries to act on that info.
