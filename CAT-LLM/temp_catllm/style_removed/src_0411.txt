The system works better because it creates specific prompts for each task based on what's happening at the moment, like the system's current state, what the robots can do, the workload, and the task phase. This means it doesn’t need to include those 5,000-6,000 extra example tokens in every prompt, which were unnecessary for the task. The process cuts down tokens in two ways: first, it focuses on what’s needed for the task, so it avoids extra steps like breaking things down or generating extra code, which used to take up about 14,000 tokens per task. Second, it replaces those example tokens with a structured way of providing context, which reduces the number of tokens in the prompts from 6,700 to 1,100. When they tested how well this system works for assigning tasks to multiple robots, they looked at things like how often tasks were completed successfully, how evenly the work was spread out, and how well it adapted to different situations. They tested it in three different setups where the robots had different skills, but the task sequence stayed the same with 36 tasks. Each setup focused on different robot strengths by changing how likely each robot was to succeed at specific tasks. The system showed it could keep up good performance while making sure the tasks were shared fairly among the robots, which is important in places like construction where both efficiency and fairness matter. In one setup, called Medium Excels, the robots with medium-level skills did the best overall, completing 87.8% of tasks successfully. The system gave most of the work to the robot that could handle all types of tasks well, which caused some imbalance in the workload. In this setup, the success rates for specific task types were 92.5% for careful tasks, 86.6% for tasks needing dexterity, and 85% for heavy tasks. While this setup got the best results overall, it also showed that focusing on performance can sometimes lead to uneven work distribution.
