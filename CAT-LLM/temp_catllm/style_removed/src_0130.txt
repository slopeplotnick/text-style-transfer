All the parts of the system work together using a shared setup, so they can be swapped out easily and still work with the rest of the system. Each part can be set up on its own, but there’s also a way to set everything up in one go using something called ExperimentConfig, which makes it easier to handle all the settings in one place. The LLM part is used to get answers from any large language model. Its main setup allows for doing multiple things at once and keeps track of how many tokens are being used. There are three types: APILLM lets you use models through an API, like ones from OpenAI or Anthropic, and there’s an example of how to set it up using the DeepInfra API. LocalLLM is for using models on your own computer with transformers. VLLM uses the v11m library to handle a lot of requests quickly and works well with GPUs. The Predictor part decides how to pull out the answers from the model’s output. For tasks like classification, it just takes the predicted category, and for math problems, it grabs the final answer. One type of predictor looks for the first time a possible answer shows up and takes that. Another type, which is more reliable, looks for answers marked between specific tags. For example, to figure out how many fish are in all the fishbowls, you’d add them up step by step, like adding 62 fish to 3 fish to get 65 fish. The Task part keeps the data and other details about what needs to be done. It also decides how to test prompts, making sure not to test every single one if it’s not needed, which saves time. This part is important for getting good results without wasting resources. We’ve set up tasks that are useful for natural language processing.
