Some methods for finding bugs in software, like SNIPER, give too many unnecessary results, while others, like BugAssIST, don’t give the smallest set of fixes needed to solve the problem. Recently, Graussam came up with a way to find bugs in ANSI C programs using a specific fault model that works with complicated features like pointers and arrays. It uses CBMC encodings, so the relaxation step happens at the CBMC level instead of directly in the code, which is different from what we do. This method can deal with multiple test failures by creating standard MBD cases and solving them with HSD to make sure the fixes are minimal for each failed test. But Graussam’s method adds an extra step after listing the fixes, which might mess up the minimality of the final results. We didn’t test this tool for two reasons: first, it needs manual annotations for the functions it checks, which isn’t practical for us since we work with over 1500 programs; second, it only works with integers and floats in C, so it doesn’t work for the C-PACK-IPAs benchmark. Model-Based Diagnosis has been used successfully in other areas like fixing issues in Boolean circuits, C software, knowledge bases, and spreadsheets. Another approach called program slicing has also been used to find bugs in programs. One method uses program slicing to list all the smallest sets of fixes for a broken program, and another method looks at the differences between different versions of the software to figure out what’s causing the problem. This paper introduces a new formula-based way to find bugs in C programs and Boolean circuits that can handle any number of issues. It uses Model-Based Diagnosis with multiple test failures to combine all the failed tests into one MaxSAT formula, which keeps everything consistent and avoids unnecessary results.
