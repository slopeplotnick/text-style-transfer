To fix these problems, we need to stop focusing on fixed outputs and start looking at how things work in real-time. The idea is to use a set of basic questions that can make any language model generate answers on the spot. This way, we can make sure that (1) fact-checking methods get the text they need, (2) hallucination detection methods can see what’s going on inside the model while it’s generating, and (3) the evaluation stays useful even as models change over time. That’s the main idea behind UniFact. To deal with the issues of outdated benchmarks, this system is based on three main ideas to make sure evaluations are strong, fair, and can work in the future. First, it doesn’t rely on old datasets of outputs. Instead, it uses a set of factual questions to make models generate answers in real-time, so it stays useful for both current and future models. Second, it allows fair comparisons by working for both hallucination detection and fact-checking methods. It gives hallucination detection methods access to what the model is doing while it generates answers and gives fact-checking methods the generated text and extra information to check against. Both methods are judged on the same task: figuring out if the model’s output is factually correct. Third, it uses an automated system to label outputs instead of relying on slow and subjective human reviews. This system checks if the model’s answers are accurate by comparing them to the correct answer and other reliable information, making it possible to evaluate lots of models quickly, fairly, and consistently.
