When you mix large language models with orchestration layers, shared memories, and external tools, you get multi-agent autonomy. Frameworks like AutoGen and CAMEL set up role-based dialogues with planners, critics, and executors all working in the same space. New systems like SWE-agent and Voyager take this further by creating loops where agents make tasks, test results, and change strategies. It's not just a fixed process but a flexible setup where each model's output changes the situation for the next one, creating feedback that builds up over time. Even if humans are supposed to be involved, their control is delayed, indirect, and limited. Traditional safety checks assume you can see and understand behavior, but in big multi-agent setups, these assumptions don't hold. Communication is often unstructured, like free-form natural language, JSON payloads, or API calls without clear meaning. When meaning comes from within the network, it's hard to trace because it's not about missing data but unstable interpretation. Technical solutions try to fix this lack of visibility. Multi-agent sandboxes now keep logs of interaction graphs and measure things like divergence, semantic coherence, influence centrality, and consensus rate to understand system behavior. The Inspect framework from the UK AI Security Institute does something similar by adding metadata to each message so you can trace back causal chains later. These changes show a shift from checking outputs to checking how information moves through the network. As things get bigger, the idea of autonomy changes. In supervised setups, autonomy meant taking action without direct human orders. In multi-agent systems, autonomy is about relationships: agents work together, compete, and guess each other's intentions. Even if they start with the same goals, small differences in rewards or context can lead to polarization, collusion, or runaway escalation. Autonomy isn't just a feature of individual parts anymore; it's something that comes out of the network itself.
