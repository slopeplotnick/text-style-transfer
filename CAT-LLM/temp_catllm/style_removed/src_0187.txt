The stuff about classifying time phases, balancing workloads, and strategies for each phase is all part of the workflow starting with Node 1, which is about figuring out phases. This node is the first checkpoint in a nine-node setup called LTAA. It checks the system's state and figures out the time context for the next steps. The Phase Detection Node is where the framework checks how tasks are going and updates workload numbers. As shown in Figure 9a, this node gets four main bits of info from the system: how many tasks are done and how many there are in total, how the workload is spread among robots, and what the ideal workload should be. These details help set up the context for each step in the process. In this node, the framework figures out how far along things are and uses that to decide if the system is in the early, middle, or late phase. Each phase is a different decision situation, affecting how the next nodes balance success rates and workload fairness. The node then works out a balance score to see how evenly tasks are spread and how bad the imbalance is compared to the ideal workload. These numbers sum up both progress and workload dynamics simply. The node finishes by updating the system state with new info: allocation_phase, balance_score, imbalance_severity, and operational_mode, which get passed to the next node. This makes sure all the next steps have the latest info on progress and workload. As shown in Figure 9a, this process is a one-way flow where the Phase Detection Node turns raw data into structured decision info for the next phase. The strategy for allocating phases needs solid LLM reasoning to make good decisions. But, LLM outputs can vary and might not be good enough for important construction work. To fix the issues found during the SMART-LLM implementation, the authors made a validation framework that checks reasoning quality with a weighted assessment and feedback system.
