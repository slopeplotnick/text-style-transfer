In specific SFT tasks, we usually stick to a set format for the task and requirements, then add the query and item details from each dataset to create the prompt. To make the base model work well, we include important info like what the task is about, the rules for making decisions, and how the output should look in the prompt. We also add clear instructions to help the model follow our two-step process: first, figure out what the query is asking for and what attributes it needs, then pull out the right attributes from the item info and make decisions based on the rules. For reasoning tasks, giving more detailed instructions in the prompt helps the model get the right answer more easily. But in SFT, this isn’t always the case because the model learns more from the response data than just the instructions. To find the best way to design prompts, we tried three versions. The long one has all the task details, rules, and instructions, and it’s over 7,000 tokens. The mid version is shorter, keeping only the most important instructions, and is about 800 tokens. The short version is the simplest, just giving a basic role description like: "You’re an e-commerce relevance expert. Score the query and item." This stage is about starting the model off and improving its basic ability to make decisions. To do this, we need a training dataset that’s both broad and clean. For the broad part, we use a good sampling method to cover different types of e-commerce data and avoid picking too much or too little of any one type.
