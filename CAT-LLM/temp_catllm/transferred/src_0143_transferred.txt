Prior to executing any operations, the functionality and safety of the agent's components are assessed to ensure compliance with security standards. Tools such as MCP-watch are employed to evaluate the integrity of the code associated with the agent, while MCP-scan simultaneously examines MCP servers to identify potential vulnerabilities, including those susceptible to exploitation or manipulation. During the agent's operational phase, mechanisms for immediate threat mitigation are required, and several approaches have been proposed to address this need. For instance, the SLM as Guardian method utilizes a compact model to detect potentially harmful user queries. To counter prompt injection attacks, a technique has been developed that segregates developer prompts from user data, thereby reducing the likelihood of system compromise. Following execution, the agent’s activities are analyzed to identify any security-related concerns. In this context, the LLM-as-a-Judge methodology offers a cost-efficient alternative to human evaluation but demonstrates limitations in addressing novel security threats, functioning effectively only in scenarios involving known risks. This study examines a contemporary LLM-agent architecture that incorporates the Model Context Protocol (MCP), wherein the LLM within the agent assumes a managerial role by interpreting user instructions, devising procedural steps, and utilizing external tools to complete assigned tasks. Each MCP tool operates autonomously within the agent and communicates with the LLM via a standardized API. Throughout task execution, the LLM actively monitors ongoing processes, including tool transitions, thereby facilitating advanced reasoning capabilities. Within this framework, the LLM serves as the primary cognitive entity, while the tools are tasked with specific operational functions. Adversarial entities aim to exploit the computational resources of the agent without obtaining unauthorized access or breaching system integrity. These entities are conceptualized as developers of MCP tools distributed in open-market environments. Their interactions with the system are strictly limited to legitimate MCP calls, without access to the internal structure of the agent or the ability to modify system regulations.
