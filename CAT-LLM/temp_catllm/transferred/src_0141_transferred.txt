The previous attempt to relax conditions did not effectively address infinite loops, particularly those perpetuated by a constant true condition. Consequently, a novel approach has been introduced, utilizing a methodology akin to the management of if-statements, whereby else relaxation variables are incorporated to control the outcomes when the original condition ceases to be true. This strategy facilitates a comprehensive understanding of the program's potential execution paths, including scenarios involving non-terminating loops. Specifically, CFAULTS is employed to establish relaxation variables within the primary program module, ensuring their consistent application across multiple function calls. The standardized application of relaxation variables ensures that identical program components, such as statements and instructions, consistently utilize the same variable configured within the main module. Consequently, should a relaxation variable be evaluated as false, the associated program segment remains inactive during testing phases. Moreover, the initialization of relaxation variables is deferred, allowing CFAULTS to ascertain the minimal subset of components requiring deactivation. It is imperative to note that these relaxation variables are local to the main module, thereby preventing the automatic false-setting by the C compiler.
