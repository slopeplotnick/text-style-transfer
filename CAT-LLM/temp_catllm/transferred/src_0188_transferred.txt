Prior to commencing the measurement process, the only predetermined knowledge pertains to the continuity of the measurements alongside their constrained average and spread. Consequently, energy use is modeled as a normal distribution, thereby circumventing the introduction of additional assumptions and facilitating simplified handling without complex mathematical formulations, which consequently accelerates the analytical process. Moreover, a multi-level model with a non-centered configuration is employed to enhance the efficiency and performance of the model without compromising the integrity of the results. This methodology is implemented in Java 21, although it is adaptable to any statically typed language operational on the JVM. Specifically, attention is directed towards a subset of Java to assess the efficacy of the method. All Java code undergoes conversion into Java bytecode via the OpenJDK 21.0.6 compiler. In order to minimize external interference and ensure the energy measurements reflect worst-case energy consumption scenarios, several variables influencing energy use are regulated: dynamic class unloading and JIT compilation in the Java runtime system are disabled, and the system operates in interpreted-only mode. Furthermore, the CPU speed is set to its minimum at 1.5GHz, and wireless networking on the platform is deactivated. The benchmark setup comprises 174 small tests, each methodically organized by operation, data type, and data size. With regard to data types, 32- and 64-bit integers, floating-point types, and reference types for arrays and objects are examined.
