Non-Deterministic Generation: Claude 3.5 Haiku and GPT-4 produced inconsistent outputs when provided with identical prompts, with some results being executable while others contained syntax errors. These inconsistencies were further exacerbated by training example contamination, as GPT-4 occasionally reused few-shot example sequences across runs, leading to logical errors. For instance, tasks such as "throw spatula in trash" were erroneously replaced with objects from unrelated tasks like "put eggs in fridge." Such anomalies highlighted the absence of validation mechanisms in the original architecture, thereby necessitating explicit error detection and retry systems within the LangGraph framework. To address these issues, the framework employed a few-shot prompting approach that concatenated example demonstrations from three critical stages—task decomposition, task allocation, and code generation—into a single unified prompt. However, while appending additional examples improved performance on complex tasks, it also increased token counts beyond the model's context window, triggering API failures during inference. Therefore, the scalability bottleneck—where richer context enhanced accuracy but exceeded feasible input lengths—underscored the need for modular prompt optimization and dynamic context management, later integrated into the LTAA framework. These dual challenges—generation inconsistencies and context window limitations—directly informed the architectural requirements for reliable multi-robot coordination. Specifically, systematic validation mechanisms were required to ensure reasoning quality, alongside a modular design capable of managing input constraints. Consequently, the authors developed a validation-centric architecture that incorporated multi-stage validation, structured feedback loops, and controlled retry mechanisms to address these limitations. Furthermore, to evaluate the practical feasibility of LLM-driven reasoning for multi-robot task allocation, a Self-Corrective Agent Framework was devised. Unlike the earlier single-agent reasoning design, this framework introduced a multi-stage iterative pipeline consisting of three specialized agents: the Task Decomposition Agent, the Task Allocation Agent, and the Code Generation Agent. As illustrated in Figure 2, each agent operates alongside an independent validation node and is orchestrated through the LangGraph workflow engine. The pipeline begins with the Decomposition Agent, which translates high-level natural language instructions into a structured sequence of subtasks, identifying task dependencies, environment objects, and the temporal ordering necessary for successful completion. Subsequently, the Allocation Agent maps these validated subtasks to the most suitable robots, leveraging their capabilities, skill sets, and available resources to determine the optimal execution order.
