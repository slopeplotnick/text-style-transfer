The general rule for relaxing program statements involves encapsulating each statement within an if-statement, where the condition is represented by a relaxation variable. For instance, in the program presented in Listings 3, CFAULTS relaxes lines 5 and 6 by introducing relaxation variables _rv1 and _rv2, which subsequently appear as lines 11 and 12 in Listings 4. Moreover, when relaxing if-statements, the expressions within both the then-block and the else-block adhere to the same relaxation principle. However, the conditions of these if-statements are relaxed using a ternary operator, as exemplified in line 14 of Listings 4. It is important to note that if the relaxation variable is set to true, the original if condition will be executed. Conversely, an alternate relaxation variable, such as _ev4 in Listings 4, determines whether the program transitions into the then-block or the else-block, provided one exists. These relaxation variables, which are specific to the scope of each failing test, ensure that individual tests control whether execution proceeds into the then or else-block. In handling expression lists, CFAULTS employs a strategy analogous to its approach for general program statements. Specifically, each expression is enclosed within a ternary operator rather than an if-statement. This ensures that when a particular program component is deactivated, the relevant expression evaluates to 1. For example, the initialization of variable i in line 11 of Listings 3 is transformed into a ternary operation in line 17 of Listings 4. Furthermore, all relaxation variables associated with loops are defined as Boolean vectors, facilitating the relaxation of loop statements. Each entry in these vectors corresponds to the relaxation of statements for a specific iteration. Therefore, the maximum allowable iterations of loops are determined by user-defined settings in CFAULTS. For inner loops, CFAULTS constructs arrays of arrays, encapsulating them within appropriate structures. Similarly, for simple program statements within loops, CFAULTS employs if-statements, associating relaxation variables with the iteration number. This approach is illustrated in line 20 of Listings 4, where a statement within a loop is relaxed. Additionally, the loop's condition is relaxed through the implication of the relaxation variable, as demonstrated in line 18 of Listings 4. Each loop is further associated with offsets for indexing its relaxation variables. These offsets are initialized immediately prior to the loop and incremented at the conclusion of each iteration, as shown in line 19 of Listings 4.
